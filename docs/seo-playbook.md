# SEO-плейбук

Постоянные правила SEO для всего проекта. Любая новая публичная страница, раздел,
тип контента или статья обязаны проходить чеклист §1 до мержа. Снимок текущего
состояния и находки — в `docs/seo-audit-2026-07-06.md`; здесь — то, как делать всегда.

Канонический образец реализации — каталог ингредиентов: `features/ingredients/seo.ts`
и `app/(public)/catalog/**`. Новые разделы копируют этот паттерн, а не изобретают свой.

---

## 1. Чеклист новой публичной страницы (обязательный)

Перед мержем страница проходит по всем пунктам:

- [ ] **Метаданные**: уникальные `title` и `description` из данных страницы (не generic),
      собранные билдером в `features/<домен>/seo.ts`.
- [ ] **Canonical**: `alternates.canonical` на каждой странице (self-canonical;
      правила параметров — §4).
- [ ] **Sitemap**: новый тип контента добавлен в `app/sitemap.ts` с честным
      `lastModified` из `updatedAt` (или задекларировано, почему не добавлен).
- [ ] **JSON-LD**: тип разметки по таблице §6, минимум `BreadcrumbList` на деталках.
- [ ] **OG**: `openGraph` (title/description/type/images) + картинка — своя или
      сайтовый дефолт.
- [ ] **Статусы**: несуществующая сущность → `notFound()` **в `generateMetadata`**
      (не только в теле — иначе `loading.tsx` отправит 200 до 404); переехавший URL →
      `permanentRedirect` (308), не `redirect` (307).
- [ ] **Серверный рендер**: весь индексируемый контент и все внутренние ссылки — в
      серверном HTML (§7). Клиентский fetch — только для персонализации/живых обновлений.
- [ ] **H1**: ровно один, содержит ключевую сущность страницы; заголовки без прыжков
      уровней; страница обёрнута в `<main>`.
- [ ] **Перелинковка**: страница достижима ссылками с хаба/листинга; сама ссылается на
      смежные разделы (§8).
- [ ] **robots**: служебные/приватные варианты страницы (create/edit/print/export)
      закрыты noindex + disallow.
- [ ] Прогнан валидатором: rich results test (Google) + валидатор Яндекс.Вебмастера
      (после запуска домена).

Для новой **статьи** дополнительно — §9. Для нового **типа UGC** — §12.

## 2. URL и слаги

- Слаг — человекочитаемая транслитерация, генерируется при создании.
- **После первой публикации слаг замораживается навсегда** — смена заголовка не меняет
  URL (образец: `features/content-articles/service.ts` — «URL канонический и не должен
  ломаться»). Если смена слага всё же нужна — только с записью старого слага и
  `permanentRedirect` со старого URL.
- Неймспейсы слагов не пересекаются: один путь — один тип контента. Коллизии слагов
  между типами в одном префиксе запрещены.
- Легаси-URL всегда отвечают 308 на канонический, никогда не рендерят дубль контента
  (даже с canonical).
- Новые разделы — path-иерархия (`/catalog/hops`), не query (`/catalog?category=hop`).
  Query-параметры — только для состояния (фильтры, сортировки, шаги калькулятора).

## 3. Метаданные

- Билдеры метаданных живут в `features/<домен>/seo.ts`, страница их только вызывает.
- `title`: ~50–60 символов, сущность + тип + ключевая характеристика из данных
  («Citra — хмель Yakima Chief», «Калькулятор IBU — горечь пива»). Название сущности
  вперёд, служебные коды — в скобки после. Шаблон `%s · <бренд>` доклеивается из layout.
- В title/H1 обязано быть слово, по которому страницу ищут: «рецепт», «калькулятор»,
  «стиль пива», «солод» — не внутренние продуктовые имена. Проверка: сформулируй запрос,
  по которому страница должна найтись, — есть ли его слова на странице?
- `description`: ~150–200 символов, из данных страницы (параметры, состав), обрезка по
  границе слова (`truncateAtWordBoundary` в `features/ingredients/seo.ts`). Сырые
  пользовательские тексты не подставлять без обрезки. Один generic-фолбэк на весь раздел
  запрещён — лучше собрать description из фактов («ABV 6.5%, IBU 60, объём 20 л…»).
- `openGraph`: type (`website`/`article`), images. Дефолтные siteName/locale ru_RU —
  в корневом layout. У контентных страниц OG-картинка обязательна (обложка, фото, либо
  генерированная из данных — SRM-цвет рецепта).

## 4. Canonical и параметры

- Self-canonical на каждой индексируемой странице. `metadataBase` задан в layout —
  использовать относительные пути.
- Параметры в canonical:
  - фильтры/сортировки/utm → canonical на чистый URL (или на path-лендинг, если он есть);
  - `?page=N` (N>1) без фильтров → self-canonical с `?page=N` и title «— страница N»;
  - поиск (`?q=`) и приватные вкладки (`?view=mine`) → `robots: { index: false,
    follow: true }`;
  - состояние инструмента (`/calculators/ibu?og=…`) → canonical на чистый слаг.
  Всё это уже реализовано в `buildCatalogListMetadata` — копировать оттуда.
- Страница за пределами пагинации (`page > totalPages`) → `notFound()`, не пустое
  состояние с 200 (soft-404).

## 5. Индексация: robots, noindex, sitemap

- В `robots.ts` закрыты приватные зоны и **все служебные публичные роуты**. При
  добавлении страницы create/edit/print/export/ембеда — сразу и disallow, и
  `robots: { index: false }` в metadata (двойной слой: disallow режет краулинг,
  noindex страхует по внешним ссылкам).
- Помнить: группа `(app)` не даёт префикса URL — страница `app/(app)/foo/page.tsx`
  живёт на `/foo`, и disallow `/app` её НЕ закрывает. Проверять реальный URL.
- Ресурсы, нужные для индексации контента (картинки рецептов и т.п.), не должны
  попадать под disallow `/api/` — точечный allow или чистый путь через rewrite.
- Sitemap:
  - каждый индексируемый тип контента добавляется в `app/sitemap.ts` в том же PR,
    что и страницы;
  - `lastModified` — только честный `updatedAt` из данных; для статики — либо реальная
    дата правки, либо ничего. `new Date()` в lastModified запрещён;
  - у sitemap стоит `revalidate` — новые URL появляются без пересборки;
  - пользовательские/приватные сущности в sitemap не попадают никогда.
- Новые окружения/стенды: всё, что не production-домен, отдаёт `X-Robots-Tag: noindex`.

## 6. Структурированные данные (JSON-LD)

Что размечаем (проверено по документации Google, июль 2026):

- **Рецепт** → `Recipe` (name, image — реальное фото/генерированная картинка, не логотип;
  author как Person; datePublished/dateModified; recipeIngredient из состава;
  recipeInstructions как HowToStep из brew-steps; recipeCategory = стиль;
  recipeYield = объём; nutrition.calories из OG/FG; keywords) + `BreadcrumbList`.
  `aggregateRating` — только при реальных оценках.
- **Статья/гайд** → `Article`/`BlogPosting` (headline, image, author.name +
  **author.url на страницу автора**, datePublished/dateModified с таймзоной,
  mainEntityOfPage) + `BreadcrumbList`.
- **Листинг рецептов** → `ItemList` (карусель со своего сайта поддерживается для Recipe).
- **Ингредиент** → `BreadcrumbList`; `Product` — только когда есть aggregateRating или
  offers (без них rich results не будет).
- **Калькулятор** → `BreadcrumbList` (+ `WebPage`); `SoftwareApplication` — только при
  реальных пользовательских оценках.
- **Главная** → `Organization` (name, url, logo ≥112×112) + `WebSite` (name,
  alternateName — источник Site Names в выдаче).
- **Не размечать**: `HowTo` (мёртв с 2023), `FAQPage` (отключён для всех с 05.2026),
  `SearchAction`/sitelinks searchbox (мёртв с 2024), `Product` без rating/offers,
  self-serving `Review` на собственных продуктовых страницах.

Правила:
- Разметка описывает **только видимый на странице контент**. В `aggregateRating` идёт
  отображаемый `ratingAvg`/`ratingCount`, а не внутренний `ratingBayes`.
- Recipe — только на странице одного рецепта, на подборках — `ItemList`.
- Сериализация — через `jsonLdScriptProps` (экранирование `</`); скрипт не первым
  ребёнком контейнера со `space-y` (ловушка отступов).
- Все URL в разметке — абсолютные от `APP_URL`.
- Яндекс принимает JSON-LD ограниченно (Article/Breadcrumb — да); для остального при
  необходимости — Microdata, но это не блокер.

## 7. Рендеринг и краулинг

- **Правило №1: контент и внутренние ссылки существуют только если они в серверном
  HTML.** Клиентский fetch в useEffect для индексируемого контента запрещён — Яндекс
  JS-рендерит плохо, а fetch к закрытому в robots `/api/*` не выполнит даже Google.
  Паттерн: серверная выборка → пропс → клиентский компонент дорисовывает живое поверх.
- Навигация — только `<Link>`/`<a href>`. Кнопки с `router.push` для переходов между
  индексируемыми страницами запрещены (краулер не нажимает кнопки).
- Сворачиваемый контент сворачивать визуально, не убирая ссылки/текст из DOM.
- `generateMetadata` и тело страницы делят одну выборку через React `cache()`
  (образец: `catalog/[source]/[id]/page.tsx`).
- Контентные деталки — статические или ISR (`generateStaticParams` + `revalidate`);
  не читать `cookies()`/`searchParams` в серверных компонентах без необходимости —
  это опрокидывает роут в дынамический рендеринг.
- `notFound()` — в `generateMetadata`; про `loading.tsx` рядом с редиректными/
  404-ветками помнить: стриминг фиксирует статус 200 раньше тела.

## 8. Перелинковка и структура

- Новый раздел при запуске получает: ссылку в футере (`lib/navigation.ts`), место в
  sitemap, вход с хаба. Страниц-сирот не заводим.
- Деталки ссылаются на смежное: рецепт → стиль BJCP + ингредиенты каталога + похожие
  рецепты; стиль → рецепты стиля + калькуляторы; статья → калькуляторы/рецепты
  (через `related-links`); ингредиент → рецепты с ним. Перелинковка всегда двусторонняя:
  добавил ссылку A→B — проверь, есть ли путь B→A.
- Хлебные крошки на всех деталках: видимый `<nav aria-label="Breadcrumb"><ol>` +
  синхронный `BreadcrumbList` JSON-LD с теми же URL. Крошки ведут на чистые
  канонические URL, не на параметрические.
- Anchor-тексты содержательные («Калькулятор IBU», не «подробнее»).
- Листинг — не голая сетка: 1–2 вводных индексируемых абзаца (образец — intro
  лендингов каталога), секции с h2.

## 9. Контент: правила для новых статей

- `seoTitle` и `seoDescription` заполняются при создании статьи — без них не публикуем.
- Обложка — JPEG/PNG (не SVG — мессенджеры не рендерят его в og:image), прописывается
  в og:image и в JSON-LD image.
- Автор: byline на странице, ссылка на страницу автора, `author.url` в разметке.
  Даты publishedAt/updatedAt — реальные; фейковое «обновление» ради свежести запрещено.
- Структура: h1 один (заголовок страницы), тело — h2/h3 с id-якорями, оглавление
  у лонгридов.
- В теле — контекстные ссылки на калькуляторы/рецепты/каталог/стили; блок «Дальше»
  из `related-links`.
- Рецепт внутри статьи размечается как `Recipe` (или Article + вложенный Recipe),
  не остаётся просто текстом.
- E-E-A-T: собственные фото/замеры варок ценнее стоковых; на темах, смежных со
  здоровьем/безопасностью (санитария, крепость), — точность и источники.
- Тексты — по глоссарию проекта, без руинглиша и калек (см. правила терминологии).

## 10. Изображения и медиа

- Контентные изображения — `next/image` (или `<img>` с width/height + loading="lazy" +
  decoding="async"); картинки без габаритов в потоке текста запрещены (CLS).
- Смысловые изображения — осмысленный alt с названием сущности; CSS-background — только
  для декора. «Как выглядит стаут» — картиночный интент: hero-изображения контента
  должны быть настоящими `<img>`.
- Имена файлов осмысленные (`ibu-calculator.png`, не `2-Photoroom.png`).
- URL картинок не под disallow в robots (иначе выпадают из поиска по картинкам и
  ломают Recipe.image/og:image).
- OG-картинки: 1200×630; для Recipe — три соотношения (16:9, 4:3, 1:1) по возможности.

## 11. Производительность

- Тяжёлые клиентские зависимости (симуляции, графики, редакторы) — только через
  `next/dynamic`; в first-load публичных страниц они не попадают.
- Аналитика — динамический import после согласия; в общий бандл статически не тащить.
- Публичные страницы с БД-данными — кэш: ISR/`revalidate`, React `cache()`, процессный
  TTL-кэш (помнить про 2MB-лимит `unstable_cache`).
- Шрифты — только `next/font` с кириллическим сабсетом; новые начертания не добавлять
  без нужды.
- Фиксированные оверлеи (баннеры, тосты) не сдвигают layout.

## 12. UGC-политика (рецепты и будущие типы)

- Публикация ≠ индексация. Для индекса (sitemap + отсутствие noindex) — порог качества:
  у рецепта есть описание/фото/оценки или подтверждённые варки. Ниже порога — страница
  живёт с `noindex, follow` и в sitemap не попадает. (Яндекс режет хост целиком за
  массовый thin-content — МПК.)
- Клон рецепта без существенных правок — canonical на источник либо noindex.
- Слаг опубликованного UGC заморожен (§2).
- Кастомные пользовательские сущности (ингредиенты и т.п.) — приватные: 404 чужим,
  noindex владельцу, вне sitemap (уже реализовано в каталоге — сохранять паттерн).
- Будущий форум/сообщество проходит те же правила до запуска: гейт качества, canonical,
  пагинация, sitemap.

## 13. Яндекс-специфика

- **IndexNow** — пинговать при каждой публикации/правке/удалении индексируемой страницы
  (рецепт, статья, ингредиент): ключ-файл + POST. Это главный ускоритель индексации.
- **Яндекс.Метрика** — за cookie-гейтом согласия; включить «обход по счётчикам».
- **Яндекс.Вебмастер** — sitemap, регион, диагностика, валидатор микроразметки.
- Поведенческие факторы — крупнейший фактор Яндекса: честные сниппеты (title обещает
  то, что есть на странице), интерактив, скорость, отсутствие тупиков (пустых страниц,
  английских 404).
- Canonical для Яндекса — рекомендация, не директива: дубли лучше не создавать вовсе
  (редиректы, чистые URL); при упорных параметрических дублях — `Clean-param` через
  кастомный robots.txt route-handler.
- Турбо-страницы мертвы (2025) — не тратить время. Директива `Host` мертва (2018).
- Mobile-first: новые страницы проверять на мобильной ширине в первую очередь.

## 14. Чеклист запуска домена (разовый, но обязательный)

- [ ] Домен выбран и куплен заранее (проверить историю по archive.org до покупки);
      заглушка с индексируемой главной — чтобы возраст домена тикал.
- [ ] `APP_URL` = канонический прод-URL; fail-fast на localhost при production.
- [ ] Канонизация зеркал: www/без-www, http→https — 301 на уровне инфраструктуры.
- [ ] Верификация Google Search Console + Яндекс.Вебмастер (DNS), отправка sitemap,
      регион РФ в Вебмастере.
- [ ] IndexNow-ключ, Метрика, «обход по счётчикам».
- [ ] Staging/preview-стенды закрыты `X-Robots-Tag: noindex`.
- [ ] `WebSite.name`/`alternateName` соответствуют выбранному имени бренда.
- [ ] Фавиконки: favicon.ico + PNG 192/512 + apple-icon.
- [ ] 18+ остаётся **age-notice** (неблокирующий баннер, контент в HTML под ним).
      Блокирующий age-gate/редирект запрещён — он выключает индексацию всего сайта.
      Если юристы потребуют гейт — только JS/CSS-оверлей поверх полного HTML,
      без разного контента боту и людям.

## 15. Антипаттерны (быстрый список «никогда»)

1. Индексируемый контент/ссылки через клиентский fetch (Brewfather: SPA-шелл — ноль
   органики при сильном продукте).
2. `redirect()` там, где переезд постоянный.
3. `notFound()` только в теле страницы при живом `loading.tsx` (получится 200).
4. `lastModified: new Date()`.
5. Generic title/description на всём разделе; сырой пользовательский текст в
   description без обрезки.
6. Смена слага опубликованной сущности без редиректа.
7. Разметка того, чего нет на странице (рейтинги, offers).
8. Кнопка вместо ссылки для перехода на индексируемую страницу.
9. Контентные картинки CSS-фоном или с `alt=""`.
10. Новый роут в группе `(app)`/вне `(public)` без проверки реального URL в robots.
11. Блокирующий age-gate.
12. Ссылки на `/login?next=…` без noindex на /login.
