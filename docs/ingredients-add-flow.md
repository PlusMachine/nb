# Flow добавления ингредиента на `/app/ingredients`

Дата фиксации: `2026-04-04`

## Что именно проверено

- `http://127.0.0.1:3000/app/ingredients` без auth-сессии сейчас отвечает `307` и редиректит на `/login`.
- Сам flow восстановлен по текущей реализации компонентов и серверных action'ов.
- Поведение подтверждено тестами:
  - `tests/inventory-add-flow.test.ts`
  - `tests/ingredient-picker.test.ts`

Команда проверки:

```bash
npm run test -w @nb/web -- tests/inventory-add-flow.test.ts tests/ingredient-picker.test.ts
```

## 1. Точки входа в flow

1. Основная CTA на странице `/app/ingredients`:
   `Добавить ингредиент`
2. Если склад пуст, та же CTA есть в empty state:
   `Пока нет ингредиентов` -> `Добавить ингредиент`
3. Есть deep-link сценарий из каталога:
   если страница открыта с `?addSource=<catalog|custom>&addId=<id>`, модалка открывается сразу и уже знает выбранный ингредиент.

## 2. Как выглядит модалка сейчас

- Это затемнённый overlay с белой модалкой.
- На мобильном модалка выглядит как bottom sheet:
  во всю ширину, со скруглением сверху.
- На desktop модалка центрируется и ограничена по ширине примерно `sm:max-w-2xl`.
- Вверху:
  - заголовок `Добавить ингредиент`
  - кнопка `Закрыть`
- Сразу под заголовком идёт выбор категории в виде grid-кнопок с иконками:
  - `Солод`
  - `Сбраживаемое сырье`
  - `Хмель`
  - `Дрожжи`
  - `Водоподготовка`
  - `Расходники`
- Ниже расположен segmented switch из двух режимов:
  - `Из каталога`
  - `Свой ингредиент`
- Активный сегмент подсвечивается белой плашкой на сером фоне.

## 3. Flow добавления ингредиента из каталога

### 3.1. Старт

1. Пользователь нажимает `Добавить ингредиент`.
2. Открывается модалка.
3. По умолчанию активен режим `Из каталога`.
4. Категория берётся:
   - из initial selection, если пришли с deep-link
   - иначе из текущего фильтра страницы
   - иначе по умолчанию это `hop`

### 3.2. Поиск ингредиента

1. В форме есть поле `Ингредиент` с placeholder:
   `Начните вводить название ингредиента`
2. Поиск стартует только когда:
   - поле открыто
   - введено минимум 2 символа
3. Поиск ограничивается выбранной категорией, а для fermentable ещё и subtype (`malt` / `fermentable`), если он задан.
4. В dropdown показываются результаты поиска.
5. Если совпадений слишком много, включается refinement mode по производителю:
   пользователь сначала сужает выбор через `Уточнить производителя`.
6. Если результатов нет, показывается CTA:
   `Не нашли? Добавить свой ингредиент`
   Она сразу переключает пользователя во вкладку `Свой ингредиент`.

### 3.3. После выбора ингредиента

1. После выбора появляется заметная карточка `Выбран ингредиент`.
2. В карточке отображаются:
   - основное название
   - secondary name, если есть
   - бренд / производитель
   - страна
   - типизированная краткая сводка
3. Для пользовательского ингредиента в поиске дополнительно показывается badge `СВОЙ`.
4. Карточку можно сбросить кнопкой `×` (`Очистить выбранный ингредиент`).
5. Если для ингредиента известен pack equivalent, под карточкой показывается строка вида:
   `1 pack = ...`

### 3.4. Что заполняет пользователь дальше

После выбора ингредиента ниже доступны поля для добавления в склад:

- `Количество`
- `Ед. изм.`
- `Дата покупки`
  - по умолчанию стоит сегодняшняя дата
  - рядом есть кнопка очистки `×`
- `Годен до`
- блок цены
- `Заметки`

Блок цены одинаково важен для обоих flow:

- заголовок меняется между:
  - `Цена за всё количество`
  - `Цена за <единицу>`
- переключатель режимов:
  - `За всё`
  - `За единицу`
- отдельного выбора валюты в UI нет;
  используется `preferredCurrency` пользователя
- под полем суммы есть helper/preview:
  либо расчёт итоговой цены, либо приблизительная цена за единицу

### 3.5. Submit

Кнопка submit:

- `Добавить в запасы`
- в pending-состоянии: `Сохранение...`

На submit вызывается `addSelectedIngredientAction`.

Дальше возможны 2 подветки:

1. Если выбран `catalog` item:
   вызывается `addCatalogIngredientAction`
2. Если выбран уже существующий `custom` item из пользовательского поиска:
   вызывается `addCustomIngredientToInventory`

### 3.6. Успешный результат

- Сообщение успеха:
  `Ингредиент добавлен в запасы.`
- Модалка закрывается.
- Вызывается `router.refresh()`.
- Ре-валидируются пути:
  - `/app/ingredients`
  - `/app/catalog`

### 3.7. Валидация и ошибки

Основные ограничения:

- обязательно должен быть выбран конкретный ингредиент
- `enteredQuantity` должен быть `> 0`
- единица измерения должна быть допустимой для выбранного ингредиента
- если передана цена, она сохраняется в валюте профиля

Типовые сообщения:

- `Выберите ингредиент из каталога.`
- `Единица измерения не поддерживается.`
- `Эта единица измерения не подходит для выбранного ингредиента.`
- `Ингредиент из каталога не найден или недоступен.`

## 4. Flow создания своего ингредиента и мгновенного добавления в запасы

### 4.1. Как в него попадают

Есть два сценария:

1. Пользователь вручную переключается на вкладку `Свой ингредиент`
2. Пользователь ищет в каталоге, ничего не находит и нажимает:
   `Не нашли? Добавить свой ингредиент`

### 4.2. Визуальная структура формы

Форма разделена на 2 смысловых блока:

1. `Параметры ингредиента`
2. `Что добавить в запасы`

Под первым блоком есть пояснение:

`Показываем только те поля, которые реально нужны для выбранной категории.`

Под вторым:

`Единица учета подбирается автоматически...`

### 4.3. Общие поля в custom-flow

В блоке `Параметры ингредиента` всегда есть:

- `Название ингредиента`
- `Бренд`

Дополнительно, в зависимости от категории:

- `fermentable`
  - `Тип ферментируемого`
  - `Цвет, EBC`
  - `Экстрактивность, %`
- `hop`
  - `Альфа-кислота, %`
  - `Год урожая`
- `yeast`
  - `Тип дрожжей`
  - `Аттенюация, %`
- `water_treatment`
  - показывается selector подтипа
- `consumable`
  - показывается selector подтипа

Важно:

- для `hop` отдельный selector `Подтип` не показывается
- для `fermentable` subtype реально влияет на taxonomy (`malt` / `fermentable`)
- для `water_treatment` и `consumable` subtype по умолчанию уходит в `other`, если пользователь его не меняет

### 4.4. Блок добавления в запасы

Во втором блоке пользователь заполняет:

- `Количество`
- `Единица количества`
- `Дата покупки`
  - по умолчанию сегодняшняя дата
  - есть кнопка очистки
- `Годен до`

Далее идут:

- тот же блок цены, что и в catalog-flow
- `Заметки`

Кнопка submit:

- `Создать и добавить в запасы`
- в pending-состоянии: `Сохранение...`

### 4.5. Что происходит на submit

Вызывается `addCustomIngredientAction`, и внутри него идут 2 шага:

1. Создаётся новый пользовательский ингредиент через `createUserCustomIngredient`
2. Сразу после этого он добавляется в склад через `addCustomIngredientToInventory`

### 4.6. Успешный результат

- Сообщение успеха:
  `Собственный ингредиент создан и добавлен в запасы.`
- Модалка закрывается
- вызывается `router.refresh()`
- ре-валидируются:
  - `/app/ingredients`
  - `/app/catalog`

### 4.7. Основная валидация custom-flow

Общее:

- `displayName` обязателен, минимум 2 символа
- обязательно должна быть определена категория
- `enteredQuantity` должен быть `> 0`

Категориальные требования:

- `fermentable`
  - обязателен `Цвет, EBC`
  - обязательна `Экстрактивность, %`
- `hop`
  - обязательна `Альфа-кислота, %`
- `yeast`
  - обязательны `Тип дрожжей` и `Аттенюация, %`

## 5. Важные текущие нюансы реализации

- Верхний выбор категории синхронизирован между вкладками `Из каталога` и `Свой ингредиент`.
- Для fermentable в хедере модалки есть два отдельных entry point:
  `Солод` и `Сбраживаемое сырье`, но внутри taxonomy оба живут в категории `fermentable` с разным subtype.
- В catalog-flow поиск включает и пользовательские ингредиенты тоже.
  То есть вкладка `Из каталога` фактически работает как unified picker по catalog + existing custom.
- Для dry yeast unit profile может автоматически переключаться на `pack`.
- Отдельных полей `Куплено`, `Ед. закупки` и явного selector валюты в текущем add-flow нет.
