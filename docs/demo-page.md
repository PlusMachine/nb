# Демо-страница `/demo` — «мастерская изнутри»

Публичная страница-презентация продукта. Решает проблему порога: показать NB
«с заполненным аккаунтом» (склад, рецепты, варки, автоматика, брожение) без
регистрации, БД-данных пользователя и подготовки. Все данные — захардкоженные
реалистичные фикстуры; страница не читает БД и не требует сессии.

Референсы: визуальный язык и правила копирайтинга — `notes/home-redesign/design-spec.md`
(§1, §3, §4 действуют здесь целиком: SRM-палитра как акцент, один тёмный блок,
без стоковых фото/каруселей/слоганов, термины пивоваров, без пояснительных
подзаголовков). Паттерн иллюстративных фрагментов — `apps/web/components/home/home-loop.tsx`.

## 0. Концепция

Не список фич, а **сквозная история одной варки**: рецепт → сверка со складом →
варочный день (помощник и автоматика) → брожение → дашборд. Каждая секция —
настоящий UI продукта (реюз компонентов, где это безопасно) с реалистичными
данными. Отличие от главной `/`: главная продаёт мини-фрагментами, демо даёт
**полноразмерные экраны закрытой зоны** — то, что нельзя увидеть без заполненного
аккаунта.

Центральный wow-элемент — **живой пульт BrewForge**: настоящий `LiveDashboardView`
поверх клиентского `SimDevice` (реальный движок симуляции прошивки из
`packages/brewforge-sim`). Температура тикает, стадии сменяются, кнопки
транспорта реально управляют симуляцией. Каждый посетитель получает свою
изолированную симуляцию (client-side) — никакого разделяемого состояния.

Честность: страница явно говорит, что данные — примеры, а пульт подключён к
симулятору контроллера с ускоренным временем. Это не мокап — это настоящий
интерфейс и настоящая математика.

- Рецепт №3: «Czech Premium Pale Lager» — 3B, 20 л, OG 1.050 / FG 1.014 / IBU 36 / ABV 4.7% (по calculateAbv из OG/FG) / SRM 4.5. Приватный.
- Рецепт №4: «American Pale Ale» — 18B, 20 л, OG 1.052 / FG 1.012 / IBU 38 / ABV 5.2% / SRM 7. Черновик.
- **Партии:**

- Чеклист 4 строки: «Засыпь — 5,7 кг ✓», «Затирание 66 °C · 60 мин ✓»,
  «Промывка ✓», «Кипячение 60 мин — идёт» (done-строки — line-through + зелёный,
  как в `BrewStepRow`).
- Под ними — настоящий `BrewStageRail` (`.../brew-stage-rail.tsx`, чистый компонент
  без actions): фикстурные `BrewDayStageGroup[]` (Затор ✓ → Кипячение (идёт) →
  Вирпул → Охлаждение → Брожение → Розлив) + `BrewDayProgress`. Лейблы — реюз
  `brewDayStageLabels` из `features/brew-batches/contracts.ts`.
- Таймер чисто клиентский, ничего не пишет.

**b) Автоматика (тёмный блок — единственный на странице).**
Заголовок «Или на автомате: BrewForge». Настоящий пульт:
- `LiveDashboardView` (`apps/web/features/brew-controller/components/live-dashboard-view.tsx`,
  `variant="page"`, `channel="demo"` — ChannelBadge честно покажет демо-канал).
- Двигатель — `SimDevice` из `@nb/brewforge-sim` (браузеро-безопасен: единственная
  зависимость — `@nb/brewforge-protocol`). Клиентский компонент `DemoPult`:
  инстанс в `useRef` (создание лениво на клиенте, НЕ при SSR — компонент рендерит
  пульт только после mount, до этого — каркас-заглушка тех же размеров, чтобы не
  прыгала вёрстка), `setInterval` ~1 c → `advanceToNow()` → `snapshot()` →
  собрать `TelemetryStream`-объект → `setState`. Стартовое состояние — разгар
  затирания IPA (`ensureDemoBrewing()` или эквивалентный сценарий конструктора;
  время ускорено `tickScale` так, чтобы за ~2–3 минуты просмотра посетитель
  увидел смену паузы затирания).
- `command`-проп — объект формы возврата `useDeviceCommand`
  (`features/brew-controller/use-device-command.ts` — прочитать и повторить контракт):
  `send` маршрутизирует в `sim.handleCommand()` (пауза/продолжить/пропустить шаг
  РАБОТАЮТ), lease — «удержан мной», `pending:false`, `undo:null`. E-STOP тоже
  работает на симуляции — это честно и эффектно.
- `initialHistory` — профиль нагрева и паузы осахаривания за «прошедшие» ~40 минут,
  согласованный с точкой прогрева симуляции (честный профиль, не абстрактная кривая).
- График — управляемый: `DemoPult` копит собственный ряд точек (префикс
  `buildMashHistory` + точка с каждым тиком симуляции) и передаёт его через
  аддитивные пропсы `LiveDashboardView.liveHistory` → `TelemetryChart.live`
  (в этом режиме fetch-поллинг истории отключён — серверу неоткуда знать состояние
  симуляции в браузере посетителя). График честно следует за варкой: пауза посетителя
  даёт полку, «Пропустить» — скачок стадии. Отдельный роут истории устройству demo
  НЕ нужен (существующий продуктовый `POST /api/devices/demo` — не трогать!).
- Подпись под пультом (строка-факт, оправдана — это главный блок):
  «Это настоящий пульт NB, подключённый к симулятору контроллера — время ускорено.
  С железом всё выглядит так же.»
- `faultMask=0` (AlarmsPanel скрыт), сим стартует в затирании (BrewRecipeOnDevicePicker
  не показывается). `pushableRecipes` не передавать.

## 4. Жёсткие правила реализации

1. **Никакой БД и сессии.** Демо-модули не импортируют `features/*/service.ts`,
   `@/lib/auth`, `@nb/db` — ни прямо, ни транзитивно. Типы — только `import type`
   из `contracts.ts`. Оба API-роута — чистые генераторы JSON.
2. **Фикстуры типобезопасны:** собираются под настоящие типы контрактов без `as any`
   (единичный `satisfies` — ок). Если поле контракта неясно — читать контракт,
   не угадывать.
3. **Тема:** только семантические токены (`bg-card`, `text-foreground`,
   `border-border`, `text-muted-foreground`, `bg-muted`…). Хардкод hex запрещён,
   кроме SRM-цветов через `srmToHex` (осознанное исключение, как на главной).
   Страница обязана выглядеть правильно в светлой и тёмной теме.
4. **Копирайтинг:** правила `notes/home-redesign/design-spec.md` §3 — термины
   пивоваров, без калек («вирпул», не «водоворот»; «сухое охмеление»), без
   «мощный/удобный/интуитивный», без пояснительных подзаголовков. Цифры — `tabular-nums`.
5. **Никаких кликов в server actions.** Всё, что внутри реюзнутых компонентов
   дёргает actions, глушится `pointer-events-none` на обёртке. Кнопки пульта —
   исключение: они ходят только в локальную симуляцию.
6. **Модалки/тосты** если понадобятся — только из `@nb/ui` (см. CLAUDE.md), но в
   демо их быть не должно.
7. **`prefers-reduced-motion`:** тикающие таймеры продолжают обновлять текст (это
   контент), но пульсации/переходы отключаются (как на главной).
8. **Мобайл:** страница полностью читаема на 390px; пульт и график скроллятся/сжимаются
   так же, как на своих родных страницах (они уже адаптивны); сетки складываются
   в столбец.
9. Перед завершением: `npx tsc -p apps/web/tsconfig.json --noEmit` зелёный.

## 5. Известные ловушки (из разведки)

- `OwnerRecipeCard` — реюз as-is; `RecipesGrid` НЕ использовать (тянет
  `RecipeSavesProvider`/`RecipeMatchProvider` с server actions на mount).
- `InventoryListItem` не имеет readOnly-пропа — глушить обёрткой, не патчить компонент.
- `BrewDayBoard`/`FermentationBoard`/`BrewJournal` НЕ реюзать (server actions,
