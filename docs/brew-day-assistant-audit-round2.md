# Помощник варки: аудит №2 и план рефакторинга

Дата: 2026-07-03. Контекст: после реализации фаз A1–A3 редизайна
(`docs/brew-day-assistant-redesign.md`) владелец повторно прошёл страницу
`/app/brew-batches/[id]` и задал семь вопросов. Ниже — вердикт по каждому
с привязкой к коду и план фиксов P0–P2. Этот документ — рабочий чеклист
текущего рефакторинга; вычёркиваем по мере выполнения.

---

## Диагнозы

### 1. Вход в варку порван: два входа с разной семантикой

- Диалог «Сварить» из рецепта **сразу переводит партию в brewing**
  (`app/(public)/recipes/[slug]/brew-actions.ts:50`) — пользователь никогда
  не видит акт «Подготовка» с кнопкой «Начать варочный день».
- Акт «Подготовка» видят только те, кто запланировал варку (флоу списка
  покупок → `createBrewBatchFromRecipeAction`).
- В гиде нет подготовительных шагов: первый шаг дня — сразу «Осахаривание ·
  66 °C · 60 мин». Нет «Нагреть воду до температуры затирания», «Засыпать
  солод», «Промывка/фильтрация» между затором и кипячением
  (`features/brew-batches/brew-day.ts`, `buildBrewDaySteps`).
- Запуск таймера паузы — маленькая outline-кнопка с Play; не читается как
  «начать шаг».

### 2. Нет «шага назад»

Откат — только снятием чекбокса в списке. Если закрыт последний шаг этапа,
этап сворачивается в `<details>` — сначала раскрой, потом снимай отметку.
В герое рядом с «Готово» кнопки отката нет
(`features/brew-batches/components/brew-day-board.tsx`, `CurrentStepHero`).

### 3. Док «+ Замер / + Заметка» сломан на обеих раскладках

`features/brew-batches/components/brew-quick-dock.tsx`:

- **Десктоп:** док статичен и стоит в самом низу страницы — *ниже* секций,
  к которым скроллит. Клик «ничего не делает».
- **Мобайл:** док `sticky bottom-0 z-20`, а в app-зоне есть фиксированный
  нижний таб-бар `fixed bottom-0 z-40` (`components/app/app-shell.tsx:263`)
  — док прилипает к низу вьюпорта **под таб-баром** и не виден.
- Даже при удачном скролле поле ввода не фокусируется.

### 4. Соли и pH: напоминания частичные или отсутствуют

- Строки «Водоподготовка» со стадией `mash`/`boil` в гид попадают
  («Внести: Гипс · 5 г»). Но дефолтная стадия water_treatment — `other`
  (`components/recipes/recipe-designer/helpers.ts:803`), а `other` в снапшот
  варки не попадает (`brew-plan.ts` фильтрует `boil|mash`).
- Соли/кислоты, рассчитанные водным движком (advanced-режим), живут только в
  `waterPlanMeta` — гид его не читает → нет напоминаний, и со склада они не
  списываются (аллокации строятся по строкам рецепта).
- Напоминания «замерьте/скорректируйте pH затора» нет нигде.

### 5. Мобайл: спроектировано, не верифицировано

Код мобайл-грамотный (горизонтальный скролл ленты этапов, flex-wrap,
тач-таргеты 44px, `pb-24` под таб-бар), но главный мобильный элемент — док —
перекрыт таб-баром (п. 3). Живой прогон на телефоне не делался.

### 6. Списание склада: трижды списать нельзя, но флоу мутный

Поверхности: редактор рецепта («Списать со склада»), чекбокс в диалоге
«Сварить», секция «Склад» на партии. Защита рецепт-скоупная — consumed-
аллокации блокируют повтор везде (`features/brew-batches/inventory.ts`).
Дыры:

- **Молчаливый сбой в диалоге «Сварить»:** неудачное списание глотается
  `catch {}` (`brew-actions.ts:55`) — варка стартует, пользователь думает,
  что списал.
- **Списание из редактора не привязано к партии** (нет `brewBatchId`):
  на странице партии видна только фраза «уже списаны» — без списка и без
  возможности «Вернуть на склад».
- **Повторная варка того же рецепта заблокирована навсегда:** завершение
  партии не освобождает аллокации; вторая партия не спишет новые закупки.
  Модельная дыра: «списано» должно жить на партии, а не на рецепте.
- **Истории движений нет в UI:** `inventory_transactions` есть в БД и даже
  возвращается (`view.log`), но нигде не рендерится.

### 7. «Поставить на брожение»: название верное, место нет

Название — принятый пивоварский язык, не переименовывать. Случай «день не
пройден» уже покрыт подтверждением («Ещё N шагов не отмечено»). Проблема —
позиция: кнопка стоит между героем и списком шагов, на прайм-позиции всё
время дня (`brew-day-board.tsx:187-202`) — мягкий рецидив старой болезни
(доминирующий статус-виджет).

## План рефакторинга

### P0 — чинится сейчас, без миграций

- [x] **Док быстрых действий** (`brew-quick-dock.tsx`): мобайл — sticky
  `bottom-14 z-50` над таб-баром (таб-бар получил детерминированную `h-14`);
  на `lg+` не рендерится; клик = скролл + focus первого поля секции.
  Попутно вскрыт и починен корневой баг: `tailwind.config.ts` не включал
  `./features/**` в content-глобы — уникальные утилиты компонентов фич
  (в т.ч. `bottom-14`) молча выпадали из собранного CSS.
- [x] **«Поставить на брожение» по месту** (`brew-day-board.tsx`): день не
  пройден → outline + confirm внизу, после списка шагов; день пройден (или
  план пуст) → primary CTA внутри зелёной панели героя, туда же переехала
  подсказка про OG.
- [x] **«Вернуть шаг»** — undo в герое (и в зелёной панели), снимает отметку
  с последнего done-шага акта в порядке обхода групп; чистый хелпер
  `resolveLastDoneStep` в `brew-day.ts` + юнит-тесты. `<details>` откату не
  мешает — откат идёт из героя.

### P1 — сквозной флоу старта и честность списания

- [x] **Единый вход «Сварить»**: принят основной вариант — диалог создаёт
  партию в `planned` и ведёт в акт «Подготовка» (кнопка подтверждения —
  «Создать варку», старт варочного дня — на странице партии). Комментарий
  «клик реально запускает варку» переписан со ссылкой на этот аудит.
- [x] **Фидбек списания в диалоге «Сварить»** (`brew-actions.ts`):
  `catch {}` убран, результат кодируется в результате экшена, довозится на
  страницу партии query-параметром (`?stock=consumed&items=N` /
  `?stock=<код ошибки>`) и показывается тостом (`brew-stock-notice.tsx`),
  параметры вычищаются из URL.
- [x] **Подготовительные шаги гида** (`brew-day.ts`): `mash:strike`
  «Нагрейте воду» (объём + первая пауза `+4 °C`), `mash:dough-in` «Засыпьте
  солод» (`grainBillTotalKg` — новое поле снапшота, старые снапшоты
  деградируют мягко), `mash:lauter` «Промывка и фильтрация»
  (`spargeWaterVolumeL`); герой таймер-шага — крупная primary «Начать шаг»
  («Готово» на это время становится outline).

### P2 — модель данных и вода

- [x] **Соли/pH в гиде**: водный движок прекомпьютится при создании партии в
  новое поле снапшота `waterSchedule` (соли затора/промывки, кислоты,
  целевой pH); шаги гида: «Внесите соли в воду» → «Подкислите затор» →
  засыпь → «Проверьте pH затора» → «Подготовьте промывочную воду» перед
  промывкой. Дефолтная стадия water_treatment в recipe-designer — `mash`
  вместо `other` (строки теперь попадают в снапшот). Старые снапшоты без
  поля — без шагов воды, мягко.
- [x] **Списание per-batch вместо per-recipe**: миграция `0047` — колонка
  `recipe_inventory_allocations.brew_batch_id` (+ индекс, + backfill по мете
  транзакций); consumed блокирует повторную варку только при активной партии
  (`planned/brewing/fermenting`) или без привязки (редактор/легаси —
  консервативно). Ловушка таймстампов journal обойдена (`when` 0047 =
  1791000000013), применение в dev-БД проверено. Coverage рецепта не
  учитывает consumed завершённых партий.
- [x] **Журнал движений склада в UI**: `view.log` рендерится свёрнутым
  блоком «История движений» в секции «Склад» партии.
- [x] **Живой прогон** — эмуляция телефона (Playwright, 390×844): все пять
  актов + сквозной флоу «Сварить»→«Подготовка»→старт дня, док над таб-баром,
  фокус полей из дока, undo, «Начать шаг» — 19/19 проверок. Прогон на
  реальном телефоне остаётся за владельцем.
