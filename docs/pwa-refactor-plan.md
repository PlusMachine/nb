# Рефактор PWA — план

> Статус: РЕАЛИЗОВАНО 2026-07-06 (P1–P6, не закоммичено). Основание — аудит PWA
> (манифест есть, SW только пуши, оффлайн-кэша нет; оффлайн-варка через веб-пульт
> архитектурно невозможна и не нужна — её закрывает встроенный `/ui` прошивки).
>
> Отклонения/уточнения по факту реализации:
> - Открытые вопросы решены: `start_url: /app`, имя осталось «NB».
> - `/offline` — НЕ инлайн-скрипты, а клиентские компоненты
>   (`app/offline/offline-console-list.tsx`, `offline-retry-button.tsx`):
>   инлайн-мутация DOM до гидратации ловила React #418, и React выбрасывал
>   добавленные узлы (найдено живым прод-прогоном). Контракт localStorage —
>   обычный импорт из `features/pwa/device-local-console.ts`.
> - Поэтому SW прекэширует не только HTML `/offline`, но и её JS/CSS-чанки
>   (парсинг `/_next/static/*` из HTML в `precacheOffline`), иначе первый
>   оффлайн без онлайн-визита страницы остался бы без гидратации.
> - Кэш статики ограничен капом `MAX_STATIC_ENTRIES=200` (FIFO-подрезка).
> - Генератор иконок: `apps/web/scripts/generate-pwa-icons.mjs` (sharp);
>   скруглённые 192/512 — с альфа-каналом, maskable/apple — flatten.
> - Проверка: vitest 1610/1610 + tsc чисто; прод-сборка в копии дерева +
>   Playwright (`apps/web/e2e/pwa.spec.ts`, конфиг `e2e/pwa-prod.config.ts`):
>   манифест/иконки, захват контроля SW, оффлайн-фоллбек со ссылкой на
>   локальный пульт — зелёные, без ошибок гидратации.

## 0. Рамки

**Позиционирование.** Наш PWA — это **онлайн-HMI**: устанавливаемое приложение с
пушами, киоском и честным поведением без сети. Оффлайн-варка — **не** задача
веб-пульта: браузер не общается с прибором напрямую (всё через сервер + Postgres),
а PWA с HTTPS-облака физически не может ходить на `http://192.168.…` (mixed
content + Private Network Access). Оффлайн-путь — встроенный веб-UI прошивки
(`http://<ip-прибора>/ui`); задача портала — сделать его обнаружимым (P5).

**Вне скоупа:** синк журнала по MQTT (бэклог D7 в `../brewforge`), self-hosted
LAN-деплой, прекэш SSR-страниц пульта (оффлайн он всё равно мёртв без сервера —
кэшировать нечестно), workbox/next-pwa (обвязка руками, как весь `sw.js`).

## P1 — Иконки и манифест (installability)

Самый дешёвый и заметный этап; без него установка выглядит сломанной.

- Сгенерировать из `app/icon.svg`: PNG **192** и **512** (`purpose: any`) +
  **maskable 512** (с safe-zone ~80%, иначе Android режет края в белом круге).
  Положить в `public/images/pwa/`.
- **`app/apple-icon.png`** (180×180, непрозрачный фон) — Next сам вставит
  `<link rel="apple-touch-icon">`; iOS манифестные иконки игнорирует.
- `app/manifest.ts`: массив `icons` (192/512/maskable), `id: "/"`,
  `description`, `shortcuts` (Приборы `/app/devices`, Варки `/app/brew-batches`,
  Склад `/app/inventory`).
- `display: "standalone"` оставляем (fullscreen ломает системные жесты, киоску
  хватает `?kiosk=1`).

## P2 — Регистрация SW при загрузке

Сейчас SW регистрируется только при включении пушей
(`use-push-subscription.ts:112`) — у остальных его нет вовсе.

- Хук `useServiceWorkerRegistration()` в `features/pwa/` (новая фича-папка),
  вызов из `components/providers.tsx`: `navigator.serviceWorker.register("/sw.js")`
  после load, под гардами (`"serviceWorker" in navigator`, secure context).
- **Только в production** (`process.env.NODE_ENV === "production"`): в `next dev`
  кэширующий SW конфликтует с HMR и протухшими чанками.
- `use-push-subscription` не трогаем — повторный `register("/sw.js")` идемпотентен.

## P3 — Оффлайн-слой в `sw.js`

Расширяем существующий рукописный `public/sw.js`, пуш-логика без изменений.

- **Версионированный кэш:** константа `CACHE = "nb-v1"`; на `activate` удалять
  чужие версии. Bump версии — вручную при изменении SW (деплой-автоматизацию не
  заводим, пока SW меняется редко).
- **`fetch`-хендлер, три правила:**
  1. Навигация (`request.mode === "navigate"`) → network-first; при отказе сети —
     `caches.match("/offline")`. Сами страницы **не кэшируем** (SSR, сессия).
  2. `/_next/static/*` (иммутабельные хэш-чанки) → cache-first.
  3. Всё остальное (в т.ч. `/api/*`, SSE) — не трогаем, сквозной `fetch`.
- **Страница `/offline`** — статический роут в `(public)`: «Нет сети» + блок
  «Прибор в локальной сети работает без интернета: откройте `http://<адрес>/ui`»
  (адреса — из localStorage, см. P5; нет сохранённых — общий текст).
  Прекэшится на `install`.
- Ловушка: `/offline` должен быть полностью самодостаточным после прекэша —
  инлайн-стили или гарантированно закэшированные чанки, никаких запросов данных.

## P4 — iOS

- `apple-touch-icon` — уже в P1.
- Пуши на iOS работают **только у установленного** PWA. В `NotificationOptIn`:
  если iOS-Safari и не standalone (`!matchMedia("(display-mode: standalone)")` и
  нет `navigator.standalone`) — вместо мёртвой кнопки показывать «Добавьте
  приложение на экран „Домой“, чтобы получать уведомления».

## P5 — Мостик к оффлайн-варке

- На пульте `/app/devices/[id]` и в настройках: ссылка **«Локальный пульт
  прибора»** → `<localUrl>/ui` (рендерить только при заданном `localUrl`;
  открывается в новой вкладке — это чужой origin, наш хром там не нужен).
- При загрузке пульта писать `{deviceName, localUrl}` в localStorage
  (`nb_device_local_urls`) — источник ссылок для `/offline` (P3).

## P6 — Проверка

- Lighthouse: installability без ошибок, иконки подхвачены.
- Ручной прогон: установка на Android и iOS (иконка не в белом круге, сплэш
  тёмный); режим полёта → открытие PWA → `/offline` со ссылкой на локальный
  пульт; пуш приходит и открывает нужный экран (регресс Phase 6); киоск
  `?kiosk=1` как раньше.
- Vitest: тест на `manifest.ts` (иконки объявлены и файлы существуют в
  `public/`), тест на маршрутизацию `fetch`-правил SW, если логика выносится в
  чистую функцию.
- `npm run typecheck` + суайт как обычно.

## Открытые вопросы (владельцу)

1. **Имя в манифесте:** сейчас `name/short_name: "NB"`. Если решится «hmelo» —
   поменять здесь же (память: hmelo-name-candidate).
2. **`start_url: /app/devices`** писался под киоск. Для обычного пользователя
   логичнее `/app` (дашборд). Предлагаю `/app`; киоск-закладка всё равно
   открывает свой URL.
