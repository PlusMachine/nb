# Страница «Рецепты» (`/recipes`) — навигация и фильтры

Документ описывает публичную витрину рецептов проекта NB (web-first платформа для
домашних пивоваров): глобальную навигацию, структуру страницы и — подробно — как
устроены фильтры. Цель — дать полный контекст для обсуждения UX/архитектуры.

> Стек: Next.js 15 (App Router) + React 18 + TypeScript strict, Tailwind +
> shadcn-style примитивы (`packages/ui`), PostgreSQL + Drizzle. Витрина —
> mobile-first.

---

## 1. Глобальная навигация (header)

Шапка (`components/shared/site-header.tsx`) общая для публичной зоны и рабочей зоны.

- **Логотип `NB`** → `/` (главная).
- **Разделы сайта** (видны из любой зоны, мост между публичным сайтом и рабочей
  зоной):
  - `Стили пива` → `/bjcp` (справочник BJCP с умным поиском — UX-первоисточник
    для пикера стиля на витрине рецептов).
  - `Калькуляторы` → `/calculators`.
  - `Рецепты` → `/recipes` (эта страница).
  - Активный раздел подсвечивается (тёмный фон), `aria-current="page"`.
- **Правый блок:**
  - Гость → кнопка `Войти` (`/login`).
  - Залогинен → кнопка `Рабочая зона` (`/app`) + меню пользователя
    (`Рабочая зона`, `Профиль`, `Выйти`; закрывается по Escape/клику вне).

Публичный layout (`app/(public)/layout.tsx`) оборачивает страницу в контейнер
`max-w-7xl` и подставляет сессию пользователя в шапку. Сама витрина `/recipes`
**публичная** — доступна без логина.

## 2. Структура страницы `/recipes`

Файл: `app/(public)/recipes/page.tsx` (серверный компонент).

Сверху вниз:

1. **Hero-блок** — заголовок «Рецепты сообщества» + подзаголовок.
2. **Тулбар** (`RecipesToolbar`) — поиск, сортировка, переключатель вида.
3. **Кнопка «Фильтры»** (`RecipesFilterSheet`) — **только на мобильных**
   (`lg:hidden`), открывает bottom-sheet с фильтрами; на кнопке бейдж с числом
   активных фильтров.
4. **Двухколоночная сетка** (`lg:grid-cols-[260px_1fr]`):
   - **Левая колонка (десктоп)** — sticky-сайдбар фильтров
     (`RecipesFilterSidebar`, скрыт на мобильных).
   - **Правая колонка** — активные чипы фильтров (`ActiveFilterChips`) + результаты
     (`RecipesResults` под `Suspense` со скелетоном).

То есть **одни и те же контролы фильтров** (`RecipesFilterControls`) рендерятся в
двух местах: в sticky-сайдбаре на десктопе и в bottom-sheet на мобильном.

### Что страница готовит на сервере

- `getBjcpCatalogData()` — каталог BJCP (семейства + стили), уже нужен для других
  целей, доп. запроса нет.
- `buildRecipeStyleSearchIndex(catalog)` — **компактный поисковый индекс**
  (только поля для поиска/отображения, без контента статей) для клиентского
  пикера стиля. Не гоняем весь каталог на клиент.
- `getPublicRecipeFamilyCounts()` — `{ familyId: число_рецептов }`, считает
  опубликованные рецепты по семействам (см. §6). **Семейства с 0 рецептов в карту
  не попадают.**
- `familyOptions` / `styleOptions` — лёгкие словари `id/code → название` для
  лейблов активных чипов.

## 3. Базовый принцип: всё состояние — в URL

Ключевая архитектурная идея: **фильтры, поиск, сортировка, страница и вид — это
query-параметры URL, а не локальный стейт компонентов.** Любой контрол лишь
патчит URL; страница (серверный компонент) перечитывает параметры и заново
запрашивает данные.

Плюсы: страницу можно расшарить ссылкой, она краулабельна (SEO), кнопки
браузера «назад/вперёд» работают, нет рассинхрона UI и данных.

Инфраструктура:

- **`useRecipeQueryNav()`** (`components/recipes/use-recipe-query.ts`) — хук
  навигации: читает живой `searchParams`, мержит патч и обновляет URL
  (`push`/`replace`) внутри `startTransition` — чтобы Suspense-граница показала
  скелетон во время загрузки.
- **`mergeRecipeQuery()`** (`features/recipes/recipes-url.ts`) — чистая функция
  слияния патча с текущим query:
  - `null` или пустая строка в патче → ключ удаляется (снятие фильтра);
  - прочие текущие ключи сохраняются (мерж, не перезапись);
  - любое изменение фильтра/поиска/сортировки сбрасывает `page` на 1
    (для пагинации и смены вида — `resetPage: false`);
  - дефолты в URL не пишутся: `sort=newest`, `view=grid`, `page=1` опускаются —
    URL остаётся чистым.

### Контракт URL-параметров

| Параметр              | Назначение                          | Пример              |
|-----------------------|-------------------------------------|---------------------|
| `q`                   | Поиск по названию/автору            | `q=west coast`      |
| `family`              | Фильтр по семейству BJCP (id)       | `family=ipa_hoppy`  |
| `style`               | Фильтр по стилю (BJCP-код)          | `style=21A`         |
| `colorMin`/`colorMax` | Диапазон цвета, SRM                 | `colorMin=6&colorMax=9` |
| `abvMin`/`abvMax`     | Диапазон крепости, %                | `abvMin=5&abvMax=7` |
| `ibuMin`/`ibuMax`     | Диапазон горечи, IBU                | `ibuMin=30`         |
| `sort`                | Сортировка                          | `sort=abv_desc`     |
| `page`                | Номер страницы                      | `page=2`            |
| `view`                | Вид списка (презентационный)        | `view=list`         |

`family` и `style` **взаимоисключающи** (оба резолвятся в один и тот же серверный
`styleId IN (...)`): выбор одного очищает другой.

## 4. Фильтры — подробно

Все контролы фильтров собраны в `RecipesFilterControls` в порядке:
**пикер стиля → шкала цвета → слайдер ABV → слайдер IBU → «Сбросить фильтры»**.

### 4.1. Пикер стиля/семейства (`RecipeStylePicker`)

Заменил два длинных нативных `<select>` (≈10 семейств / 80+ стилей — плохой
user-flow на телефоне). Состоит из **двух раздельных блоков без вложенности**:

**Блок «Семейство»** — ровный список кнопок во всю ширину:
- Первая строка — `Все семейства` (активна, когда не выбрано ни семейство, ни
  стиль; снимает фильтр).
- Далее — по строке на семейство. Показываются **только непустые** семейства (с
  рецептами на витрине), справа у каждой — **число рецептов** в этом семействе
  (приглушённый счётчик, `tabular-nums`). Семейства с 0 рецептов **скрыты** —
  фильтр не засоряется.
- Клик по семейству ставит `family=<id>` (и очищает `style`); повторный клик по
  активному — снимает фильтр. Длинные названия усекаются (`truncate` + `min-w-0`),
  не вылезают за сайдбар.
- Источник чисел — серверный `getPublicRecipeFamilyCounts()`; порядок и фильтрация
  пустых — чистая функция `orderedFamiliesWithCounts(index, counts)`.

**Блок «Поиск стиля»** — всегда видимое поле фаззи-поиска (не disclosure):
- Тот же скоринг-движок, что и умный поиск на `/bjcp`
  (`@nb/brewing-core`: `buildBjcpQueryVariants`, `foldBjcpSearchDiacritics`,
  `normalizeBjcpSearchText`, `scoreBjcpSearchText`) — поиск client-side,
  синхронно, без round-trip.
- Запрос < 2 нормализованных символов → пусто. Иначе — выпадающий `listbox`
  совпадений (топ-8 стилей) ровными строками `код · название` (напр. `21A ·
  American IPA`), плейсхолдер «Название или код, напр. American IPA».
- Понимает код (`21A`), русское и английское название, диакритику, кириллицу
  (`стаут` → `20B`).
- Клик по результату ставит `style=<код>` (и очищает `family`), очищает поле ввода.
- Когда поле пустое, но стиль выбран — показывается тёмная строка выбранного стиля
  с крестиком «Убрать стиль».

> Почему два блока, а не один комбинированный: предыдущая версия с
> disclosure-тогглом давала двухуровневую вложенность (открыть → потом ещё вводить
> поиск) — отвергнута как неудобная.

### 4.2. Шкала цвета пива (`RecipesColorScale`)

Заменила 7 серых чипов на **кликабельную градиентную шкалу реальных оттенков
пива**.

- 7 сегментов из `srmColorBands`, заливка — реальный цвет пива по середине
  SRM-диапазона (`srmToHex`):

  | Сегмент      | SRM   |
  |--------------|-------|
  | Соломенный   | 0–3   |
  | Золотистый   | 3–6   |
  | Янтарный     | 6–9   |
  | Медный       | 9–14  |
  | Коричневый   | 14–20 |
  | Тёмный       | 20–30 |
  | Чёрный       | 30–80 |

- Клик по сегменту ставит `colorMin`/`colorMax` границами бэнда; повторный клик
  по активному — снимает. Активный сегмент обведён рамкой (`ring`).
- Под шкалой — подпись выбранного оттенка + SRM или «Любой цвет».
- **a11y:** цвет не единственный сигнал — у каждого сегмента `aria-label`
  (`«Янтарный, SRM 6–9»`), `aria-pressed`, `sr-only`-текст; подпись снизу
  `aria-live="polite"`.

### 4.3. Слайдеры ABV / IBU (`RecipesRangeSlider`)

Заменили пары number-инпутов на **двухпальцевые слайдеры диапазона** (поверх
`@radix-ui/react-slider` через `SliderScaffold` из `packages/ui`).

- **ABV:** 0–20 %, шаг 0.1. **IBU:** 0–200, шаг 1 (`abvBound`/`ibuBound`).
- Значение читается из URL; **drag** обновляет только локальную подпись, **запись
  в URL — по отпусканию** (`onValueCommit`, режим `replace` — не плодим историю).
- **Граница диапазона = «нет фильтра»:** если нижний thumb на 0 — параметр `*Min`
  опускается; если верхний на максимуме — `*Max` опускается. Совпадает с серверным
  контрактом (отсутствующий параметр = безграничный).
- Подпись справа в легенде: «любой» / «до X» / «от X» / «X – Y» (+ единица).
- Логика маппинга — чистые функции `sliderValueFromParams` /
  `rangeSliderToParams` / `formatSliderRange` (`features/recipes/range-slider.ts`):
  клампы, своп перевёрнутых границ, снэп к шагу (убирает float-дрожание).

### 4.4. Кнопка «Сбросить фильтры»

Полный сброс — `router.push(pathname)` без query (все фильтры/поиск/сортировка
очищаются).

## 5. Тулбар, чипы, результаты

### 5.1. Тулбар (`RecipesToolbar`)

- **Поиск** — инпут с debounce 250 мс → `q` (режим `replace`). Ищет по названию
  рецепта и имени автора. Это **отдельный** поиск от поиска стиля в фильтрах
  (тот ищет по каталогу BJCP, этот — по тексту рецептов).
- **Сортировка** — нативный `<select>` → `sort` (`push`). Опции:

  | `sort`      | Лейбл           |
  |-------------|-----------------|
  | `newest`    | Сначала новые (дефолт) |
  | `rating`    | По рейтингу (NULLS LAST) |
  | `abv_desc`  | Крепче          |
  | `abv_asc`   | Слабее          |
  | `ibu_desc`  | Горше           |
  | `ibu_asc`   | Мягче           |
  | `color_asc` | Светлее         |
  | `color_desc`| Темнее          |
  | `name`      | По алфавиту      |

  (`popular` есть в контракте, но скрыт из UI — нет данных, маппится на `newest`.)
- **Переключатель вида** — сетка / список → `view` (без сброса страницы).

### 5.2. Активные чипы (`ActiveFilterChips`)

Над результатами — удаляемые чипы всех активных фильтров (поиск, семейство, стиль,
цвет, ABV, IBU). Клик по ✕ убирает соответствующий параметр(ы) из URL (мерж,
прочие сохраняются, `page` сбрасывается). Лейблы семейства/стиля резолвятся из
серверных словарей; цвет — по названию бэнда; диапазоны — «от/до/X–Y».

### 5.3. Результаты, пагинация, пустые состояния (`RecipesResults`)

Серверный async-компонент под `Suspense`:

- Дёргает `searchPublicRecipes(filters)`, показывает счётчик («Найдено N
  рецепт/рецепта/рецептов» — со склонением), сетку карточек (`RecipesGrid`,
  grid/list) и пагинацию.
- **Пагинация** (`RecipesPagination`) — numbered с окном `1 … c-1 c c+1 … N` и
  «Назад/Дальше». Рендерится как `<Link>` (краулабельно), меняет только `page`.
  Размер страницы по умолчанию 24 (макс. 48).
- **Пустое состояние** — два варианта: `no-results` (фильтры активны, но ничего не
  нашлось) либо `no-recipes` (рецептов нет вовсе).

## 6. Серверный путь (контракт данных)

**Жёсткая граница:** редизайн фильтров — чисто презентационный. URL-контракт и
серверный путь (`public-recipe-query.ts`, `service.ts`, SQL) **не менялись**.

- **`parsePublicRecipeFilters`** — парсит `searchParams` в валидированный
  `PublicRecipeFilters` с дефолтами и клампами (мусор тихо нормализуется, страница
  не падает). Диапазоны клампятся (color 0–80, abv 0–20, ibu 0–200), перевёрнутые
  границы свопаются.
- **`resolveStyleScope(filters)`** — резолвит `family`/`style` в набор
  `recipes.styleId` для SQL `WHERE styleId IN (...)`. Семейства берутся из того же
  каталога BJCP, что и `/bjcp`; учитываются кросс-листинговые стили. `null` если
  фильтр не задан; `[]` если задан, но ничего не сматчилось (→ пусто, без падения).
- **`searchPublicRecipes`** — собирает SQL: `publicationState='published'` +
  условия (`q` по названию/автору через `ilike`, `styleId IN`, `color/abv/ibu`
  через `gte/lte`), сортировка, пагинация, `count(*)` для total.
- **`getPublicRecipeFamilyCounts`** (для счётчиков семейств) — один
  `GROUP BY styleId` по опубликованным рецептам, затем маппинг в семейства через
  `resolveFamilyStyleScopes()` (обратная сторона `resolveStyleScope`:
  `familyId → styleId[]`). Возвращает только непустые семейства. Это **не** меняет
  контракт витрины — отдельный агрегат для UI фильтра.

## 7. Mobile-first и доступность

- **Десктоп (`lg+`):** sticky-сайдбар фильтров слева, результаты справа.
- **Мобильный (`< lg`):** сайдбар скрыт; кнопка «Фильтры» открывает bottom-sheet
  (ручной `role="dialog"`, `aria-modal`, закрытие по Escape/overlay/крестику,
  кнопка «Показать результаты»). На кнопке — бейдж числа активных фильтров
  (`countActiveRecipeFilters`: каждое измерение — поиск/семейство/стиль/цвет/ABV/IBU
  — считается один раз; sort/page/view не учитываются).
- **a11y:** цветовая шкала и слайдеры дублируют сигнал текстом/числами и
  `aria`-атрибутами; навигация по семействам — кнопки с `aria-pressed`;
  пагинация — `nav` + `aria-current`.

---

## 8. Что намеренно вне скоупа

- Не тронуты: серверный SQL-путь, рейтинги, карточки рецептов, структура
  пагинации, текстовый поиск тулбара.
- `method`-фильтр есть в контракте, но в текущей фазе не применяется (метод нигде
  не хранится).
- Счётчики у семейств считают **рецепты на витрине**, а не число стилей в
  справочнике (это была отдельная правка — раньше ошибочно показывался styleCount
  каталога).
