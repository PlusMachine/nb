# SEO-аудит — 2026-07-06

Полный технический и продуктовый SEO-аудит платформы (ветка `feature/home-redesign`).
Методика: 9 независимых аудитов по разделам/измерениям (рецепты, каталог, BJCP, статьи,
калькуляторы, главная+служебные, инфраструктура, семантика/перелинковка, производительность),
каждая находка адверсариально перепроверена по коду вторым проходом (часть — живыми
curl-запросами); параллельно — исследование требований Google (июль 2026), специфики
Яндекса/рынка РФ и разбор SEO конкурентов (Brewer's Friend, Brewfather, BeerSmith,
Grainfather, maischemalzundmehr, King Arthur, BBC Good Food).

Постоянные правила для новых разделов — в `docs/seo-playbook.md` (этот файл — снимок
состояния, плейбук — то, что живёт дальше).

> **Статус реализации (2026-07-07):** код-находки закрыты — A0–A15 полностью,
> P2/P3-пакеты (robots, not-found, 308, canonical, крошки, картинки, кэш выборок
> главной, posthog/demo-бандлы), S1/S2 (гейтинг индексации UGC v1 + клоны), S4/S12
> учтены в разметке. A12 закрыт минимальным вариантом (TTL-кэш; PPR/статизация
> публичной зоны — отдельное решение владельца из-за серверной темы/сессии в layout).
> Открыты стратегические: S3 (авторы, /about), S6–S8/S10 (чеклист запуска домена,
> staging-noindex, Метрика, clean-param), S11 (видео), история слагов рецептов
> (заморозка сделана), динамические OG-картинки рецептов.

## Резюме

Фундамент лучше среднего по нише: `robots.ts`/`sitemap.ts`/`metadataBase` есть, каталог
ингредиентов — образцовый SEO-слой (canonical, noindex поиска, JSON-LD, честные 404),
непубличный контент не утекает, публичные страницы серверные, пагинация краулабельна.
Но три системные дыры съедают почти весь потенциал:

1. **Редакционные статьи физически не индексируемы** — деталки не существует (P0).
2. **Ядро контента не задекларировано**: рецепты и калькуляторы отсутствуют в sitemap,
   на них нет ни canonical, ни JSON-LD, ни OG — при том что по исследованию рынка
   именно калькуляторы и структурированные рецепты — самые доступные кластеры RU-выдачи.
3. **Ключевая перелинковка живёт только в клиентском JS** (стиль→рецепты, хаб BJCP),
   а для Яндекса с его слабым JS-рендерингом это означает «её нет».

Итог по объёму: 1 × P0, 15 × P1, ~30 × P2, ~25 × P3 (после склейки дублей между
секциями) + 12 стратегических тем вне кода. Ни одна находка при перепроверке не была
полностью опровергнута; 11 скорректированы по severity/деталям.

## P0 — блокирует индексацию целого раздела

### A0. Деталки редакционных статей не существуют: весь контент-маркетинг — цепочка 308→404
`apps/web/app/(public)/articles/[slug]/page.tsx:1-6` — роут содержит только
`permanentRedirect('/bjcp/<slug>')` (рудимент переезда BJCP), а `/bjcp/[slug]` для
слагов контент-статей отвечает `notFound()`. При этом на `/articles/<slug>` ссылаются
листинг (`articles/page.tsx:37`), главная (`page.tsx:118`) и sitemap (`sitemap.ts:44-47`).
Проверено вживую: `/articles/kak-svarit-pervoe-pivo` → 308 → 404.
`getPublishedContentArticleBySlug` (`features/content-articles/service.ts:297`) не имеет
ни одного потребителя-роута. Вся инфраструктура при этом готова: в БД есть
`seoTitle/seoDescription/coverImageUrl/publishedAt/authorId`, слаг замораживается после
публикации, обложка сознательно JPEG под og:image, перелинковка `related-links.ts` написана.

**Фикс:** создать страницу деталки: рендер через `getPublishedContentArticleBySlug`
(+`notFound()`), `generateMetadata` из `seoTitle`/`seoDescription` + canonical + OG
type=article с обложкой, JSON-LD `BlogPosting` (author/datePublished/dateModified/image)
+ `BreadcrumbList`, блок «Дальше» из `getRelatedLinksForArticle`. Legacy-редирект на
`/bjcp/<slug>` оставить только для слагов, реально существующих в `@nb/content`.
До запуска решить: `/articles/*` или `/guides/*` (CLAUDE.md обещает `/guides`, код живёт
на `/articles`) — см. тему S9 про неймспейсы слагов.

## P1 — существенно режет SEO-потенциал

### A1. Sitemap не покрывает ядро контента (рецепты, калькуляторы, /brewforge)
`apps/web/app/sitemap.ts:19-59` — есть статика, BJCP, гайды, каталог; нет ни одного
`/recipes/[slug]` (главный SEO-актив), ни одного из 15 `/calculators/[slug]`, нет
`/brewforge`. Обнаружение рецептов краулером идёт только через страницы пагинации,
которые сами канонизированы на `/recipes` (см. A8).
**Фикс:** выборка опубликованных рецептов (slug+updatedAt) в `features/recipes/service`;
`allCalculatorSlugs` из реестра; `"/brewforge"` в staticPaths. На вырост — `generateSitemaps`.

### A2. Sitemap генерируется один раз на билде
`sitemap.ts` читает БД, но без `export const revalidate` метадата-роут кэшируется при
сборке: новые рецепты/статьи/ингредиенты не попадут в sitemap до следующего деплоя.
**Фикс:** `export const revalidate = 3600` в `app/sitemap.ts`.

### A3. Нет JSON-LD Recipe (и вообще никакой разметки) на рецептах
Ни `Recipe`, ни `BreadcrumbList`, ни `ItemList` на листинге — grep по `ld+json` в зоне
рецептов пуст. Все данные уже в `RecipeDetailDto` (ингредиенты, ABV/IBU/OG, рейтинг,
фото, даты, автор). По исследованию: Recipe rich results живы, ограничений на алкоголь
в органике нет, а `aggregateRating` не отдаёт **ни один** конкурент ниши — прямое
конкурентное окно (звёзды в сниппете).
**Фикс:** `Recipe` + `BreadcrumbList` на деталке (server component), `ItemList` на
листинге. В `aggregateRating` — только видимый на странице `ratingAvg`/`ratingCount`
(НЕ внутренний `ratingBayes` — расхождение разметки с контентом карается). Инструкции —
как `HowToStep` из brew-steps; nutrition (калории) считается из OG/FG — приём
Brewer's Friend. Экранирование `</` по образцу `jsonLdScriptProps`
(`features/ingredients/seo.ts:447`).

### A4. Метаданные деталки рецепта бедные, OG-слоя нет
`recipes/[slug]/page.tsx:14-17` — title `<название> · Рецепт` без стиля/ABV; description —
сырое описание до 6000 символов без обрезки либо один и тот же generic-фолбэк; openGraph/
twitter отсутствуют (фото есть в DTO). Шаблон лидера ниши: `<имя> — рецепт <стиль>` +
description из данных «ABV …%, IBU …, объём … л, солод: …, хмель: …».
**Фикс:** билдер метаданных в `features/recipes/seo.ts` по образцу каталога.

### A5. Canonical отсутствует почти на всём сайте
Задан только на 4 поверхностях (листинг `/recipes`, `/articles`, `/bjcp/[slug]`, каталог).
Нет на: деталках рецептов (`recipes/[slug]/page.tsx:8-24`), калькуляторах (состояние
живёт в query — расшаренные `/calculators/ibu?og=...` = индексируемые дубли, а такие
ссылки массово рендерятся в HTML из `buildCalculatorHref`), главной, `/bjcp`, `/brewforge`,
`/demo`, `/legal/*`, `/login`. Любая utm-метка = дубль.
**Фикс:** self-canonical на каждой публичной странице (metadataBase уже настроен,
достаточно относительных путей).

### A6. Мягкие 404 у рецептов: снятый с публикации рецепт отдаёт HTTP 200
`recipes/[slug]/page.tsx:18-23` — `generateMetadata` в catch возвращает заглушку
«Рецепт не найден» вместо `notFound()`, а `loading.tsx` рядом начинает стриминг со
статусом 200 до того, как тело страницы дойдёт до `notFound()`. Каталог от этой ловушки
защищён явно (комментарий в `catalog/[source]/[id]/page.tsx:202`) — рецепты нет.
У `recipes/id/[id]` то же самое + `redirect()` даёт 307 вместо 308.
**Фикс:** `notFound()` прямо в `generateMetadata`; у legacy-роута `/recipes/id/[id]`
убрать `loading.tsx` и перейти на `permanentRedirect`.

### A7. Перелинковка «стиль BJCP → рецепты стиля» невидима поисковикам
`style-recipes-provider.tsx:46` — рецепты стиля грузятся клиентским fetch к
`/api/recipes/by-style`, который закрыт в robots (`/api/`). Заблокированные robots
ресурсы Google не фетчит даже при JS-рендеринге; Яндекс JS рендерит плохо. Живая
проверка: в серверном HTML страницы стиля ноль ссылок `href="/recipes/…"`. Самая ценная
тематическая связка (справочник → UGC) не существует для краулера.
**Фикс:** отдавать первые N рецептов стиля серверным пропсом (выборка уже есть —
используется для страницы стиля), клиентский fetch оставить для живого обновления.

### A8. Хаб /bjcp отдаёт краулеру малую часть ссылок, крошки плодят параметрические дубли
Живая проверка: HTML `/bjcp` содержит каталог (зона рендерится динамически), но только
~18 из ~120 ссылок на стили (аккордеон рендерит `<Link>` только для раскрытой категории,
навигация по семействам — кнопки `router.push` без href). При этом у `/bjcp` нет
canonical, а крошки со всех страниц стилей ведут на `/bjcp?view=bjcp&category=…` —
параметрические копии хаба индексируются как дубли.
**Фикс:** canonical на `/bjcp`; серверный полный индекс стилей (сворачивать визуально,
не убирая `<Link>` из DOM); крошку вести на чистый `/bjcp`.

### A9. Title главной — «NB»
`layout.tsx:26` default title «NB», страница задаёт только description. Главная не
таргетирует ни один запрос. **Фикс:** явный title с ключами («…платформа для домашних
пивоваров: рецепты, калькуляторы, стили BJCP»), расширить и default в layout.

### A10. Калькуляторы не содержат слово «калькулятор» и прячут свой контент
Ни в одном из 15 title/description/H1 нет слова «калькулятор» («Горечь пива (IBU)» вместо
«Калькулятор IBU») — а весь кластер запросов именно такой, и по исследованию RU-выдача
здесь самая слабая (голые формы, сайты-однодневки): это кластер №1 по скорости захвата.
Заодно: готовые тексты `whenToUse`/`nextSteps` из `catalog.ts` нигде не рендерятся
(мёртвые поля), формулы/ошибки спрятаны в свёрнутые `<details>`, на листинге после h1
сразу h3 без h2-секций и без вводного текста.
**Фикс:** поле `seoTitle` в реестре («Калькулятор ABV — крепость, сбраживание и калории»),
вывести `whenToUse` видимым абзацем, `nextSteps` в блок «Дальше», секции листинга — h2.

### A11. JSON-LD Article у BJCP-стилей полупустой, даты фиктивные
`bjcp-article-page.tsx:375-401` — нет `image` (обязателен для Article rich results),
`datePublished/dateModified`, `mainEntityOfPage`, `publisher.logo`; BreadcrumbList в
JSON-LD нет (видимые крошки есть). Даты стилей генерируются как «2026-03-01 + порядковый
индекс» (`packages/content/src/bjcp.ts:448-451`) и уходят в sitemap — фиктивны и
нестабильны (вставка стиля сдвигает даты всех последующих).
**Фикс:** дополнить payload реальными полями; дату ревизии хранить в данных BJCP или
не отдавать lastModified вовсе.

### A12. Вся публичная зона рендерится динамически на каждый запрос
`app/layout.tsx:42-46` читает `cookies()`/`getSessionUser()` на каждый запрос,
`(public)/layout.tsx:5` — ещё раз: `generateStaticParams` у `/bjcp/[slug]` и
`/calculators/[slug]` фактически не даёт статики, главная делает 4 БД-запроса на каждый
анонимный хит, кэшей уровня страниц в зоне нет. TTFB для краулера = время Postgres.
**Фикс:** разорвать «сессия ради хрома» и рендер контента (PPR/Suspense вокруг
session-зависимого хрома или клиентская догрузка хрома); как минимум — React `cache()` +
процессный TTL-кэш (образец: `features/ingredients/service.ts:340`) для BJCP-каталога,
счётчиков и выборок главной; `export const revalidate` на контентных деталках.

### A13. /login без metadata и noindex, ?next= плодит дубли
`login/page.tsx` не экспортирует metadata (title «NB»); публичные страницы ссылаются на
`/login?next=…` минимум с 3 разными query; все гейты `requireUser` редиректят на такие
URL. **Фикс:** `robots: { index: false, follow: true }` + canonical `/login` + title
«Вход»; `/login` в disallow.

### A14. OG-слой отсутствует как класс
В корневом layout нет `openGraph` (siteName, locale ru_RU, type) и `twitter`; во всём
приложении ноль файлов `opengraph-image.*`. Шаринг любой страницы в Telegram/VK — голая
ссылка. Для RU-дистрибуции контента (Telegram-каналы пивоваров) это прямая потеря.
**Фикс:** дефолтный блок в layout + `app/opengraph-image.png` (1200×630); дальше —
динамические OG-картинки рецептов из SRM-цвета + параметров (наша SRM-айдентика,
конкуренты подкладывают логотип — их разметка из-за этого не проходит в rich results).

### A15. Смена названия рецепта меняет slug опубликованного рецепта без редиректа
`features/recipes/service.ts:1550-1561` — slug пересчитывается при любом изменении title,
истории слагов нет, старый URL = 404: накопленные ссылки и позиции сгорают.
**Фикс (минимум):** заморозить slug после первой публикации (у контент-статей это уже
сделано — `content-articles/service.ts:153-157`); полноценно — таблица истории слагов +
`permanentRedirect`.

## P2 — заметные улучшения

**Индексация и гигиена**
- `robots.ts` не закрывает: `/ui-playground` (dev-страница доступна в prod — лучше
  `notFound()` вне development), `/login`, `/recipes/id/`, `/catalog/new`,
  `/catalog/custom/`, `/profile`, `/settings` (группа `(app)` не даёт префикса URL —
  disallow `/app` их не покрывает).
- Фото рецептов отдаются только с `/api/recipe-images/*`, закрытого в robots — рецепты
  невидимы в Google Images/Яндекс.Картинках, а будущие og:image/Recipe.image по этому
  пути не пройдут валидацию. Фикс: точечный `allow: ['/api/recipe-images/']` или rewrite
  на чистый путь.
- Архивные (isActive=false) ингредиенты остаются индексируемыми сиротами
  (`features/ingredients/service.ts:410` — выборка деталки без фильтра). Фикс: 404 или noindex.
- Пагинация за пределами диапазона — soft-404 (200 + пустое состояние + самоканоничный
  URL): `/catalog/hops?page=999` (`catalog/content.tsx:78,500`). Фикс: `notFound()` при
  `page > totalPages`.
- Страницы пагинации `/recipes?page=N` канонизированы на корень — глубокие рецепты
  теряют вес; после добавления в sitemap некритично, но правильнее self-canonical для
  чистого `?page=N` (образец уже есть в каталоге).
- Legacy-алиасы слагов BJCP отдают дубль 200 вместо `permanentRedirect`
  (`bjcp/[slug]/page.tsx:51-57`).
- `/catalog?category=fermentable` и `/catalog?subtype=malt` — самоканоничные дубли с
  базовым title (вторая — полный дубль лендинга malts).
- Нет корневого `app/not-found.tsx` — системная английская заглушка (статус 404
  корректен, но без навигации; поведенческий минус в Яндексе).
- `lastModified: new Date()` у всей статики и лендингов sitemap — обесценивает честные
  updatedAt рядом. Фикс: убрать или зашить реальные даты; лендингам — max(updatedAt).
- `APP_URL` дефолтится в `http://localhost:3000` без прод-гварда
  (`packages/shared/src/index.ts:8`) — забытая переменная молча уводит canonical/sitemap/
  robots в localhost. Фикс: fail-fast при NODE_ENV=production. Плюс захардкоженный
  localhost в ошибочных ветках OAuth-роутов (`api/auth/oauth/{yandex,vk}/route.ts:10`).
- Нет RSS/Atom-фида статей и нет IndexNow — для Яндекса это главный ускоритель
  индексации новых страниц («минуты, а не недели»).
- Деталка рецепта без явной кэш-политики (`revalidate`) — `revalidatePath` при правках
  уже вызывается, не хватает только TTL на роуте.

**Разметка и метаданные**
- BreadcrumbList JSON-LD: нет на рецептах (и UI-крошек тоже — только «← Рецепты»),
  нет на BJCP (UI есть); у каталога крошки — голый div без `<nav aria-label="Breadcrumb">`.
- OG-разметка и картинки по разделам: BJCP (`twitter card summary_large_image` объявлен
  без image при живых hero), статьи, калькуляторы, каталог.
- JSON-LD `Organization` + `WebSite` на главной нет. `WebSite.name` — главный сигнал для
  Site Names в выдаче Google; критично при выборе имени (NB vs hmelo). SearchAction не
  добавлять — sitelinks searchbox мёртв (убран в 2024).
- Product на ингредиентах без offers/rating не даст rich results (Google требует
  минимум одно из review/aggregateRating/offers). Держать как задел допустимо; правильнее
  добавить aggregateRating, когда появятся оценки ингредиентов, или не ждать сниппетов.

**Перелинковка и контент**
- Ингредиенты рецепта не ссылаются на каталог (`ingredientCatalogItemId` есть в контракте,
  ссылок нет); блока «похожие рецепты» нет. По конкурентному разбору хаб
  «ингредиент → рецепты с ним» не делает никто в нише — наша связка каталог↔рецепты
  может стать уникальной.
- `getRelatedLinksForArticle` — мёртвый код (перелинковка статей написана, не подключена).
- Со страницы стиля BJCP нет ссылок на калькуляторы/гайды (входящие есть, обратных нет).
- Статьи/BJCP не ссылаются на конкретные калькуляторы — у деталки калькулятора один
  родитель (индекс).
- `/brewforge` — почти сирота: одна входящая ссылка с главной, нет в футере.
- `/calculators` — thin: нет вводного текста, заголовки прыгают h1→h3.

**Производительность (CWV)**
- `posthog-js` статически в общем бандле каждой страницы (init при этом честно ждёт
  согласия) — перевести на динамический import после согласия.
- `/demo` синхронно тянет всю симуляцию BrewForge (1590 строк state-machine) + пульт +
  график — обернуть в `next/dynamic`.
- Картинки в теле статей без width/height (реальный CLS на лонгридах); обложки статей

## Стратегический слой (вне текущего кода)

- **S1 [P1] UGC-гейтинг для индекса.** Единственный гейт — `publicationState=published`:
  любой пользователь одной кнопкой создаёт индексируемую страницу. Как только рецепты
  попадут в sitemap, это канал thin-content/спама — Яндекс за это режет весь хост (МПК).
  Никто из конкурентов гейтинг не делает — на малом доменном авторитете он критичен.
  Решение: порог качества для индексации (описание/оценки/сваренность), ниже порога —
  noindex (страница живёт, в sitemap не идёт).
- **S2 [P1] Клоны рецептов** — штатный флоу (`clonedFromRecipeId`), опубликованный клон =
  дубль. Решение: canonical на источник или noindex для клонов без существенных правок.
- **S3 [P1] E-E-A-T: нет страниц авторов и «О проекте».** Автор — некликабельные
  инициалы. Для алко-смежной тематики (YMYL-adjacent) и Яндекса «кто это пишет» — прямой
  фактор. Решение: `/about`, публичные профили авторов, byline+блок автора на статьях,
  `author.url` в разметке.
- **S4 [P2] Правила разметки рейтингов**: в `aggregateRating` — видимый `ratingAvg`,
  не внутренний `ratingBayes`; тип статей `review` — кандидат на Review-разметку;
  self-serving reviews на /brewforge запрещены правилами Google.
- **S5 [P2] 18+ = age-notice, не age-gate — зафиксировать как инвариант.** Текущий баннер
  SEO-безопасен (контент рендерится под ним). Блокирующий оверлей/редирект убьёт
  индексацию всего сайта в один коммит: Googlebot не нажимает кнопки. Если юридически
  потребуется гейт — только JS/CSS-оверлей поверх полного HTML. Ограничения алкотематики
  бьют по платным каналам (Директ запрещает), не по органике, — поэтому SEO для этой ниши
  основной канал по определению.
- **S6 [P2] Выбор домена — SEO-решение**: .ru vs .com, регион в Вебмастере, проверка
  истории домена по archive.org до покупки, возраст тикает с первой индексации — завести
  домен с индексируемой заглушкой заранее. Все canonical/OG/sitemap зависят от него.
- **S7 [P2] Не-prod окружения не защищены от индексации** — добавить `X-Robots-Tag:
  noindex` для staging/preview (когда окружение != production).
- **S8 [P2] Яндекс.Метрика отсутствует** — это не только аналитика: «обход по счётчикам»
  ускоряет индексацию, связка с Вебмастером. Подключить за существующий cookie-гейт.
- **S9 [P2] Неймспейс слагов**: BJCP-стили и файловые статьи делят `/bjcp/<slug>`,
  CMS-статьи заявлены на `/articles/<slug>` — развести (`/guides/*` для CMS?) и
  задокументировать правило уникальности до запуска.
- **S10 [P2] Clean-param для Яндекса** невозможен в `MetadataRoute.Robots` — при
  необходимости склейки параметрических дублей именно в Яндексе (где canonical — лишь
  рекомендация) перейти на route-handler для robots.txt с секцией `User-agent: Yandex`.
- **S11 [P3] Видео-стратегия**: выдача «как сварить пиво» перегружена видео-блоками —
  без YouTube/VideoObject этот инвентарь недоступен. Принять решение делаем/нет.
- **S12 [P3] Языковая политика**: одноязычному сайту hreflang не нужен — зафиксировать;
  `og:locale: ru_RU` добавить при внедрении OG.

## Рынок и приоритеты кластеров (из исследования выдачи RU)

Конкуренты в RU-выдаче — контент-маркетинг магазинов (malt.ru, mirbeer.ru, rdshop.ru,
beermachines.ru), форумы (homedistiller.ru — длинный хвост), устаревший Бир.рф
(ближайший функциональный аналог), федеральные медиа на головных запросах. Ниша
«продуктового» контентного сайта (структурированные рецепты + интерактив + справочники)
фактически вакантна. Платный трафик в нише законодательно почти закрыт → все живут на SEO.

Порядок захвата (от самого доступного):
1. **Калькуляторы** — выдача слабейшая (голые формы, однодневки, укр. домены); наш
   уровень с формулами и объяснениями может забрать кластер целиком; отличные
   поведенческие → разгон домена. Требует: A1, A5, A10.
2. **BJCP/стили пива на русском** — в выдаче только пересказы BJCP-2015; наша связка
   «стиль → рецепты → калькуляторы» уникальна. Требует: A7, A8, A11.
3. **Справочник ингредиентов** («хмель каскад характеристики», «дрожжи US-05
   температура») — конкуренция с тонкими карточками магазинов; наш каталог сильнее.
   Уже почти готов; добить перелинковку с рецептами.
4. **Длинный хвост рецептов по стилям** («NEIPA зерновой рецепт») — против
   статей-пересказов, с Recipe-разметкой и звёздами. Требует: A1, A3, A4, S1.
5. **«Как сварить пиво»** (головной) — забит магазинами и медиа; заходить хвостом после
   набора траста. Гайды — сначала починить A0.
6. **«Автоматическая пивоварня с управлением с телефона»** — подхвост почти пуст,
   угол BrewForge.

Факты Google (июль 2026), на которые опираются правила: Recipe rich results живы и
применимы к пиву (ограничений на алкоголь в органике нет); HowTo мёртв с 2023,
FAQPage отключён для всех с 07.05.2026 — не размечать; sitelinks searchbox мёртв,
но `WebSite.name` нужен для Site Names; Product требует review/rating/offers;
SoftwareApplication требует rating — калькуляторам достаточно WebPage+BreadcrumbList.
Яндекс: JSON-LD принимает ограниченно (Article/Breadcrumb ок), турбо-страницы мертвы
(апрель 2025), IndexNow жив и рекомендуется, поведенческие факторы — главное отличие,
mobile-first.
