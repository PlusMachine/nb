# Помощник варки (зона A) — редизайн страницы партии

> Страница `/app/brew-batches/[id]` для варки БЕЗ устройства («Помощник» по терминологии
> `brewery-command-center-l2-redesign.md` §1.2). Заземлено на тот же ресёрч
> (`brewery-command-center-ux-research.md`) + аудит текущего кода (2026-07-03).
> Статус: спека на реализацию.

## 0. Рамки

- **Что переделываем:** информационную архитектуру и flow страницы партии — чтобы она была
  пошаговым помощником варочного дня (референс — Brewfather Brew Tracker), а не набором форм учёта.
- **Device-путь не трогаем:** партия с привязанным контроллером живёт по спеке L2 (`LiveDashboard`
  остаётся героем). Эта спека — про партию с `deviceId = NULL`. Акты/«замеры по месту» (§5) позже
  применимы и к device-партии, но это отдельная фаза.
- **Бэкенд почти не меняется:** `brewPlanSnapshot`, `brewDayProgress`, журнал замеров и движок
  списания склада уже дают все данные. Новое — только чистые резолверы (курсор, акты) и
  синтетические шаги; таблиц/миграций для MVP не нужно.

## 1. Диагноз текущей страницы

| # | Симптом (как видит пользователь) | Причина в коде |
|---|---|---|
| 1 | Самое видное на странице — чёрные «В брожение» / «Отменить варку», не относящиеся к процессу | `BrewLifecycle` — админ-виджет смены статуса — стоит первым блоком; primary-кнопка страницы мутирует статус, а не ведёт варку |
| 2 | Степпер статусов выглядит как табы, но клик по нему меняет статус | Чипы `FLOW` в `brew-lifecycle.tsx` — кликабельные сеттеры без подтверждения |
| 3 | «Непонятные поля» — гид не читается как план дня | `BrewDayGuide` — плоский чеклист ВСЕХ стадий сразу (затор…розлив), без «текущего шага», без привязки к статусу партии: розлив можно отметить в статусе «Запланирована» |
| 4 | Формы замеров и плитки «—» до того, как что-либо произошло | `BrewJournal` рендерится всегда, статы OG/FG/ABV пустыми прочерками (та же боль, что «нулевые stat'ы» калькуляторов) |
| 5 | Склад и заметки — контекстлесс секции внизу | «Списать со склада» — момент старта варки, а не вечная кнопка; заметки не привязаны к моментам |
| 6 | «Нет кнопки начать» | Вход в варочный день размазан: «Начать варку» = смена статуса в виджете, гид стартует «сам собой» |
| 7 | Нет охлаждения | `buildBrewDaySteps` не строит шаг охлаждения между вирпулом и внесением дрожжей |

Корневая проблема одна: **у страницы нет машины состояний**. Статус партии почти ничего не
определяет в раскладке — а именно он и есть «время» варки.

## 2. Принципы (из подтверждённого ресёрча)

| Принцип | Основание |
|---|---|
| Герой экрана = **текущий шаг** крупно + таймер + «что дальше» | любимое #1 (гид с промптами); Brewfather Brew Tracker |
| Страница ветвится по статусу партии: показываем **релевантный акт**, остальное свёрнуто | самоочевидность > богатство (#4, анти-RAPT) |
| Статус двигается **гидом** (CTA завершения акта), а не отдельным виджетом | боль #4 «clunky»; виджет статуса = плата, торчащая наружу |
| Замеры/склад/заметки — **по месту во времени**, не секциями-вечняками | гладкий workflow рецепт→варка (Brewfather) |
| Мобайл = одна колонка, крупные цели нажатия, быстрые действия в зоне пальца | паритет #5; на варке руки заняты/мокрые |
| Алерты таймеров должны переживать вкладку (web-push с сервера) | боль #2 (обрыв молча убивает алерт хмеля) |

## 3. Архитектура: страница = машина состояний («акты»)

| Статус партии | Акт | Герой | Что ещё на экране |
|---|---|---|---|
| `planned` | **Подготовка** | План дня + CTA «Начать варочный день» | чек подготовки: склад, вода, оборудование |
| `brewing` | **Варочный день** | Текущий шаг + таймер + «Готово» | этап-полоса, шаги текущего этапа, свёрнутые прошлые/будущие, быстрые «+ Заметка / + Замер» |
| `fermenting` | **Брожение** | День N из M + nudge (`resolveBrewNudge`) | шаги брожения по дням (дрохмель, колд-краш…), замеры FG, розлив в конце |
| `completed` | **Итог** | `BrewCompletionSummary` (есть) | план↔факт, оценка рецепта, весь гид read-only как история |
| `cancelled` | **Архив** | бейдж + «Вернуть в план» | прогресс read-only |

Переходы = CTA завершения акта (или ручной escape hatch, §6). Порядок секций внутри акта —
по убыванию актуальности «сейчас».

### 3.1 Акт «Подготовка» (`planned`)

```
┌────────────────────────────────────────────────────────┐
│ ‹ Все варки   Тропический IPA #3   [Запланирована]  ⋯ │
│ по рецепту «Тропический IPA» · запланирована на 5 июля │
├────────────────────────────────────────────────────────┤
│ План дня                                               │
│ Затор 60 мин → Кипячение 60 мин → Вирпул 20 мин →      │
│ Охлаждение · ≈ 3 ч · 14 шагов · цель OG 15.2 °P        │
│                                                        │
│ Подготовка                                             │
│  ○ Ингредиенты: 8 позиций      [ Списать со склада ]   │
│  ○ Вода: 32 л                                          │
│                                                        │
│ [ ▶ Начать варочный день ]                             │
└────────────────────────────────────────────────────────┘
```

- **«Начать варочный день»** — единственная primary-CTA страницы (это и есть «кнопка начать»).
  Ставит `status = brewing` (`startedAt` уже проставляется сервисом) и открывает акт 1.
- «План дня» — превью таймлайна из снапшота: длительности этапов, суммарная оценка, цель OG.
  Считается тем же `buildBrewDaySteps` — новый чистый хелпер `summarizeBrewDayPlan`.
- Склад: текущий `BrewInventory` встраивается строкой чек-листа подготовки. Если при старте
  не списано — мягкий промпт в момент CTA («Ингредиенты не списаны — списать?»), не блокер.
- Никаких форм замеров и плиток «—» в этом акте.

### 3.2 Акт «Варочный день» (`brewing`)

```
┌────────────────────────────────────────────────────────┐
│ ‹ Все варки      Тропический IPA #3     [Варится]   ⋯ │
├────────────────────────────────────────────────────────┤
│ Затор ✓ ─ Кипячение ● 2/5 ─ Вирпул ─ Охлаждение        │  этап-полоса
│ ┌─ СЕЙЧАС ─────────────────────────────────────────┐   │
│ │ Кипячение сусла                    41:23 / 60:00 │   │  текущий шаг крупно
│ │ следом: Внести Citra 30 г — через 11:23          │   │  次-подсказка
│ │ [ сброс таймера ]                 [ Готово ✓ ]   │   │
│ └──────────────────────────────────────────────────┘   │
│ Кипячение                                              │
│  ✓ Начало кипячения                                    │
│  ● Внести: Magnum 15 г · за 60 мин до конца            │
│  ○ Внести: Citra 30 г · за 30 мин до конца             │
│  ▸ Вирпул (3 шага)                                     │  будущие свернуты
│  ▸ Охлаждение (2 шага)                                 │
│  ▸ Затор — готово ✓                                    │  прошлые свернуты
├────────────────────────────────────────────────────────┤
│ [ + Заметка ]   [ + Замер ]                            │  быстрый док (mobile: sticky)
└────────────────────────────────────────────────────────┘
```

- **Герой «Сейчас»** — первый не-done шаг акта: название, детали (t°/количество), большой
  таймер (для `kind=timer`), «Готово» → курсор сам съезжает на следующий. Отметки вне порядка
  по-прежнему можно ставить в списке (гибкость сохраняем, курсор — просто первый не-done).
- **Этап-полоса** — узкая лента Затор → Кипячение → Вирпул → Охлаждение с прогрессом
  (аналог `StageTimeline` пульта, но по чек-листу, не по телеметрии).
- **Хмель по обратному отсчёту** (веб-версия отложенного W6): пока таймер кипячения идёт,
  у ещё не внесённых засыпей вместо статичного «за 30 мин до конца» показываем живое
  «через 11:23» = `remaining(boil) − timeOffsetMinutes`. Данные уже в снапшоте.
- **Показываются только стадии варочного дня**: mash / boil / whirlpool / chill. Брожение и
  розлив в этом акте не рендерятся (они — следующие акты), «заглядывание вперёд» — свёрнутые
  группы в конце списка.
- **Финал акта:** после охлаждения — шаги «Замерьте OG» (§5) и «Перелейте в ферментер, внесите
  дрожжи», затем на месте героя появляется CTA **«Поставить на брожение»**. Она же заменяет
  шаг `ferment:primary` (сейчас дублируются «Поставить на брожение»-чекбокс и кнопка статуса).
  CTA доступна и при неотмеченных шагах — с мягким подтверждением «N шагов не отмечено».
- **Быстрый док:** «+ Заметка» (таймстамп-строка в журнал) и «+ Замер» (та же форма журнала
  инлайн-попапом). На мобайле док sticky снизу.

### 3.3 Акт «Брожение» (`fermenting`)

```
│ Брожение · день 4 из 14 · цель 18 °C                   │
│ ⚠ 5 дней без замера — проверьте FG                     │  resolveBrewNudge (уже есть)
│  ○ Внести на брожении: Citra 50 г · 3 дн.              │
│  ○ Колд-краш: 2 °C · 2 дн.                             │
│  ▸ Розлив (2 шага)                                     │
│ Замеры                                                 │
│  OG 15.2 → 6.4 °P (вчера) · сбраживание 58 %           │
│  [ + Замер ]                                           │
│ …FG стабильна и шаги отмечены → [ Завершить варку ]    │
```

- Герой — «день N из M» (от `startedAt`/перехода в fermenting и `primaryDurationDays`) +
  целевая t°; nudge переиспользует `resolveBrewNudge` из `dashboard.ts` (один словарь
  подсказок на дашборде и странице).
- Журнал замеров здесь — **главный блок** (динамика плотности, FG); плитки статов появляются
  только когда есть хоть один замер.
- Шаги акта: дрохмель/extra/колд-краш/выдержка из билдера + группа «Розлив» в конце
  (отдельный статус розлива не заводим — см. §11).
- CTA «Завершить варку» — в конце, появляется всегда, но подсвечивается, когда шаги отмечены
  и последние замеры стабильны.

### 3.4 «Итог» и «Архив»

- `completed`: как сейчас (`BrewCompletionSummary`, оценка рецепта), плюс гид read-only
  свёрнутой секцией «Как прошла варка» и журнал целиком. Форм ввода нет.
- `cancelled`: бейдж, «Вернуть в план», всё read-only.

## 4. Курсор гида (чистый слой)

Новое в `features/brew-batches/brew-day.ts` (без БД/React, юнит-тесты рядом с существующими):

- `brewDayActForStatus(status)` → `prep | brewday | fermentation | done | archived`.
- Маппинг стадий на акты: `mash|boil|whirlpool|chill → brewday`; `fermentation|packaging →
  fermentation`.
- `resolveBrewDayCursor(groups, progress, status)` → `{ current: BrewDayStep | null,
  next: BrewDayStep | null, actComplete: boolean }` — первый/второй не-done шаг в стадиях
  текущего акта. `actComplete` включает CTA перехода в герое.
- Синтетические шаги (добавляются билдером, id стабильны):
  - `chill:target` — «Охладите сусло до X °C» (X = `fermentationPlan.primaryTemperatureC`,
    без данных — «до температуры внесения дрожжей»); новая стадия `chill` («Охлаждение»)
    между вирпулом и брожением;
  - `measure:og` / `measure:fg` — шаги-замеры (§5), их `done` **выводится из журнала**
    (есть замер в соответствующем акте), в `brewDayProgress` не пишется;
  - `ferment:pitch` — «Перелейте в ферментер, внесите дрожжи» (замена `ferment:primary`;
    старый id остаётся валидным ключом прогресса для существующих партий).

## 5. Замеры и склад — по месту

| Что | Было | Стало |
|---|---|---|
| OG | форма журнала «всегда» | шаг «Замерьте OG» в конце варочного дня; отметка = инлайн-ввод плотности → запись в журнал |
| FG | там же | блок «Замеры» в акте брожения + шаг `measure:fg` перед «Завершить варку» |
| Плитки OG/FG/ABV | «—» с создания партии | появляются с первым замером; до того не рендерятся |
| Списание склада | секция внизу всегда | строка чек-листа подготовки + промпт при старте дня; после списания — строка «Списано ✓» в ⋯/журнале |
| Заметки | textarea-секция | «+ Заметка» в быстром доке (таймстамп-строка), полотно заметок — в секции «Журнал» |

Секция «Журнал» (история замеров + заметки + удаление) остаётся единой, но уезжает вниз и
свёрнута по умолчанию во всех актах, кроме брожения.

## 6. Ручное управление статусом — escape hatch

- Виджет `BrewLifecycle` (степпер + кнопки) **удаляется**.
- В шапке — меню ⋯ (`DropdownMenu` из `@nb/ui`): «Изменить этап…» (ручная установка любого
  статуса — редкий путь исправления ошибок) и «Отменить варку» через `ConfirmActionDialog`
  (сейчас отмена — одно случайное нажатие ghost-кнопки, без подтверждения).
- Статус-бейдж в шапке остаётся единственным индикатором этапа.

## 7. Мобайл

Одна колонка, тот же состав (паритет #5): шапка → этап-полоса → герой «Сейчас» → шаги акта →
свёрнутое остальное; быстрый док («+ Заметка / + Замер», в герое — «Готово») — sticky снизу в
зоне пальца. Цели нажатия ≥ 44 px (чекбоксы шагов сейчас 20 px — увеличить зону тапа строкой).

## 8. Уведомления (фаза A4, после раскладки)

`timerStartedAt` + `durationSeconds` уже в БД — сервер знает момент истечения таймера и может
слать web-push «Пауза закончилась — следующий шаг», переживающий сворачивание вкладки (боль #2).
Зависимости: инфраструктура `push_subscriptions` (миграция 0044 — проверить применённость,
см. память о баге таймстампов журнала миграций). До пушей — хотя бы звук/титул вкладки при
истечении таймера (дёшево, в `BrewDayHero`).

## 9. Компоненты: keep / refactor / new / remove

**Keep (логика):** сервисный слой `service.ts` целиком (`setBrewDayStepState`, журнал, склад),
`buildBrewDaySteps` (расширяется, не ломается), `resolveBrewNudge`, `BrewCompletionSummary`.

**Refactor:**
- `page.tsx` → ветвление по акту (server component выбирает раскладку по `batch.status`);
- `brew-day-guide.tsx` → `BrewStepList` (шаги одного акта; прошлые/будущие группы —
  `details`-свёртки; таймеры остаются) — герой выносится отдельно;
- `brew-journal.tsx` → статы только при наличии замеров; форма — переиспользуемый
  `MeasurementForm` для героя/дока; история — секция «Журнал»;
- `brew-inventory.tsx` → строка чек-листа подготовки (акт 0) + компакт-строка после списания;
- `brew-notes.tsx` → внутрь секции «Журнал» + быстрый «+ Заметка».

**New:** `BrewDayHero` (текущий шаг, таймер, «Готово», CTA перехода акта), `BrewStageRail`
(этап-полоса), `BrewPrepCard` (план дня + чек подготовки + «Начать варочный день»),
`FermentationBoard` (день N/M + nudge + шаги + замеры), `BatchMenu` (⋯: ручной статус, отмена),
`QuickDock` (быстрые действия, sticky на мобайле).

**Remove:** `BrewLifecycle` (виджет статуса), пустые плитки «—», вечные формы замера,
дубль «Поставить на брожение» (чекбокс + кнопка).

## 11. Дефолты / открытые

1. **Розлив — не отдельный статус.** Шаги розлива живут в конце акта «Брожение»; статусов в БД
   не добавляем. **[дефолт]**
2. **Быстрые заметки** — MVP: таймстамп-строки в `brew_batches.notes`. Единая лента событий
   (замеры + заметки + смены статусов одной хронологией) — кандидат на будущее, потребует
   таблицу событий. **[открыто]**
3. **Device-партия**: акты и «замеры по месту» применимы и там (герой = `LiveDashboard`
   в акте brewing), но делаем после связки W5 пульта. **[отложено]**
4. Пропуск шага — отдельного состояния «skip» не заводим: не отмечен = не сделан; переходы
   актов не блокируются. **[дефолт]**
