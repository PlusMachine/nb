# Редизайн пульта устройства L2 — спека (BrewForge)

> Заземлено на `brewery-command-center-ux-research.md` (анатомия экранов + сентимент) + аудит текущего кода.
> Дизайн-план архитектуры/безопасности — `brewery-command-center.md`.
> Статус: спека на реализацию. Обновлено 2026-07-01 решениями владельца (см. §1).

## 0. Рамки

- **Что переделываем:** пульт устройства L2 `/app/devices/[id]` (зона B). Зона A «варка партии»
  `/app/brew-batches/[id]` переиспользует те же компоненты (`LiveDashboard`, `TelemetryChart`) — рефактор
  чинит её тем же движением, ломать нельзя.
- **Только презентация/IA** (плюс одна связующая фича — §7). Safety-слой не трогаем: `use-device-command`,
  `control-lease`, `command-gate` (freshness), dead-man/keepalive, транспорты/провайдеры, `telemetry-source`,
  ядра `faults`/`stage-timeline`/`telemetry-annotations`. Ресёрч подтверждает: безопасность у всех — firmware-
  interlock, не UI-модалки.
- **Почему редизайн:** ресёрч валидирует архитектуру — 4 из 6 самых любимых паттернов уже в бэкенде. Красные
  клетки — только раскладка: «чистый самоочевидный UI» и «паритет телефон/планшет».

## 1. Решения владельца (2026-07-01) — фиксируем, чтобы не потерять контекст

1. **Вкладку «Обзор» — убрать** (в рамках «делай всё для лучшего UI/UX», п.5). Метаданные — только в Настройках.
2. **Пульт зеркалит плату, а не выдумывает режимы.** На устройстве авто-варка идёт по флоу стадий: засыпь →
   **паузы затора** → **йодная проба** → **промывка** → **кипячение** → **вирпул** → **охлаждение**, с
   промптами; плюс **ручной режим** — так же, как на плате. UI просто **отражает состояние устройства**
   (простой / авто-варка / ручной), никакого абстрактного 3-way-переключателя, который я ошибочно нарисовал.
   «Помощник» — это зона A (гид для варки БЕЗ устройства), не режим пульта.
3. **НОВОЕ — связка «сварить рецепт» ↔ автоматика (§7).** Нажал «Сварить» на рецепте → запускается тот же
   авто-флоу устройства, но **с подставленными данными из рецепта**. Это главная связка витрины/мастерской и
   пульта.
4. **НОВОЕ — «слоты» из UI убрать (§8).** Явные слоты — странно и непонятно. Ограничить число рецептов на
   пивоварне — ок, но **не называть это слотами** и **не требовать ручного сохранения в слот**: при «сварить»
   данные уходят на устройство на лету. Слоты остаются внутренней деталью прошивки/БД, наружу не торчат.
5. **Кнопки/`@nb/ui` и прочее — «делай всё, что необходимо для лучшего UI/UX»** (одобрено, §10).
6. **Термины — только реальные, из языка сообщества, ВЕЗДЕ** (и в UI автоматики, и на сайте): никаких калек/
   рунглиша/нейрослопа, которых в русском нет. «Хмелестояние» → **вирпул** (whirlpool; хопстенд — рядом, часто
   отмечают вместе). Нужен аудит всех строк (§3).
7. **Гид по хмелю (внесения в кипячении/вирпуле) — отложить** (§12), сейчас только зафиксировать в доках.

## 2. Принципы (каждый — из подтверждённого паттерна/боли ресёрча)

| Принцип | Основание |
|---|---|
| Герой экрана = крупная t°+уставка + текущий шаг/таймер + **живой авто-график** | любимое #1/#2/#3; анти-боль #3 (RAPT «graph без автообновления») |
| Гид с алертами, **переживающими обрыв связи** (пуш с сервера) | любимое #1; боль #2 (обрыв молча убивает алерт хмеля) |
| Статус «с одного взгляда» + ручные **Target/Heat%/Pump** в реальном времени | любимое #2 |
| **Самоочевидная раскладка важнее богатства** экрана | любимое #4; боль #4 (RAPT «clunky/non-intuitive») |
| Паритет: мобайл = **одна колонка, тот же состав и контроль** | любимое #5 |
| **Пульт зеркалит флоу платы** (авто-стадии + ручной), а не абстрактные режимы | решение владельца (§1.2); анатомия (autonext-профиль у Brautomat32/BierBot) |
| **«Сварить рецепт» = авто-флоу с данными рецепта** | решение владельца (§1.3); гладкий workflow рецепт→варка (любимое, Brewfather) |

## 3. Терминология — принцип и фиксы

**Принцип (владелец, §1.6):** только термины, которые реально использует русское пивоваренное сообщество —
и в UI автоматики, и на сайте. Принятые заимствования (вирпул, хопстенд, засыпь, сухое охмеление…) — ок; кальки
и выдумки (хмелестояние, «слоты рецептов», «пилюль-статус») — нет. Опора — глоссарий калькуляторов
(`features/calculators`), см. память `calculators-terminology-glossary`.

| Понятие | Убрать | Правильно |
|---|---|---|
| whirlpool / hop stand | «Хмелестояние» (`stage-timeline.ts:24,33`) | **Вирпул** (в детали — «вирпул / хопстенд») |
| skip stage (транспорт) | «Пропустить» | **Далее** (guided, как Grainfather/BierBot Next) |
| рецепты на устройстве | «на борту», «слоты» | **рецепты пивоварни** / «загруженные рецепты» (без номеров слотов) |
| mash / rests / boil / cooling | — | **Затор / Паузы / Кипячение / Охлаждение** (уже ок) |

**Действие:** grep по всему проекту (brewforge + сайт) на кальки/рунглиш; свести к терминам сообщества.
«Хмелестояние»→«Вирпул» — первый в списке (`stage-timeline.ts`).

## 6. Поведение по зонам

- **Хедер (sticky):** back → L1, имя, **один** индикатор статуса, канал (LAN/облако), аренда управления,
  шестерёнка → Настройки. Один `h1`. Убирает двойной заголовок.
- **Индикатор статуса (единый словарь):** «В эфире» / «Устарело» / «Офлайн» / «Ошибка связи» / «Подключение…».
  Выводится из `conn` + freshness + `device.status`.
- **UI отражает состояние устройства (зеркало платы), НЕ абстрактный режим:**
  - **Простаивает:** блок «Пивоварня свободна» + «Сварить рецепт…» (§7) + «Ручной режим».
  - **Авто-варка:** гид-промпты (засыпь/йодная проба/промывка…), герой, профиль-полоса, статус, транспорт
    (Пауза/Продолжить/Далее/Стоп). Всё как на плате.
  - **Ручной:** раскрыты `Target / Heat% / Pump` (существующий `ManualControlCard`), правка в реальном времени;
    эксклюзивно через control-lease.
- **Гид-промпт (#1):** активный промпт крупно + web-push через мост (переживает сворачивание/обрыв — боль #2).
  Рендер только когда есть.
- **Герой:** слияние текущего отсчёта и `TelemetryChart` — крупные t°+уставка, стадия+«Пауза N/M»+таймер;
  живой график факт/уставка/профиль + вторая ось heat%. График **сам обновляется** по SSE (анти-RAPT).
- **Профиль-полоса:** `StageTimeline` тонкой лентой (Затор → Кипячение → **Вирпул** → Охлаждение → Готово).
- **Статус glanceable (#2):** мощность нагрева %, ТЭН, насос, промывка, «нагрев разрешён» — компактно.
- **Транспорт:** Пауза/Продолжить/**Далее**/Стоп — conditional visibility; sticky снизу. Стоп — двухшаг,
  E-STOP — hold-to-confirm, всегда доступен (fail-safe).
- **Аварии:** баннер только при активных; журнал — в `details`.

## 7. Связка «Сварить рецепт» ↔ автоматика (новое, §1.3)

Главная продуктовая связка витрина/мастерская → пульт. Модель:

- На рецепте/в мастерской действие **«Сварить»** → выбор привязанной пивоварни (если их >1) → портал
  транслирует план рецепта в `DeviceRecipe`, **пушит на устройство на лету** и запускает **тот же авто-флоу**
  (START_BREW), что и на плате — но уставки/паузы/хмель/охлаждение взяты **из рецепта**.
- Пользователь видит «варится «Название рецепта»» и обычный пульт (§5). **Никаких слотов, никакого ручного
  «сохранить в слот N»** в этом пути.
- Технически связь рецепт↔варка уже есть (`brewPlanSnapshot`, `pushRecipeToDevice`, `device_recipe_slots` для
  привязки) — слот выбирается автоматически как деталь реализации, наружу не показывается.
- Обратная сторона (телеметрия варки этого рецепта) уже течёт через зону A `/app/brew-batches/[id]` — она и
  есть «варка партии с данными рецепта». Пульт L2 и зона A делят компоненты (§0).

**Уточнение владельца (2026-07-01): «Сварить» — ГЕЙТ выбора, НЕ авто-решение.** Есть РАЗНЫЕ «сварить», и
портал не выбирает за пользователя — гейт «ясно указывает» на варианты:
- **С автоматикой (device-first):** на привязанной пивоварне BrewForge — пуш рецепта + START_BREW (этот раздел).
- **Без автоматики (веб-помощник):** гид варочного дня на ЛЮБОЙ пивоварне (в т.ч. не-BrewForge / другой) —
  портал только ведёт по шагам; это batch-путь зоны A (`BrewDayGuide`), уже есть. Рядом в витрине живёт
  `components/recipes/brew-from-stock-button.tsx` (clone публичного → мастерская → штатная «Начать варку»).
- Действие «Сварить» на рецепте показывает варианты ЯВНО (выбрать пивоварню с автоматикой ЛИБО сварить как
  веб-помощник; возможно, назвать по-разному — НЕ решать за пользователя). Пульт L2 в простое (§5) — это уже
  device-first вход «Сварить рецепт…» (контекст = автоматика, отдельный гейт там не нужен).

## 8. Рецепты на пивоварне — без «слотов» (новое, §1.4)

- **Из UI убираем слово и сущность «слот».** Явные номера слотов — деталь прошивки, наружу не торчат.
- Основной путь — §7 («Сварить» пушит на лету). Отдельный экран управления загруженными рецептами —
  **вторичен**; если оставляем, то как **список «рецепты пивоварни»** (что сейчас загружено), с лимитом по
  ёмкости устройства, но **без номеров слотов** и без ручного «записать в слот N».
- `device_recipe_slots`, `putRecipe(slot)`, `listSlots` — остаются как внутренний механизм (привязка
  слот↔recipeId), но UI-обёртка `OnboardRecipesPanel` переосмысляется: не «Что на плате / Записать в слот», а
  «Рецепты пивоварни» (просмотр) + основной вход через «Сварить». Точную форму дорабатываем при реализации.
- Честность (из главного плана): `DeviceRecipe` беднее модели nb → «импорт чужого рецепта с платы в каталог»
  по-прежнему не обещаем; просмотр — да.
