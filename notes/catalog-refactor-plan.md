# Рефактор каталога ингредиентов: /catalog + детальная страница

> Продуктово-UX/SEO план, 2026-07-05. По коду + живому прогону (десктоп/мобайл, поиск, фильтры, деталка).
> Цель страницы (от владельца): **SEO-сбор трафика по запросам любых пивных ингредиентов** + вспомогательная роль — наполнение склада и рецептов.
> Рабочий чеклист: идём по этапам сверху вниз, статус проставляем в конце пункта.
> Связано: notes/ingredients-audit.md (склад), memory `catalog-is-public`.

## Карта текущего состояния

- Список: `app/(public)/catalog/page.tsx` → `content.tsx` (server, всё состояние в URL: `view/q/category/subtype/sort/page`).
- Тулбар: `components/ingredients/ingredient-catalog-toolbar.tsx` (client) — табы «Все/Пользовательские», большие карточки категорий, поиск (debounce 250мс), сортировка, сброс.
- Деталка: `app/(public)/catalog/[source]/[id]/page.tsx` — hero (имя, бейджи, факты, CTA), «Параметры», «Использование», «Где купить», полоса алиасов.
- Service: `features/ingredients/catalog-service.ts` (`listUserCatalogIngredients` — грузит весь каталог в память, фильтрует/сортирует в JS; pageSize 20), ранжирование поиска — `features/ingredients/ranking.ts` (tier'ы exact/prefix/token/contains + fuzzy).
- SEO-инфраструктура: `app/sitemap.ts` (только `/catalog` без деталок), `app/robots.ts`. `generateMetadata` **нет ни на списке, ни на деталке**.
- ID системных ингредиентов — уже человекочитаемые слаги (`us-citra-standard`), кастомных — UUID. URL деталки: `/catalog/system/<slug>` и `/catalog/custom/<uuid>`.

## Что уже хорошо (не ломать)

- Серверный рендер списка и деталки; состояние фильтров целиком в URL — ссылки шарятся.
- Debounce-поиск с притуханием устаревшего списка (`catalog-search-dim`, UX-находка #17).
- Фасетные счётчики категорий пересчитываются под поиск; пустые категории дизейблятся.
- Единый список системных + пользовательских ингредиентов; кастомные видны только владельцу (`getUserCatalogIngredientByRef` возвращает null чужим).
- Ранжирование поиска по tier'ам с бустами избранного/популярности — фундамент правильный, чинить надо только хвост.
- Слаговые ID системных ингредиентов — половина SEO-работы с URL уже сделана.

## Диагноз (кратко)

**SEO — заявленная цель не обеспечена.** Нет title/description/canonical ни у одной страницы каталога; деталки не в sitemap (Google найдёт их только через 61 страницу пагинации); категорийные лендинги — query-параметры; нет structured data; деталка бедна текстом (thin content) — одни цифры.

**Поиск.** `citra` → 23 результата: сверху корректные хмели Citra, дальше шумный fuzzy-хвост («Карамельный экстра», 10×BEST Caramel, дрожжи «Лутра»). Хвост contains/fuzzy не отрезается при наличии точных совпадений. Сортировки только глобальные (название/обновление/категория/бренд), параметрических нет.

**Тулбар.** Счётчики продублированы 3 раза (таб + подпись + карточки). Карточки категорий съедают на мобиле ~2 экрана до первого ингредиента. Лейблы «Поиск»/«Сортировка» — лишние. «Сбросить» прыгает layout'ом.

**Таблица.** Колонка «Тип» дублирует сама себя («дрожжи/Дрожжи»). Колонка «Использование» — почти всегда «0/0». Сырые enum в пиллах (`standard`, `powder`, `piece`, `very high`). У солода цвет текстом вместо свотча. Плотность ~100px/строка.

**Деталка.** Правая колонка сетки `xl:grid-cols-[1.1fr_0.9fr]` пуста — полстраницы воздуха. Hero-факты дублируют блок «Параметры» (альфа/бета показаны дважды). «Использование 0/0» — шум. Полоса алиасов внизу без подписи — выглядит мусором. Нет ни описания, ни похожих ингредиентов, ни рецептов с ним — анонимному SEO-посетителю некуда идти дальше (все 3 CTA ведут в /login). Фасовки (`packageVariants`) и источники есть в DTO, но не рендерятся.

## Этап 1 — SEO-фундамент ⭐ P0 — ✅ СДЕЛАН 2026-07-05

Самодостаточный этап: делает страницы индексируемыми. Остальные этапы его усиливают.

> Реализация: модуль `features/ingredients/seo.ts` (лендинги, metadata-билдеры, JSON-LD) + тесты `tests/ingredient-seo.test.ts`.
> Поправка к плану: отдельный `[categorySlug]` рядом с `[source]` невозможен (Next запрещает разные имена динамического сегмента на одном уровне) — лендинги живут в `[source]/page.tsx`, слаг резолвится через `resolveCatalogLanding`.
> Дополнительно: удалён `catalog/loading.tsx` (дублировал Suspense в страницах и ломал 404 — из-за раннего флаша стрима notFound отдавал 200+noindex; теперь честные 404, как у /bjcp).
> Приёмка живьём (curl, 2026-07-05): title/description/canonical на /catalog, /catalog/hops, деталке; `?q=` → noindex; `?category=hop` → canonical на /catalog/hops; sitemap = 1207 деталок + 6 лендингов; JSON-LD BreadcrumbList+Product на деталке; битые URL → 404.

### 1.1 generateMetadata на деталке ✅
`app/(public)/catalog/[source]/[id]/page.tsx`.
- Title: `«{nameRu} ({nameEn}) — {тип}{, бренд} | {app}»`, пример: «Citra (Цитра) — хмель Yakima Chief Hops».
- Description: собрать из ключевых параметров + категории («Американский ароматный хмель, альфа 12.7%. Характеристики, аналоги и рецепты с Citra»). Генератор по категории — в `features/ingredients/presentation.ts` или новый `seo.ts`.
- `alternates.canonical` на `/catalog/system/<slug>`.
- Кастомные ингредиенты: `robots: { index: false }` (они и так owner-only, но страховка обязательна).
- OG-теги (без картинок пока).

### 1.2 generateMetadata на списке ✅
`app/(public)/catalog/page.tsx`.
- Базовый title/description для `/catalog`.
- При активной категории — категорийный title («Хмель для пивоварения — каталог, N сортов»).
- При `q` или `view=mine` — `robots: noindex, follow` (поисковые выдачи не индексируем).
- `page>1` — canonical на себя (не на первую), индексация разрешена — это путь краулера к деталкам.

### 1.3 Деталки в sitemap ✅
`app/sitemap.ts`: добавить все системные ингредиенты (`/catalog/system/<slug>`, lastModified = updatedAt). Кастомные — никогда. ~1200 URL — в лимиты одного sitemap помещается.

### 1.4 Категорийные лендинги path-урлами ✅
Сейчас `?category=hop` — под трафик «хмель для пивоварения» нужны path-страницы.
- Маршрут `app/(public)/catalog/[categorySlug]/page.tsx` (не конфликтует с `[source]/[id]` — разная глубина; слаги: `malts`, `fermentables`, `hops`, `yeast`, `water`, `additives`, `consumables` — проверить на коллизию с `system|custom|new`). *(Изначально `consumables` был одним слагом на весь `consumable`; позже расщеплён на `additives`/`consumables`.)*
- Контент = тот же `IngredientCatalogContent` с зашитой категорией + H1 категории + 2–3 предложения интро (статичный словарь, не нейрослоп).
- Query-вариант `?category=` остаётся для комбинаций/тулбара, но canonical у него — на path-версию.
- Внутренние ссылки: карточки категорий в тулбаре ведут на path-урлы.

### 1.5 JSON-LD ✅
- Деталка: `BreadcrumbList` (Каталог → Категория → Ингредиент) + `Product`/`Thing` с брендом и свойствами.
- Список/лендинги: `ItemList` первых N позиций.
- Хелпер — рядом с metadata-генератором, рендер через `<script type="application/ld+json">`.

### 1.6 Пагинация: pageSize 20 → 50 и номерные ссылки ✅
`content.tsx` + `listUserCatalogIngredients`.
- 61 страница → ~25.
- Вместо «Назад/Дальше» — номерная пагинация ссылками (`1 2 3 … 25`): и юзеру быстрее, и краулеру короче путь до всех деталок.

### 1.7 Кэш анонимного каталога ✅
`getSessionUser` делает всё dynamic — для SEO не блокер (SSR есть), но TTFB жалко.
- Минимум: обернуть `loadIngredients()` в `unstable_cache` с тегом `ingredients-catalog`, инвалидация в admin-мутациях каталога.
- Не переусложнять: полный ISR анонимной версии — только если TTFB реально станет проблемой.

**Приёмка этапа:** у `/catalog`, `/catalog/hops`, `/catalog/system/us-citra-standard` осмысленные title/description в `curl | grep '<title>'`; деталки в `/sitemap.xml`; `?q=` отдаёт noindex; JSON-LD валиден в Rich Results Test.

### 5.4 Блоки перелинковки (SEO + ценность анониму) ⭐ ключевое для трафика ✅
- **«Похожие ингредиенты»** (5–6 шт): та же категория + близкий параметр (хмель — по альфе/назначению, солод — по цвету, дрожжи — по аттенюации и типу). Сервисная функция в `catalog-service.ts`, лёгкая — каталог уже в памяти.
- **«Рецепты с этим ингредиентом»**: публичные рецепты через `recipeIngredients` → счётчик + до 3–5 карточек + ссылка на `/recipes?ingredient=<slug>` (если фильтр рецептов по ингредиенту ещё не существует — сначала счётчик и простой список, фильтр витрины — отдельная задача).
- **«Другие ингредиенты {бренд}»**: 4–5 позиций того же бренда.
Эти три блока превращают тупиковую страницу в хаб — и дают краулеру плотную перелинковку каталога.

### 5.5 CTA анонима ✅
Сейчас три кнопки — все в `/login`. Оставить одну главную «Добавить на склад» (login с next=), остальное убрать: ценность анониму дают блоки 5.4, а не серые кнопки-обманки.

### 5.6 Контент-описания (отдельная контентная работа, после структуры) — ✅ механика сделана 2026-07-05, наполнение НЕ входит

- Схема: `descriptionRu` (2–4 абзаца: характер, применение, стили, заменители) у системных ингредиентов; поле в админ-форме (`admin-ingredient-form.tsx`).
- Наполнение: начать с топ-100 ходовых (хмели, базовые солода, популярные дрожжи). Черновики можно генерировать, но публиковать только после ручной вычитки редактором.

> Реализация механики (2026-07-05): `description_ru text` в `ingredients` (миграция 0054, журнал вручную поправлен — известный баг инфлированных `when`, см. memory `drizzle-migration-timestamp-bug`); `descriptionRu` проброшен через весь стек — `IngredientCatalogItemDto`/`UserCatalogIngredientDto`, `ingredientUpsertSchema` (пустая строка → null), `mapIngredientRow`, `buildIngredientValues`/`toUpsertPayload` (оба направления upsert), `mapSystemIngredient`/`mapCustomIngredient` (у custom всегда null). ## Открытые вопросы к владельцу

1. **URL деталки.** Оставить `/catalog/system/<slug>` (ничего не мигрировать) или перейти на `/catalog/<category>/<slug>` (категория в URL, красивее для SEO, но нужны 301 со старых). Рекомендация: оставить как есть — слаги уже читаемые, сегмент `system` терпим, а 301-миграция URL — риск без большой выгоды. Категорийность дадут лендинги 1.4 + хлебные крошки.
2. **Слаги лендингов категорий**: английские (`/catalog/hops`) или транслит (`/catalog/hmel`)? Для ru-SEO значения почти не имеет; рекомендация — английские, консистентно с остальными URL.
3. **Описания ингредиентов (5.6)**: кто редактор и какой темп? Это определяет, планировать ли admin-воркфлоу сейчас или отложить.
4. Нужен ли фильтр витрины рецептов по ингредиенту (`/recipes?ingredient=`) как отдельная фича — или на деталке достаточно списка из 3–5 рецептов.
