# Аудит страницы «Мой склад» (/app/ingredients)

> Продуктово-UX аудит страницы склада, 2026-07-02. По факту кода + живого прогона (десктоп/мобайл, все интеракции).
> Рабочий чеклист: идём по пунктам сверху вниз и правим. Статус в конце каждого пункта.
> Связано: memory `recipe-master-audit`, `working-zone-lighter-than-public`, `product-model-and-roadmap`.

## Карта страницы (снимок)

- Роут: `app/(app)/app/ingredients/` — `content.tsx` (server) грузит данные, парсит `searchParams`.
- Тулбар: `components/inventory/inventory-toolbar.tsx` — кнопки категорий (сетка), чипы подгрупп, поиск, сортировка, «показать закончившиеся», сброс. Состояние целиком в URL.
- Карточка: `components/inventory/inventory-list-item.tsx` — имя/бренд/страна, бейджи, метаданные (цена/срок), инлайн-правка остатка, списание/докупка, редактор «...», удаление.
- Диалоги: `add-ingredient-modal.tsx` (добавление), `inventory-item-details-editor.tsx` (полное редактирование), `inventory-consume-control.tsx` (± остаток).
- Секция «Можно сварить»: `components/recipes/brewable-recipes-section.tsx` (обратный матчинг склад→рецепты).
- Service layer: `features/inventory/*` (service, contracts, page-model, consume, display, units).

## Что уже сделано правильно (не ломать)

- Три уровня правки остатка: инлайн-клик по числу, быстрое списание долями (¼/½/¾/Всё), полный редактор с «Дополнительно» под катом.
- Состояние фильтров целиком в URL + «Сбросить».
- Разные пустые состояния под поиск / фильтр / новичка (`inventory-empty-state.tsx`).
- Химформулы с подстрочником для водоподготовки; цветовая шкала EBC в бейджах солода.
- Модалка добавления с быстрым стартом по брендам/типам и «Недавними».
- Заголовок диалога списания уже динамический («Сколько использовали?» / «Сколько докупили?») — правка не нужна.
- «Count-conditional» видимость поиска (>12 позиций) — осознанное решение по рабочей зоне (memory `working-zone-lighter-than-public`), не трогаем.

**Что сделать.** Порог/эвристика + визуальный статус на карточке.

**Статус:** [x] решено НЕ делать (2026-07-03, обсуждено с владельцем). «Мало» осмысленно только относительно *спроса* («не хватит на то, что собираюсь сварить»), а не относительно абсолютных граммов или объёма покупки:
- Абсолютные пороги (хмель <20 г и т.п.) ложно срабатывают у пивоваров с маленькими партиями — у них всё маленькое по замыслу → половина склада «Мало» = шум.
- % от покупки: при покупке впритык ты всегда около «мало»; плюс данные о покупке разрежены (только при указанной цене).
- Спрос-относительный сигнал уже есть и в лучшем месте: **список покупок (п.11)** собирает недостачу под запланированные варки, панель матча в рецепте — «не хватает на этот рецепт». Per-card бейдж «Мало» — более слабый и шумный дубль.
- Вывод: вытеснено пунктом 11 + матчем; per-card статус не добавляет действия, только шум. Против нашего принципа «не лепить неактируемые сигналы».
- Оговорка на будущее: если понадобится — только **ручной порог на позицию** (опт-ин, без гадания), но это правка схемы (миграция) и сейчас не оправдано.

**Проблема.** С 20+ позициями до главного мотиватора страницы никто не доскроллит; на десктопе строки карточек в середине полупустые — есть место под правую колонку (rail).
