Каталог покрывает всё; движок исправен (где альфа хмеля совпала — IBU сходится до десятых:

Аудит: память `birrf-top20-flow-audit`.

## Б1 (P0). Альфа хмеля на позиции рецепта — override без кастомного ингредиента

**Проблема.** Альфу каталожного хмеля нельзя задать под рецепт. Сейчас единственный путь —
«свой ингредиент», а в инвентарном флоу правка альфы создаёт derived-кастом
(`resolveCatalogTechnicalOverrideResolution` → `resolveOrCreateDerivedCustomIngredient`,
`features/inventory/service.ts:1288,1251`). Для редактора рецепта кастомная копия вредна:
позиция теряет `ingredientCatalogItemId` → ломается матч со складом, «Аналоги», покупки,
плюс замусоривается список «своих» ингредиентов ради одного числа.

**Решение.** Per-position override в `stepMeta.alphaAcidPct` — по образцу уже существующих
позиционных параметров, влияющих на расчёт (`stepMeta.temperatureC` вирпула уже меняет IBU:
`features/recipes/service.ts:1455` → `brewing-core/ibu.ts:270`). Кастомный ингредиент в этом
флоу НЕ создаётся. Derived-кастом в инвентаре оставить как есть: там это физическая партия
хмеля на складе — отдельная сущность оправдана.

**Объём:**
1. **Хранение:** ключ `alphaAcidPct` (число, % , валидация 0–30) в `recipe_ingredients.stepMeta`.
   `sanitizeRecipeStepMeta` (`service.ts:928`) — pass-through, миграция БД не нужна.
   Схему `stepMeta` в `features/recipes/contracts.ts:384` дополнить, если там появится строгая валидация ключей.
2. **Расчёт:** в обоих путях резолвинга альфы — preview (`service.ts:1451`) и persisted (`service.ts:~1548`) —
   `readNumberMeta(stepMeta, "alphaAcidPct") ?? getIngredientAlphaAcidPercent(raw, 5)`.
   Аккуратнее: дать `getIngredientAlphaAcidPercent` опциональный `override`-аргумент, чтобы логика жила в одном месте
   (`features/ingredients/technical-fields.ts:649`).
3. **UI (модалка хмеля, `ingredient-editor.tsx`):** после выбора сорта — поле «Альфа, %»
   (NumericInput), предзаполненное эффективной каталожной альфой. Пользователь поменял →
   пишем в `stepMeta.alphaAcidPct`; вернул каталожное значение/очистил → ключ удаляем
   (не хранить override, равный каталожному). Работает для всех источников (каталог/склад/imported).
4. **Карточка позиции:** в бейдже показывать эффективную альфу одним числом («Альфа 5.7%»),
   а не диапазон «Альфа 4–9%». Если действует override — тот же вид, без пометок-подписей
   (UI без слоп-подписей); открыл карандаш — видно и можно сбросить.
5. **Импорт → сопоставление с каталогом:** в диалоге пакетного сопоставления
   (`applySelection`, свежая работа по Brewfather) при замене imported-позиции на каталожную
   переносить альфу из файла в `stepMeta.alphaAcidPct`, если она отличается от каталожной.
   Сейчас альфа файла живёт в `external_import_meta.importedIngredient.technicalData` и при
   сопоставлении терялась бы.
6. **Тесты:** vitest на резолвинг (override > typical > max > min > 5), на «очистка удаляет ключ»,
   на перенос альфы при сопоставлении импорта.

**Не делаем:** override других полей (цвет/экстрактивность засыпи, аттенюация дрожжей) — отдельным
решением, если попросят; инлайн-правку альфы в карточке без модалки.

## Б2 (P1). Каталожная альфа: фолбэк «максимум» → типовая + данные

**Проблема.** `hopAlphaAcidPct = typical ?? max ?? min` (`technical-fields.ts:562`).
У 53 из 248 активных хмелей typical не заполнен, но есть max → считаем по верху диапазона.
Каскад: min 4 / max 9 → берём 9% (реальный типовой ~5.5–7). Отсюда перелёт IBU на самых
популярных сортах (#16: 42 vs 27.4).

**Объём:**
1. **Фолбэк:** `typical ?? середина(min,max) ?? max ?? min`. Каскад станет 6.5% — рядом с истиной.
   Продублированные фолбэки (`technical-fields.ts:492`, `match-service.ts:233`) свести к одной функции.
2. **Данные:** проставить `alpha_acid_pct_typical` для популярных сортов без typical
   (список 53 шт. — запросом; в топе аудита: Каскад ~5.9, Сентенниал ~9.5, Наггет ~12.5…).
   Источник правок — `ingredients/new/*.json` + `npm run catalog:sync`, не руками в БД.
3. **Пересчёт:** `npm run recompute:recipe-stats` — ⚠ изменит IBU уже сохранённых/опубликованных
   рецептов. Прогнать осознанно, сверить дифф по публичным рецептам до/после (валидация движка
   на 20 публичных уже есть как референс).

## Б3 (P1). Модалка ингредиента: пустой склад → сразу каталог

**Проблема.** Модалка открывается на источнике «Из склада». У пользователя без склада —
пустой список, и он должен сам догадаться переключить на «Из каталога». Бьёт по первому
опыту ровно в главном флоу «завёл рецепт с нуля».

**Решение.** При открытии редактора позиции: если по выбранной категории на складе 0 позиций —
стартовый источник «Из каталога» (переключатель остаётся, руками вернуться можно).
Если склад по категории непуст — поведение прежнее (склад-first задуман).
Без подписей-объяснений. Тест на выбор стартового источника.

## Б4 (P2). Пикер в модалке: «Пшеничный» даёт 0 результатов

**Проблема.** В drawer-пикере засыпи запрос «Пшеничный» дал 0 опций, «Пшеничный светлый» —
находит; при этом `/api/ingredients/search?q=Пшеничный&category=fermentable` результаты отдаёт.
Похоже на клиентскую логику пикера (ранжирование/фильтр/limit/дебаунс-гонка), а не на API.
В том же прогоне разово 0 давал и «Пэйл Эль» (после retry — 6 опций) — возможна гонка
дебаунса со сменой источника «Склад → Каталог».

**Объём:** воспроизвести, найти причину (`components/ingredients/ingredient-picker.tsx`),
починить. Критерий: «Пшеничный» стабильно выдаёт пшеничные солода; смена источника не
глотает уже введённый запрос.

## Б5 (P3, обсудить). Дубли одноимённых позиций в пикере

17 записей «Пэйл Эль» (по производителям), пикер показывает 6 строк с одинаковым заголовком +
чипы производителей. Выбрать «тот самый» тяжело; большинству нужен просто «Пэйл Эль».
Варианты (не решено, спросить владельца):
- а) группировать одноимённые в одну строку, производитель — вторым шагом (чипы уже есть);
- б) ранжировать по доступности в РФ/популярности, остальное под «Показать все»;
- в) оставить как есть (чипы производителей уже решают), но заголовок строки дополнять
  производителем всегда, а не только в подзаголовке.

## Б6 (P2). Дрожжи: дефолт количества «1 пачка»

Позиция дрожжей не сохраняется без количества («Укажите количество больше нуля»), хотя на
расчёты пачки не влияют. При выборе дрожжей предзаполнять «1 пачка» — как разумный дефолт;
кто варит стартеры/двойные пачки, поправит.
