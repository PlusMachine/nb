# Аудит импорта/экспорта рецептов на реальных публичных файлах

Дата прогона: 2026-07-11. Ветка на момент прогона: `feature/calculators-polish` (аудит ничего не менял в коде).

## Как проверялось

Не по коду, а прогоном: реальные публичные файлы → боевой парсер `features/recipes/interop` →
боевой `createRecipeFromCanonicalImport` → реальные статы из БД (`getOwnedRecipeById`), плюс
живой импорт через модалку в браузере (Playwright, dev-сервер, `/app/recipes/new`).
Временные харнесы (`apps/web/scripts/import-audit/*`, e2e-спека) удалены после прогона, тестовый
пользователь `import-audit@local.test` из БД удалён.

Корпус — 372 файла:

| Источник | Файлов | Кто экспортировал |
|---|---|---|
| BrewDog DIY Dog (github.com/stuartraetaylor/diydog-beerxml) | 325 | генератор BrewDog |
| beerxml.com/recipes.xml (официальные примеры) | 4 (в одном файле) | BeerSmith, ISO-8859-1 |
| Brewtarget DefaultContent001 | 29 (в одном файле) | Brewtarget |
| pybeerxml tests (CoffeeStout, Oatmeal Stout, Simcoe IPA) | 3 | BeerSmith / Brewer's Friend |
| BeerXML v2 (brewpoo/BeerXML-Standard), BeerJSON (beerjson/beerjson) | 4 | — |
| Синтетические edge-кейсы (атрибуты, CDATA, комментарии, кодировки) | 7 | — |

Что поддерживается сегодня: импорт BeerXML 1.0 + Brewfather JSON («тестовая поддержка»), экспорт —
только BeerXML. BeerJSON, CSV, BeerSmith `.bsmx` не поддерживаются.

## Главный вывод

Расчётный движок мастера здоров, а слой импорта — решето. Все крупные расхождения чисел вызваны
порчей данных на входе, а не математикой:

- OG на файлах BeerSmith сходится в пределах **±2 пунктов** (1.054 → 1.056).
- OG на экстрактных рецептах Brewtarget — **±0.4 пункта**.
- IBU на all-grain — **±1 IBU**.
- Mash-шаги, стадии хмеля, формула IBU из файла подхватываются корректно.

## P0 — критичное

### 1. `YIELD`/`COLOR` = 0 в файле → OG 1.000, ABV 0 %
Нули из файла берутся буквально, фолбэка на дефолты движка (36 ppg / 2 °L) нет:
`getIngredientPotentialPpg(raw, 36)` получает не «отсутствует», а «ноль».
**323 из 325** файлов BrewDog импортируются с OG 1.000 / ABV 0.0 % / цвет 0 SRM — без единого
предупреждения. Подтверждено вживую (Punk IPA 2007–2010 в мастере: «НП 1.000 SG, ABV 0.0 %»).

Правильное поведение: 0/отсутствие → «неизвестно» → дефолт движка, а лучше — подбор из каталога.

### 2. Один ингредиент с `AMOUNT` = 0 отменяет весь импорт
`import-service.ts` кидает `INVALID_IMPORT_INGREDIENT_AMOUNT` на любую строку с `amount <= 0`.
Сухие дрожжи сплошь и рядом экспортируются как `<AMOUNT>0</AMOUNT>` → падает весь рецепт.
Поймано на Simcoe IPA (Brewer's Friend) и 2 файлах BrewDog (`ab24.xml`,
`mango_and_chili_barley_wine.xml`).

Правильное поведение: пропускать/нормализовать строку, а не отвергать рецепт.

### 3. Атрибут в теге → ингредиент молча исчезает
Парсер — регекспы (`readTag`/`readBlocks`), шаблон требует `<HOP>` вплотную к `>`.
`<HOP id="1">`, `<FERMENTABLE id="1">` не матчатся и **тихо выпадают** из импорта.
В тесте так пропал базовый солод 3.6 кг: OG упала 1.056 → 1.014, ошибок ноль.

Отдельная ловушка: guard на `<RECIPE\b` атрибуты пропускает, а `readBlocks(xml,"RECIPE")[0]`
вернёт `undefined` → фолбэк `?? xml` → «рецептом» станет весь документ.

### 4. XML-комментарии импортируются как настоящие ингредиенты
Комментарии не вырезаются. Закомментированный хмель поднял IBU с 31 до 169.5.
Хуже: комментарий, содержащий `</HOP>` или `</RECIPE>`, обрежет блок раньше времени.

### 5. Файл читается только как UTF-8
`import-export-modal.tsx` → `FileReader.readAsText(file)` без указания кодировки; XML-декларация
`encoding="ISO-8859-1"` игнорируется. BeerSmith по умолчанию пишет ISO-8859-1:
«Münchner» → `M�nchner`; кириллица из CP1251 → сплошные `�����`. Молча, импорт «успешен».

Фикс: `readAsArrayBuffer` → вытащить `encoding` из декларации → `new TextDecoder(label)`.

## P1 — серьёзное

### 6. Утечка вложенных тегов
`readTag(recipeBlock, TAG)` берёт **первое вхождение по всему блоку `<RECIPE>`**, не различая
вложенность. Следствия, подтверждённые вживую:
- «Описание рецепта» Burton Ale = маркетинговые заметки **первого хмеля**
  («Used For: General purpose hops… Substitutes: Fuggles, BC Goldings»);
- `importedStats.color` = цвет **первого солода** в Ловибондах, а не цвет рецепта
  (и он же уходит в экспорт как фолбэк);
- `BATCH_SIZE`/`BOIL_TIME` могут быть подхвачены из `<EQUIPMENT>`, если тот стоит раньше.

### 7. Дрожжи и добавки в неверных единицах
По BeerXML при `AMOUNT_IS_WEIGHT=FALSE` величина — **литры**. Мы трактуем её как «пачки»/«штуки»:
- смэк-пак Wyeast (`0.0350130`, FALSE) → **0.035 пачки** (в UI так и показано);
- Irish Moss → **0.001 штука**, Polyclar → **0.007 штука**.
Плюс у MISC дефолт `AMOUNT_IS_WEIGHT` инвертирован (`?? true`, по спеке — FALSE).

### 8. Из файла с несколькими `<RECIPE>` импортируется только первый, молча
`readBlocks(xml, "RECIPE")[0]`. В официальном примере beerxml.com их 4, в Brewtarget — 29.
Ни предупреждения, ни выбора рецепта в UI.

## Подбор ингредиентов и аналоги

Матчинга импортируемых строк на каталог **нет вообще** (это by design, зафиксировано в
`docs/reference/recipes-editor.md`): каждая строка сохраняется снимком
`RecipeImportedIngredientSnapshot`, `ingredientCatalogItemId = null`, бейдж «Импортировано»,
и пользователь должен вручную жать «Подобрать из каталога» на каждой позиции.
Следствие: нет связи со складом, нет аналогов, технические данные берутся только из файла
(а он, как в BrewDog, часто нулевой → см. P0-1).

Но и **ручной** подбор ломается. Прогнал все 352 уникальных имени из корпуса через боевой поиск
пикера (`searchUserCatalogIngredients`, тот же, что дергает `/api/ingredients/search`):

- **Хмель: находится 46 из 169 имён.** Убивает суффикс в скобках:
  `Nelson Sauvin (NZ)` → 0 результатов, `Nelson Sauvin` → «Нельсон Совин».
  То же: `Motueka (NZ)`, `Bramling Cross (UK)`. Ингредиент в каталоге **есть** — его не найти.
- **Соли не находятся из-за неверного типа.** BeerXML MISC мы всегда кладём в `consumable`
  (Water Agent не мапится в `water_treatment`), поэтому `Gypsum (Calcium Sulfate)` под
  `type=consumable` → 0 результатов; тот же запрос под `water_treatment` сразу даёт «Гипс».
  То же с `Calcium Chloride`.
- **Дрожжи с вендор-префиксом/™:** `Wyeast 2126 - Bohemian Lager™` → 0;
  `Bohemian Lager` → «Богемский лагер».
- **Хлопья теряются на фильтре типа:** `Flaked Oats` с `type=malt` → 0, хотя «Овсяные хлопья»
  есть в каталоге как `fermentable` (BeerXML `TYPE=Grain` → мы ставим `malt`).
  То же `Flaked Barley`, `Torrified Wheat`.
- **Ранжирование врёт в топе:** `Chocolate` → «Жженый черный» (шоколадный только третьим),
  `Carafa Special Malt Type 1` → «Кара Кристал», `Coffee, Dark Roast` → «Чёрный перец».
- **Реальные дыры каталога** (не баги поиска): First Gold, Sorachi Ace, Protafloc,
  Bavarian Weizen Yeast.

Минимальный набор фиксов подбора: нормализация имени (снять `(...)`, `™/®`, вендор-префикс),
правильный тип для MISC (Water Agent → `water_treatment`), поиск без жёсткого type-фильтра
(или с расширением malt ↔ fermentable), автоподбор при импорте с показом «похоже на X, подтвердить».

## Экспорт

Наш BeerXML читается сторонним парсером (проверено pybeerxml на экспорте Burton Ale), но:

- **нет обязательных по стандарту** `STYLE`, `BREWER`, `BOIL_SIZE`, `WATERS`, `GRAIN_TEMP`,
  `INFUSE_AMOUNT` — строгие импортёры (BeerSmith, Brewfather) могут отвергнуть файл;
  `BOIL_SIZE` не пишется никогда (`getBoilSizeL` — заглушка, всегда `null`);
- `TYPE` рецепта захардкожен «All Grain», `YEAST/TYPE` — всегда «Ale», `MASH_STEP/TYPE` — «Infusion»;
- **«1 пачка» уезжает как `AMOUNT=1, AMOUNT_IS_WEIGHT=FALSE`** — то есть **1 литр** дрожжевой
  суспензии для любого чужого софта (единицы `pack`/`item` не распознаются, срабатывает фолбэк);
- двойное экранирование: `&apos;` из исходника → `&amp;apos;` на экспорте, и так с каждым
  круговым рейсом (импорт декодирует только `&lt; &gt; &amp;`);
- обязательные `YIELD`/`COLOR` у FERMENTABLE и `ALPHA` у HOP пропадают, если поля пустые;
- не экспортируются: стиль, оборудование, водный план, профиль брожения, карбонизация.

## Прочее

- **BeerXML v2** (namespaced, `<beer_xml xmlns="urn:beerxml:v2">`, официальные примеры стандарта)
  → `IMPORT_RECIPE_EMPTY`. Сообщение вводит в заблуждение: формат просто не поддержан.
- **BeerJSON** → `INVALID_BREWFATHER_JSON`. Формат не поддержан (стоит явно сказать это в UI
  и/или поддержать — это де-факто преемник BeerXML).
- Модалка: нет ограничения на размер файла (Server Action упадёт на дефолтном лимите 1 МБ
  с невнятной ошибкой); `buildImportRecipeSummary` парсит весь XML синхронно на **каждое нажатие
  клавиши** в textarea — заметный фриз на крупных файлах.
- Из импорта не читаются вообще: `EQUIPMENT`, `WATERS`, `BOIL_SIZE`, `STYLE`,
  `FERMENTATION_STAGES`, карбонизация, лаборатория/product ID дрожжей, тип mash-шага.

## Предлагаемый порядок работ

1. **P0-пакет парсера**: заменить регекспы на нормальный XML-парсер (снимает P0-3, P0-4, P1-6,
   CDATA, сущности разом), нули → «неизвестно» (P0-1), не падать на `AMOUNT=0` (P0-2),
   sniffing кодировки (P0-5).
2. **Единицы**: литры для YEAST/MISC при `AMOUNT_IS_WEIGHT=FALSE`, корректный экспорт `pack`.
3. **Подбор из каталога при импорте**: нормализация имени + верный тип + автоподбор с
   подтверждением; это же чинит нулевые технические данные (P0-1) по-настоящему.
4. **Экспорт по спеке**: `STYLE`/`BREWER`/`BOIL_SIZE`/`WATERS`/`GRAIN_TEMP`, реальный `TYPE`.
5. Мультирецептные файлы (выбор рецепта), внятные сообщения для BeerXML v2 / BeerJSON.
