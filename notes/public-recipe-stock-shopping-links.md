# Публичный рецепт ↔ склад и список покупок (ТЗ 2026-07-15)

> Порядок исполнения — в едином плане: `notes/ux-walkthrough-2026-07-15.md`, раздел «Единый порядок работ» (П3 → волна 2 вместе с Ф2; П1+П2 → волна 4 вместе с Ф6; П4 — опционально после П1–П2).

Контекст: вопрос «нужны ли кнопки "на склад / в покупки" на карточках ингредиентов чужого рецепта». Разбор показал: действие уже существует в правильном месте — панель «Совпадение со складом» добавляет именно **нехватку** (с учётом остатков и пересчёта под объём), а список покупок (`/app/shopping`, таб «Чего не хватает» в «Моём складе») — выводимый, не ручной: запланированные варки (§3.2) + «Почти хватает на:» из сохранённых/своих рецептов (§3.3). Кнопки на карточках дублировали бы это худшим способом. Реальные проблемы — в видимости и доступности существующей механики.

Ключевые файлы: `apps/web/components/recipes/public-recipe-page.tsx` (раскладка, aside), `apps/web/components/recipes/recipe-match-panel.tsx` (матч + «На склад»), `apps/web/features/shopping/service.ts` (выводимый список), `apps/web/components/recipes/recipe-save-button.tsx`, `apps/web/components/inventory/inventory-tabs.tsx`.

## П1 (P1). На мобильном матч со складом практически недоступен

**СДЕЛАНО 2026-07-15 (волна 4, 7228e5b).** Мобильная плашка-вердикт (recipe-match-mobile-badge.tsx, lg:hidden) сразу после «Ключевых показателей»: процент + «Есть N из M · не хватает K»; тап скроллит к #match-panel (scroll-mt с --chrome-top — фикс ревью против липкой шапки). Данные — общий RecipeMatchProvider (recipe-match-context.tsx): плашка, панель и тост П2 читают один стейт, reload после «На склад» обновляет всех. Живой прогон 375×812: плашка в первых двух экранах, после скролла верх панели не под шапкой (y=72 > 56).

Панель «Совпадение со складом» живёт в `<aside>`, который на мобильном падает в самый низ — под ингредиенты, воду, затирание, кипячение и брожение. Пользователь с телефона не узнаёт, хватает ли ему ингредиентов, и не доберётся до кнопок «На склад».

- [x] Вердикт матча (процент / «не хватает N») виден на мобильном без скролла через весь рецепт — например, компактная плашка после статов-полосы, ведущая к полной панели (якорь/разворот). На десктопе поведение не меняется.
- [x] От вердикта один тап до списка нехваток с действиями «На склад».
- Приёмка: залогиненный на 375px видит вердикт в первом-втором экране; аноним — без изменений (документ остаётся кэшируемым, персональное — после гидрации, как сейчас). ✅ проверено живым прогоном (аноним через nb_dev_guest=1 — без плашки, консоль чистая).

## П2 (P1). Связка «Сохранить / Сварить → список покупок» невидима

**СДЕЛАНО 2026-07-15 (волна 4, 7228e5b; формулировка тоста согласована с владельцем до правок).** «не хватает N» в панели — ссылка на /app/shopping; тост после «В закладки» (Ф6) условный: при нехватках title «В закладках» + кнопка «Чего не хватает» → /app/shopping, при полном покрытии — кнопка «Закладки» → /app/saved. Живой прогон: обе ветки PASS (полное покрытие получено доукладкой Зааза на «Летний пилснер»).

Механика есть: сохранённый рецепт всплывает в «Чего не хватает» как «Почти хватает на:», запланированная варка агрегирует нехватки в общий список. Но со страницы рецепта эта цепочка никак не видна — пользователь, желающий «купить под этот рецепт», не знает, что «Сохранить» и есть его действие.

- [x] Панель матча при неполном покрытии ведёт в `/app/shopping` (ссылка от строки «не хватает N», без подписи-объяснения).
- [x] После «Сохранить» на рецепте с нехватками пользователь понимает, что рецепт попал в «Чего не хватает» (кандидат: тост с ссылкой; формулировку согласовать с владельцем).
- Приёмка: путь «увидел чужой рецепт → понял, чего не хватает → оказался в списке покупок» проходится без знания внутренностей продукта. ✅

## П3 (P2). Нехватка без каталожной привязки — тупик без действия

**СДЕЛАНО 2026-07-15 (волна 2, вместе с Ф2).** Реализован «максимум»: deeplink `/app/ingredients?addName=…&addQty=…&addUnit=…&addCategory=…` (`buildIngredientNameActionHref`) открывает модалку сразу в режиме «Добавить свой» с предзаполненным именем/количеством/категорией; в списке покупок фолбэк `resolveIngredientHrefs` отдаёт `/catalog?q=<имя>` + этот deeplink. В панели матча: строки с кастомной привязкой получили инлайн «На склад» (только для своих — чужой `userCustomIngredientId` зануляется при сборке match-DTO, строка становится name-only), строки без привязки — ссылки «Найти в каталоге»/«Добавить свой». Ref-guard префилла формы починен (не гаснет при первом несовпадении единицы, не затирает ручной ввод).

Кнопка «На склад» рендерится только у строк с `ingredientCatalogItemId` (recipe-match-panel.tsx, фильтр gaps). Строки, живущие только именем из снапшота (типично для импортированных рецептов — подбор из каталога слабый, см. notes/recipe-import-export-audit-2026-07-11.md), показываются как «Нет», но сделать с ними ничего нельзя: ни в каталог, ни на склад.

- [x] У строки-нехватки без привязки есть выход: минимум — поиск по каталогу с именем строки; максимум — добавление кастомного ингредиента с предзаполненным именем/количеством.
- [x] Та же логика — в списке покупок (`resolveIngredientHrefs` в shopping/service.ts возвращает null-hrefs → строка без действий).
- Приёмка: на импортированном рецепте с непривязанной строкой из панели матча можно дойти до пополнения склада, не набирая имя руками.

## П4 (P3, опционально). При чтении ингредиентов не видно наличие

Статус «есть/частично/нет» существует только в панели матча — читая карточки ингредиентов, пользователь сопоставляет два списка глазами. Кандидат: тихие индикаторы наличия на карточках из уже загруженного клиентского матча, **без** кнопок-действий.

- [ ] Залогиненный видит наличие прямо в списке ингредиентов; аноним — ту же страницу без изменений.
- Риск — визуальный шум на документной части страницы. Делать только после П1–П2 и смотреть вживую; если шумит — не делать.

## Чего не делаем (осознанно)

- **Кнопки «на склад / в покупки» на карточках ингредиентов** — дублируют панель матча худшим способом: добавляли бы количество из рецепта, а не нехватку, игнорируя остатки и пересчёт объёма; шумят для анонимов.
- **Ручной список покупок** (положить произвольную позицию кнопкой) — ломает выводимую модель §3.2/§3.3 («возможность, не обязательство»); отдельное продуктовое решение, не отсюда.
