# UX-аудит №2: навигация, IA, зоны, flow

> Продуктово-UX аудит всего сайта, 2026-07-03. По факту кода (ветка feature/home-redesign, включая незакоммиченный редизайн главной).
> Продолжение `notes/navigation-audit.md` (2026-07-01, все 7 пунктов закрыты — регрессий не найдено).
> Метод: multi-agent аудит (4 линзы: IA / зоны и мосты / сквозные сценарии / самоочевидность), каждое замечание адверсариально сверено с кодом. 35 сырых находок → 15 уникальных после дедупликации.

## Ответ на главный вопрос: нужно ли на главной отмечать вход в рабочую зону?

**Нет, не нужно.** Вход уже размечен структурно и многократно, дополнительная разметка была бы дублем:

- hero-CTA «Собрать рецепт» → `/login?next=/app/recipes/new` (`app/(public)/page.tsx:67`);
- секция «Как работает мастерская» с действием «Начать» (`page.tsx:104-112`);
- блок BrewForge → `next=/app/devices`;
- финальная развилка «Начать с рецепта / Начать со склада» (`page.tsx:187-213`);
- «Войти» в хедере; `/login` без `next` приземляет в `/app`.

Ключевой момент: главную видит **только аноним** (залогиненного `/` редиректит на `/app`), а для анонима «вход в рабочую зону» физически = логин. Отдельная кнопка «Мастерская» рядом с «Войти» была бы бессмысленным дублем. Редирект залогиненного с `/` контента не теряет — всё содержимое главной (стили, гайды, калькуляторы, рецепты сообщества) доступно из группы 3 сайдбара. Не трогать.

## Что спроектировано правильно (не ломать)

- Единый конфиг `lib/navigation.ts` (сайдбар/bottom-nav/drawer/табы из одного источника) — но футер до него не доведён (п.9).
- Трёхгрупповой сайдбар без текстовых заголовков: петля workflow → железо → витринные мосты; граница «моё/общее» передана порядком и разделителями.
- Дуальный хром без прыжков (итог аудита №1): аноним — хедер везде, залогиненный — сайдбар везде; лого ведёт в «дом» своего хрома.
- Прогрессивная регистрация сквозная: все CTA несут `?next=`, включая все 5 входов новой главной; `requireUser` прокидывает `x-pathname`.
- Мобильная приоритезация честная: bottom-nav = 4 primary-пункта петли + «Ещё»; недоступных с телефона разделов нет (проблема drawer — в реализации, не в составе, п.3).
- Сценарий «продолжить варку»: два клика от логина до текущего шага (редирект → дашборд → «Активные варки» по срочности).
- Онбординг новичка на дашборде: нумерованные шаги каталог→склад→рецепт, без пояснительных абзацев.
- Замкнутый цикл покупок: список покупок → каталог → deep-link «На склад» (`?addSource=&addId=`) — переходы несут данные.
- BJCP-деталка — эталон перелинковки (крошка, «Что варят в стиле» → `/recipes?style=`, соседние стили). Паттерн тиражировать (п.5, п.8).
- Новая главная почти без слопа: живая панель стилей и петля показывают продукт вместо абзацев о нём; терминология чистая.

## Задачи (по убыванию важности)

### 1. Страница /login — прототип с dev-текстами на пути всей конверсии ⭐ P1

**Проблема.** Каждый сценарий превращения анонима в пользователя (все 5 CTA главной, «Сварить»/«Сохранить» с рецепта, «Войти, чтобы добавить» из каталога) заканчивается на странице из голых кнопок вне дизайн-системы, с dev-фразами в пользовательских сообщениях: «Код отправлен по SMS (в dev — см. логи сервера)», «OTP отправлен (см. server logs)» — показываются и в prod. Кнопки «OTP»/«Magic link»/«Пароль» — внутренний жаргон. Сброс пароля требует вручную вставить reset-token. После вылизанной главной — обрыв доверия ровно на шаге решения о регистрации.

**Где.** `app/(public)/login/page.tsx:44,77,112-114,122,143,171-173`.

**Что сделать.** Довести до уровня витрины на примитивах `@nb/ui`; dev-подсказки — только за `NODE_ENV !== "production"`; reset — по ссылке из письма. Механику (phone-first, `?next=`, автосоздание аккаунта) не трогать.

**Статус:** [x]

### 2. Хаб «Рецепты» обрывается на третьем табе ⭐ P1

**Проблема.** Хаб задуман как «один пункт — три поверхности» (Мои / Сохранённые / Найти), но полоса табов есть только на `/app/recipes` и `/app/saved`. Клик по «Найти» → `/recipes`, где табы исчезают: модель, которой пользователь только что пользовался, пропала. Возврат — только повторным кликом по уже подсвеченному пункту сайдбара. Вместо таба на `/recipes` залогиненному дана кнопка-костыль «Избранные» → `/app/saved` — второй, иначе названный вход в тот же раздел. Это ядро продукта.

**Где.** `lib/navigation.ts:68-72`; `app/(app)/app/recipes/content.tsx:19`; `app/(app)/app/saved/page.tsx:25`; `app/(public)/recipes/page.tsx:75-88`.

**Что сделать.** Достроить хаб: залогиненному рендерить ту же `RecipeTabs` на `/recipes` (аноним табов не видит), кнопку «Избранные» убрать как дубль. Альтернатива — убрать таб «Найти» вовсе; половинчатое состояние хуже обоих вариантов.

**Статус:** [x]

### 3. Мобильный drawer не скроллится — «Выйти» недостижим P2

**Проблема.** Drawer — самописная `fixed inset-0` модалка (нарушение конвенции проекта «модалки только через Dialog/Sheet из `@nb/ui`»): без scroll-lock, focus-trap, Escape и, главное, без `overflow-y-auto`. Контент (11 пунктов + разделители + Админка/Профиль/Выйти) выше вьюпорта в landscape и впритык на маленьких телефонах (у staff — гарантированно не влезает). «Выйти» в мобильном UI существует ТОЛЬКО там → на таких экранах logout невозможен.

**Где.** `components/app/app-shell.tsx:208-232`; `components/app/app-sidebar-nav.tsx:36-37,88-96`.

**Что сделать.** Перевести drawer на `Sheet` из `@nb/ui` + `overflow-y-auto` списку.

**Статус:** [x]

### 4. Публичный хедер не sticky — 56px дыра на /recipes и длинные страницы без навигации P2

**Проблема.** Тулбар витрины рецептов свёрстан `sticky top-14` под мобильную шапку AppShell, но аноним получает SiteHeader, который вообще не sticky: тулбар прилипает на 56px ниже верха с пустой полосой. Вторая сторона: на длинной главной (8 блоков) у анонима в середине страницы нет ни одного постоянного элемента навигации — ни хедера, ни bottom-nav. Аноним с телефона — основной SEO-трафик.

**Где.** `app/(public)/recipes/page.tsx:105`; `components/shared/site-header.tsx:71`; `components/app/app-shell.tsx:190`.

**Что сделать.** SiteHeader → `sticky top-0` высотой `h-14` (та же, что мобильная шапка AppShell) — offset `top-14` станет верным в обоих хромах без ветвлений.

**Статус:** [x]

### 5. Деталка публичного рецепта — тупик P2

**Проблема.** Единственная деталка витрины без пути назад (у каталога и BJCP — крошки, у гайдов/калькуляторов — «← Все …»). Бейдж стиля — мёртвый span, хотя обратный мост уже построен («Что варят в стиле» → `/recipes?style=`), а паттерн кликабельного стиля уже есть на карточках списков (`StyleChip` → `/bjcp/<slug>`). SEO-посетитель на рецепте не может ни вернуться к списку, ни провалиться в справочник стиля.

**Где.** `components/recipes/public-recipe-header.tsx:22-26`; `components/recipes/public-recipe-page.tsx` (ни одной Link); эталоны: `catalog/[source]/[id]/page.tsx:196-199`, `components/recipes/recipe-card-parts.tsx:186-189`.

**Что сделать.** Бейдж стиля → ссылка на `/bjcp/<slug>` (зеркало существующего моста); back-link «← Рецепты» тем же паттерном, что у гайдов.

**Статус:** [x]

### 7. Дашборд регуляра: заголовок врёт, дубли-CTA, две плитки в одно место P2

**Проблема.** (а) h2 «С чего начать» рендерится безусловно, а содержимое переключается — регуляр с 20 варками видит повседневные действия под онбординг-заголовком. (в) «+ Новый рецепт» приклеен к заголовку чужой секции «Полезное рядом» и дублирует «Создать рецепт» строкой выше. (г) У регуляра без активных варок нет «продолжить» — дашборд почти пуст.

**Где.** `app/(app)/app/page.tsx:146-148,216-219,248-250`.

**Что сделать.** «С чего начать» — только новичку (регуляру карточки без заголовка); «Всего позиций» → плитка «Варки» → `/app/brew-batches`; «+ Новый рецепт» убрать; регуляру без варок — последние рецепты/последняя варка (перестановка существующих данных, не новые подсказки).

**Статус:** [x]

### 8. Знаниевый контур обрывается: гайд и калькулятор не ведут дальше P2

Оба главных SEO-входа — мягкие тупики: посчитал ABV, дочитал гайд — и ушёл, не увидев ни рецептов, ни мастерской. Контраст с эталоном BJCP-деталки.

**Где.** `app/(public)/guides/[slug]/page.tsx:62-64`; `components/calculators/calculator-page-client.tsx:1303,1383-1396`.

**Что сделать.** Расширить существующий блок «Дальше» калькулятора назначениями вне `/calculators` (профильный BJCP-раздел, рецепты с релевантным фильтром); в модель гайда добавить related-связи и рендерить тем же блоком. Перелинковка структурой, не текстами.

**Статус:** [x]

### 9. Футер — статическая карта, разошедшаяся с navigation.ts и слепая к сессии P2

Копирайт англоязычный («knowledge base & brewing workspace»).

**Где.** `components/shared/site-footer.tsx:6-31,64`; `app/layout.tsx:41`; `lib/navigation.ts:16-19`.

**Что сделать.** Собрать футер из `appNavGroups`/`publicLinks` с учётом сессии: анониму — витринные колонки + «Войти», залогиненному — без «Войти». Решить, нужен ли футер внутри `/app` вообще (дублирует сайдбар).

- **п.1 (логин):** сброс пароля потребляет уже существующую бек-ссылку `/login?flow=reset&token=…` (`lib/auth.ts`); ручной ввод токена убран, из протухшей ссылки есть выход («Запросить новую ссылку» / «Вернуться ко входу»). Машинные коды ошибок → человеческие тексты; dev-подсказки про логи — только вне production. Flow-имена: «Код на почту» / «Ссылка на почту» / «Пароль».
- **п.2:** на `/recipes` залогиненному рендерится тот же `RecipeTabs`; кнопка «Избранные» удалена. `countSavedRecipes` в сервисе оставлен (публичный API слоя).
- **п.4:** введена CSS-переменная `--chrome-top` (AppShell: `3.5rem`/`0` от брейкпоинта; анонимный хром: `3.5rem`) — все хром-зависимые sticky-оффсеты (тулбар `/recipes`, мастер рецептов, панели калькуляторов, aside деталки рецепта, шапка пульта устройства) привязаны к ней, ветвления по хрому в страницах не нужны.
- **п.3:** `Sheet` в `@nb/ui` расширен аддитивно (`side="left"`, `title: ReactNode` + keyframe в globals.css); drawer закрывается при пересечении брейкпоинта `lg` (портал не подчиняется `lg:hidden`).
- **п.8 (гайды):** related-связи — статическая куратируемая карта `features/content-articles/related-links.ts` (+дефолтный набор), без миграции БД — до появления CMS (Track A). Общий чип-блок «Дальше»: `components/shared/related-links-section.tsx` (калькуляторы + гайды).
- **п.9:** футер видит только аноним (монтаж в анонимной ветке `PublicShell`; залогиненный на витрине живёт в AppShell). Собирается из `publicLinks` в `lib/navigation.ts` — единый источник и для хедера (п.12/14 закрыты им же).
- **п.11:** канон «BrewForge» (пункт сайдбара, h1, крошка пульта, error-заголовок); h1 «Профили оборудования» оставлен как полное имя раздела.
- Попутно починены протухшие тесты: мок дашборда (`countBrewBatchesForUser`), футер в `site-shell.test.ts`, «Метод расчета»→«Как считаем?» в `calculators-pages.test.ts`, счётчики каталога в `catalog-seed-data.test.ts`.
- **Не тронуто осознанно:** красные `recipe-editor-components.test.ts` / `recipe-service.test.ts` (валидация публикации без `styleId`) — это параллельная незакоммиченная работа по мастеру рецептов, её тесты чинятся там.

Проверки: `npm run typecheck` — зелёный по всем workspace; vitest apps/web — 1220 тестов, красные только 2 файла параллельной работы (см. выше). Вживую (браузером) не прогонялось.
