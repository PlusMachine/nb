# Аудит навигации: зоны, переключение, ценность логина

> Продуктово-UX аудит навигации, 2026-07-01. По факту кода, не по догадкам.
> Рабочий чеклист: идём по пунктам сверху вниз и правим. Статус в конце каждого пункта.
> Связано: `docs/roadmap.md`, `docs/improvement-recommendations.md`, memory `product-model-and-roadmap`.

## Как устроено сейчас (снимок)

Три зоны с тремя разными «хромами» (обёртками):

- **Публичная витрина** `app/(public)/*` — `/`, `/guides`, `/bjcp`, `/calculators`, `/recipes`, `/catalog`, `/articles`, `/login`.
  Хром: `PublicShell` → `SiteHeader variant="public"` (лого + 5 ссылок + «Войти»/«Рабочая зона»). Широкий контейнер `max-w-7xl`. Доступна всем.
- **Рабочая зона** `app/(app)/app/*` — Обзор, Рецепты, Склад, Варки, Оборудование, Устройства, Сохранённые, Профиль, Настройки.
  Хром: `AppShell` (сайдбар слева на десктопе `w-60` + drawer/bottom-nav на мобиле), контейнер `max-w-6xl`. Гейт `requireUser()` → редирект `/login`.
- **Админка** `app/(admin)/*` — editor+. Хром: голый `<div>Admin zone</div>` вне общей навигации.

**«Дуальный хром»** (`components/shared/public-shell.tsx:21`): залогиненному на справочниках
(`referencePathPrefixes` = `/catalog`, `/guides`, `/bjcp`, `/calculators`, `/recipes`) публичный хедер
подменяется на сайдбар рабочей зоны (`AppShell`). «Один контент — два хрома».

Единый конфиг навигации — `apps/web/lib/navigation.ts` (сайдбар/футер/табы из одного источника).
Middleware нет — вся защита в layout через `requireUser()` / `requireContentRole()`.

## Что уже сделано правильно (не ломать)

- Разделение витрина/мастерская оправдано: две петли (контент привлекает из SEO → мастерская удерживает), разные ментальные модели → разный хром.
- **Контекстные якоря регистрации** — `redirectToLoginWithNext()` при «Сохранить»/«Оценить»/«Использовать для варки» → `/login?next=…` и возврат назад. Аккаунт создаётся сам при первом входе. Это лучший паттерн (progressive signup) — сохранить.
- Справочники открыты анониму (каталог/стили/калькуляторы/рецепты) — правильно для SEO и «попробуй до регистрации».
- Единый `lib/navigation.ts` — группировки не расходятся между поверхностями.

## Задачи (по убыванию продуктовой важности)

### 1. Аноним не понимает, зачем логиниться — скрыта суть продукта  ⭐ P0

**Проблема.** На главной (`app/(public)/page.tsx`) оба CTA («Читать гайды», «Рецепты сообщества») ведут в контент.
Кнопка «Войти» — голая, без обещания. Нигде на первом экране не показано, что за логином — *мастерская пивовара*
(рецепт из своего склада → «что могу сварить» → варка → журнал → устройство). Продукт сам себя подаёт как базу
знаний, пряча главный retention-слой. Пользователь узнаёт о мастерской, только случайно нажав «сохранить».

**Где.** `apps/web/app/(public)/page.tsx` (hero + entryTiles); ярлык «Войти» в `components/shared/site-header.tsx:83`.

**Что сделать.** Отдельный блок/CTA на главной про рабочую петлю («Соберите рецепт из своего склада → сварите → ведите
журнал»), визуально отделённый от контентных плиток. Не слоп-подзаголовки, а честное ценностное предложение мастерской.

**Статус:** [x] сделано (2026-07-01). `app/(public)/page.tsx`: hero H1 «Свари своё пиво — от рецепта до розлива» + подзаголовок
про склад→рецепт→варку→журнал; primary CTA «Собрать рецепт» → `/login?next=/app/recipes/new`; новый блок «Как работает
мастерская» (4 шага Склад/Рецепт/Варка/Журнал, иконка+слово); `entryTiles` сокращены (Гайды/Стили/Калькуляторы).

### 2. «Прыгающий хром» при навигации  ⭐ P0

**Проблема.** Залогиненный на `/recipes` видит сайдбар (AppShell). Кликнул на `/` или `/articles` — сайдбар исчезает,
возвращается горизонтальный хедер. `/guides` (в `referencePathPrefixes` → сайдбар) и `/articles` (не в списке → хедер)
ведут себя по-разному, хотя оба — «контент». Навигация неожиданно меняется под ногами; пользователь то «в мастерской»,
то «выпал» без явного действия.

**Где.** `components/shared/public-shell.tsx:21`, `lib/navigation.ts:65` (`referencePathPrefixes` / `isReferencePath`).

**Что сделать.** Выбрать одно согласованно: (а) залогиненному *все* публичные разделы показывать в AppShell (единый
сайдбар, из которого он не «вылетает»), либо (б) не подменять хром вовсе — один хедер + пункт «Мастерская». Минимум —
свести `/guides` и `/articles` к одному поведению. Решить осознанно, а не «наполовину».

**Статус:** [x] сделано (2026-07-01), вариант (а) app-first. `public-shell.tsx`: правило → `if (user && pathname !== "/login")`
→ AppShell (сайдбар на всех публичных страницах, кроме /login). `page.tsx`: залогиненного с `/` редиректим на `/app`.
`navigation.ts`: удалены `referencePathPrefixes`/`isReferencePath` (мёртвый код). `app-sidebar-nav.tsx`: убрана ссылка
«На сайт»→`/` (уводила по кругу). Итог: аноним → хедер везде, залогиненный → сайдбар везде, прыжка нет.

### 3. Ярлык «Рабочая зона» ничего не обещает  P1

**Проблема.** «Рабочая зона» / «Обзор» — внутренние функциональные имена, для пользователя пусты (не говорят «твои
рецепты, склад, варки»). Кнопка-мост из витрины должна нести смысл. Это не «слоп-подпись» — речь про смысл самого ярлыка.

**Где.** `components/shared/site-header.tsx:73` (кнопка «Рабочая зона»), `:165` (пункт меню), `lib/navigation.ts:33`
(«Обзор»), футер `components/shared/site-footer.tsx`.

**Что сделать.** Осмысленный ярлык («Моя пивоварня» / «Мастерская» / «Мои рецепты» — выбрать один и применить везде).

**Статус:** [x] сделано (2026-07-01). Выбран «Мастерская» (продуктовый канон из roadmap). Заменено: кнопка-мост в
`site-header.tsx`, пункт `UserMenu`, заголовок колонки в `site-footer.tsx`. Пункт сайдбара «Обзор» (дашборд `/app`)
оставлен как есть. Легко сменить на «Моя пивоварня»/«Мои рецепты».

### 4. Публичный хедер не адаптирован под мобайл  P1

**Проблема.** `SiteHeader` — просто `flex-wrap` из 5 ссылок + лого + кнопка (`site-header.tsx:34`), без бургера/drawer.
На узком экране всё переносится в 2–3 строки. При этом рабочая зона мобильно вылизана (drawer + bottom-nav).
Асимметрия наоборот: самая важная для привлечения зона (мобильный трафик из поиска) адаптирована хуже внутренней.

**Где.** `components/shared/site-header.tsx:29-90`.

**Что сделать.** Мобильный вариант публичного хедера (бургер + drawer или компактное меню).

**Статус:** [x] сделано (2026-07-01). `site-header.tsx`: на `<md` список разделов скрыт, добавлена кнопка-бургер
(Menu/X) → выпадающая панель со ссылками во всю ширину; закрытие по клику вне, Escape и смене роута. Кнопка «Мастерская»
скрыта на `<sm`, чтобы не теснить хедер. Десктоп — как раньше.

### 5. Потеря контекста при заходе на защищённый URL  P2

**Проблема.** `app/(app)/layout.tsx` → `requireUser()` → `redirect("/login")` без `next`. Аноним по прямой ссылке на
`/app/brew-batches` после логина попадёт на `/app`, а не туда, куда шёл. Якоря-кнопки `next` прокидывают, а layout-гейт — нет.

**Где.** `apps/web/lib/auth.ts` (`requireUser`, ~строки 100-106), `app/(app)/layout.tsx`.

**Что сделать.** Прокинуть `next` в редирект гейта: `redirect("/login?next=" + encodeURIComponent(pathname))`.
Учесть, что `requireUser` — общий; возможно, брать текущий путь через `headers()`.

**Статус:** [x] сделано (2026-07-01). Добавлен `apps/web/middleware.ts` (только проставляет заголовок `x-pathname`,
без auth-редиректов — dev-автологин не ломается). `requireUser` читает `x-pathname` и редиректит на
`/login?next=<encoded>` (safe-проверка `startsWith("/")`). Работает и для `requireRole` (аноним на `/admin/*`).

### 6. Размытая информационная архитектура контента  P2

**Проблема.** Три контентных входа: `/guides` (новый CMS `content_articles`), `/bjcp` и `/articles` (легаси `@nb/content`),
причём `/articles` вообще нет в меню (только по прямым ссылкам). Плюс пункт сайдбара «Рецепты» подсвечивается и на
публичной `/recipes` (`match: ["/recipes"]`, `navigation.ts:34`) — граница «моё / общее» размывается.

**Где.** `lib/navigation.ts:34` (match), `site-header.tsx:17-23` (publicLinks), роут `app/(public)/articles/*`.

**Что сделать.** Решить судьбу `/articles` (слить с /guides или убрать/редирект). Пересмотреть, должна ли подсветка
«Рецепты» в сайдбаре захватывать публичную `/recipes`.

**Статус:** [x] проверено (2026-07-01) — правок не требует. `/articles` и `/articles/[slug]` уже `permanentRedirect`
на `/bjcp` (`/bjcp/[slug]`); `ArticleCard` ведёт на `/bjcp/${slug}`; в UI на `/articles` никто не ссылается — старые ссылки
не ломаются, «третьей витрины» для пользователя нет. Контентные разделы: Гайды (`/guides`, CMS `content_articles`) +
Стили BJCP (`/bjcp`, легаси `@nb/content`). Подсветка «Рецепты» на `/recipes` — намеренная (таб «Найти» хаба рецептов),
оставлена. Остаточный технический нюанс (не UX): дубль термина «article» в коде между двумя контент-слоями — не трогаем.

### 7. Админка выпадает из системы навигации  P3

**Проблема.** `(admin)/layout.tsx` — голый заголовок «Admin zone», без моста из рабочей зоны и обратно. Узкая аудитория
(editor+), но несогласованно с остальным продуктом.

**Где.** `apps/web/app/(admin)/layout.tsx`.

**Что сделать.** Минимальный мост: ссылка на /admin из UserMenu для ролей editor+ и ссылка «Назад в приложение» из админки.

**Статус:** [x] сделано (2026-07-01). Прямой мост: флаг `isStaff` (вычисляется на сервере через `hasRequiredRole(role,"editor")`
в обоих layout'ах, не тащим роли в клиент) добавлен в `SiteHeaderUser`; при `isStaff` в сайдбаре появляется пункт «Админка»
→ `/admin`. Обратный мост: в `(admin)/layout.tsx` добавлена ссылка «← В приложение» → `/app`.
