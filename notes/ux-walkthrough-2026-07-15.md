# Сквозной UX-проход 2026-07-15: отчёт и план работ

**Статус: находки зафиксированы, фиксы НЕ делались.**

Как проверялось: живой прогон в Playwright под обычным пользователем (qa.user, роль user, сидовый склад), два полных флоу:

1. **Чужой рецепт**: витрина «Рецепты сообщества» → поиск → Pilsner Urquell → «Скопировать себе» → адаптация под своё оборудование (профиль Grainfather G30, пересчёт под 22 л) → мастер воды (осмос → профиль «Пльзень», соли + молочная кислота, pH 5.35) → «Сварить» → ветка автоматики (демо-пивоварня) → брожение (OG/FG замеры) → «Завершена».
2. **Свой рецепт с нуля**: «Цитровый IPA» 21A → ингредиенты через пикер (склад/каталог, инкрементальный ввод по 2–3 символа) → «Сварить самому» → списание со склада → гид варочного дня (9 шагов) → «Поставить на брожение».

Оба флоу проходимы до конца. Ядро (расчёты, автосейв, списание, гид) работает. Ниже — находки в порядке приоритета, с якорями на код и приёмками.

Пересечение с параллельной работой: идёт незакоммиченный редизайн публичной страницы рецепта (полоса показателей с треками стиля). Ф1 и Ф6 трогают ту же страницу — синхронизировать перед началом.

## P0 — доверие к данным и блокирующие дефекты

- [x] **Ф1. Дрейф показателей при копировании рецепта.** — СДЕЛАНО 2026-07-15. Разведка опровергла гипотезу «дефолтная эффективность»: параметры партии копия наследовала и раньше. Реальные причины: (1) у витринных рецептов сохранённые статы — авторитетные цифры первоисточника поверх движка, а копия всегда пересчитывалась движком; (2) редактор молча обнулял унаследованный снапшот оборудования, если профиль принадлежит автору оригинала. Фикс: копия наследует og/fg/abv/ibu/color источника (кроме явного пересчёта под другой объём); чужой equipmentProfileId в копию не переносится, снапшот сохраняется и редактором не выбрасывается; селект показывает «Оборудование автора рецепта»; в редакторе закрываемая плашка «Показатели автора отличаются от расчёта движка: …» по разошедшимся метрикам. Тесты: clone-service, lifecycle (5 сквозных), designer-equipment-snapshot (новый файл); живой прогон на dev-БД: копия PU = 1.048/4.4/40/4 как у источника.
  Витрина: OG 11.9 °P / ABV 4.4% / IBU 40 / SRM 4 («В стиле»). Сразу после «Скопировать себе»: НП 13.1 °P / ABV 5.8% / IBU 42 / SRM 5.8 (ABV «Выше») — молча. Причина: публичная страница показывает сохранённые статы автора, а редактор пересчитывает копию своим движком с дефолтной эффективностью (72%), не унаследовав параметры оригинала.
  Где: `apps/web/features/recipes/service.ts` (~1963, билдер payload клона — какие параметры партии переносим), `components/recipes/recipe-designer/*` (пересчёт при открытии).
  Варианты: (а) копия наследует эффективность/объём/оборудование-параметры оригинала, пока пользователь сам не сменит профиль; (б) если пересчитали — явный баннер «Показатели пересчитаны под ваши настройки: ABV 4.4% → 5.8%» с кнопкой «вернуть параметры автора».
  Приёмка: копия PU сразу после создания показывает OG/ABV/IBU/SRM оригинала (или явное объяснение разницы); тест на копирование со сравнением статов.

## P1 — понятность ключевых развилок

- [ ] **Ф6. «Сохранить» vs «Скопировать себе» на публичном рецепте — неразличимы.**
  Живой вопрос владельца с `/recipes/oatmeal-stout-stephen-galante`: «вижу сохранить и скопировать — чем отличается? что делает то, что другое?»
  Факт: «Сохранить» = закладка в таб «Сохранённые» (`components/recipes/recipe-save-button.tsx`), копию не создаёт, рецепт остаётся авторским. «Скопировать себе» = редактируемый черновик-копия в «Мои». Слово «Сохранить» без контекста читается как «сохранить себе» ≈ «скопировать» — оба глагола обещают одно и то же.
  Решение (обсудить формулировки с владельцем — правило «имена действиями»): «Сохранить» → **«В закладки»** (иконка Bookmark уже такая) или «В сохранённые»; у «Скопировать себе» оставить как есть. На витрине флажок-иконка — ок, там есть тултип-контекст.
  Приёмка: на детальной странице две кнопки читаются без наведения: закладка vs копия; тексты согласованы с владельцем.

- [ ] **Ф7. Ветка «Сварить → Подключить BrewForge» теряет контекст варки.**
  Из диалога «Сварить рецепт» пункт «Подключить BrewForge» уводит на `/app/devices` без обратного пути: подключив устройство, пользователь должен сам вспомнить рецепт, найти его и нажать «Сварить» заново.
  Где: `components/recipes/brew-picker-dialog.tsx`, `app/(app)/app/devices/*`.
  Решение: передавать `?return=brew:<recipeId>` (или state) — после появления онлайн-устройства показать на «Устройствах» баннер «Устройство подключено → Продолжить варку „Цитровый IPA“».
  Приёмка: путь «Сварить → Подключить → (создать демо) → Продолжить варку» проходит без ручного поиска рецепта.

- [ ] **Ф8. Поиск «Рецептов сообщества» не понимает транслит/раскладку.**
  «пил» не находит Pilsner Urquell, «pilsner» не находит «Летний пилснер». При этом поиск стилей BJCP и поиск каталога ингредиентов кросс-раскладку умеют (там же логика «раскладка-фолбэк» уже есть — переиспользовать).
  Где: `components/recipes/recipes-toolbar.tsx` + серверный поиск витрины в `features/recipes/service.ts`.
  Приёмка: «пил» находит и «Летний пилснер», и Pilsner Urquell; «vayceh»/«вайцен» находят Weihenstephaner; тест на поиск.

- [ ] **Ф9. Пересчёт под объём даёт «0.73 пачки» дрожжей.**
  После «Пересчитать ингредиенты под 22 л» дрожжи стали 0.73 пачки — так не отмеряют.
  Где: `components/recipes/recipe-designer/*` (пересчёт), `recipe-designer/helpers.ts`.
  Решение: для единицы «пачка» округлять вверх до целого (или до 0.5 с подсказкой), показывать хинт «нужно ≥ 0.73 пачки → 1 пачка». Граммы оставить точными.
  Приёмка: пересчёт 30→22 л для «1 пачка» даёт «1 пачка» (не 0.73); обратный пересчёт 22→44 л даёт «2 пачки».

- [ ] **Ф10. План варочного дня дублирует засыпь.**
  Для односолодового рецепта гид даёт «Засыпьте солод 5 кг» (до пауз) и отдельно «Внести: Пэйл Эль 5 кг» ПОСЛЕ часовой температурной паузы. Пивовар видит два внесения одного солода, второе — не в том месте.
  Где: `features/brew-batches/brew-day.ts:233` («Засыпьте солод»), `:284` («Внести: …» — тайминг-шаги ингредиентов).
  Решение: солод с использованием «Затор» не должен порождать отдельный шаг «Внести» (он уже входит в «Засыпьте солод»); отдельные шаги — только для внесений с явным «поздним» таймингом (настой, кипячение, брожение).
  Приёмка: односолодовый рецепт → в гиде одно внесение солода; рецепт с поздним внесением (например, декстроза в кипячение) сохраняет свой шаг.

- [ ] **Ф11. Профиль оборудования нельзя создать из редактора рецепта.**
  В дропдауне «Оборудование» только «Без профиля»/ручной ввод — пользователь должен догадаться пойти в «Оборудование», создать профиль и вернуться.
  Где: `components/recipes/recipe-designer/recipe-batch-parameters-block.tsx`.
  Решение: пункт «+ Создать профиль…» в конце списка → открывает `/app/equipment?mode=create` в новой вкладке или инлайн-диалог; после создания — профиль выбран.
  Приёмка: из редактора без профилей можно дойти до выбранного профиля не теряя черновик.

- [ ] **Ф12. Демо-пивоварня: варка выглядит сломанной.**
  а) Сценарий mash зациклен: таймер паузы скачет (осталось 6:00 → 37:30 → 22:30 → 40:30), график — пила из повторов затирания; варка не доходит до кипячения.
  б) «Далее» даёт тост «Стадия пропущена», но стадия/прогресс не меняются — я нажал трижды (на реальном железе так перескочат лишние стадии). Нужна мгновенная обратная связь: оптимистичная смена стадии или дизейбл кнопки до подтверждения устройства.
  в) Пульт показывает «Затирание (сценарий mash)», уставку 64 °C и «Пауза 1 из 2», хотя в рецепте один шаг 65 °C/60 мин — нигде не сказано, что демо крутит встроенный сценарий, а не рецепт. Подписать: «Демо-сценарий, не ваш рецепт» (или гнать демо по рецепту).
  Где: `packages/brewforge-sim/src/sim-device.ts` (луп сценария), пульт партии в `apps/web/app/(app)/app/brew-batches/[id]/*`.
  Приёмка: демо-варка проходит затор→кипячение→готово за ~10 мин без луп-повторов; «Далее» либо меняет стадию ≤2 с, либо блокируется с индикатором «команда отправлена».

## Что работает отлично (не трогать)

- **Мастер воды** — сильнейшее место прохода: профили из каталога ранжируются «подходит по стилю», соли и кислота считаются вместе (гипс 0.24 г / CaCl₂ 0.11 г / эпсом 0.04 г / молочная 6.58 мл на осмосе для Пльзеня — правдоподобно после Ф1–Ф12 водного аудита), доменное предупреждение «Объём до кипячения не помещается в котёл (28,0 л)».
- **Гид варочного дня**: «СЕЙЧАС/Следом», таймеры шагов, «Вернуть шаг», хмель «за 60/10 мин до конца», прогресс 9/9 → «Поставить на брожение».
- **Склад**: списание с историей движений и «Вернуть на склад» (Цитра −120 г корректно сложила три закладки), «Рецепты под ваш склад» с процентом и списком нехваток.
- Диалоги с guardrail'ами: копирование («попадёт как черновик»), запуск нагрева («убедитесь, что в ёмкости есть вода»), завершение («день 1 из 35 … этап можно вернуть»).
- Онбординг-чеклист «С чего начать», виджеты дашборда, автосейв редактора.

## Инфраструктурная заметка (не продуктовые баги)

Во время прогона в системе крутились **три** dev-сервера (два посторонних, без TTY — вероятно, от параллельной сессии; см. memory `parallel-sessions-worktrees`). Они делили `.next` и давали каскад артефактов: 500/404 на роутах, слетевший CSS (страница «Мои рецепты» рендерилась картинкой стиля BJCP на весь экран — это НЕ продуктовый баг), потеря куки → dev-автологин молча подменял qa.user на qa.admin (memory `dev-anon-qa-trap`), из-за чего пикер склада разово показал чужие остатки. Лечение: убить лишние процессы точечно (`kill -TERM <pid>`), `touch apps/web/next.config.ts` для пересборки манифестов. Правило: параллельные сессии — только в worktree.

Артефакты прогона в БД (qa.user): рецепты «Pilsner Urquell (копия)», «Цитровый IPA»; партии №1 обоих рецептов; профиль Grainfather G30; демо-пивоварня; списанный склад (−5 кг pale ale, −120 г Citra, −11 г US-05). Чистка: `npm run seed:qa`.
