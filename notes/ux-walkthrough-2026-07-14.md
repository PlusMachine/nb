# UI/UX-обход всех разделов (2026-07-14)

Живой прогон в браузере (Playwright + dev-сервер) в трёх ролях:

- **аноним** — через dev-гостевой просмотр (cookie `nb_dev_guest`);
- **свежий пользователь** — создан чистый аккаунт `fresh.user@localhost`, первые шаги пройдены руками через UI;
- **QA-админ** (`qa.admin@localhost`, dev-автологин) — рабочая зона с данными.

Проверено: вся публичная витрина, вход/регистрация, онбординг с нуля (склад → рецепт → варка), партии и помощник варки, наклейки, оборудование, профиль, админка (обзор), мобильная вёрстка 390px, тёмная тема. Только оценка — **фиксы не делались**.

## Резюме

Навигация и IA цельные: витрина (Рецепты / Стили пива / Калькуляторы / Статьи / Каталог / Маркет / BrewForge) и рабочая зона (сайдбар + нижний таб-бар на мобильном) говорят одним языком. Онбординг — сильная сторона продукта: цепочка «регистрация → пустые состояния → первый ингредиент → рецепты под склад» работает без разрывов. Основной долг — мелкая лексика и один системный ляп с автоименами партий.

## Что работает хорошо (не трогать)

1. **Онбординг-чеклист «С чего начать» (0 из 3)** на `/app` — шаги-ссылки, прогресс засчитывается фактическими действиями (проверено: добавил солод → «1 из 3», шаг зачёркнут, дашборд оброс виджетами).
2. **Момент активации**: после первого же ингредиента на складе появляется колонка «Рецепты под ваш склад» с процентом совпадения, бейджами «Хватает всего / Почти хватает» и списком «не хватает». Это лучший крючок в продукте.
3. **Гейты для анонима контекстные**: «Сварить» у анонима → модалка «Войдите, чтобы начать варку. Варка сохранится в вашей мастерской… Аккаунт создаётся автоматически при первом входе» — правильная мотивация вместо голого редиректа. На деталке рецепта — «Войдите, чтобы увидеть, сколько ингредиентов… есть на вашем складе».
4. **Вход и регистрация одной формой** (телефон/e-mail, 18+ и согласие ПДн) — минимум трения.
5. **Пустые состояния** во всех разделах app-зоны: одна фраза + один CTA («Пока нет рецептов → Создать рецепт», «Пока нет ни одной партии → Сварить», устройства → «Демо-пивоварня / Подключить устройство»).
6. **Модалка добавления ингредиента**: категория → «Из каталога / Добавить свой» → поиск с чипами «уточнить производителя» (с счётчиками) → шаг количества с необязательным аккордеоном «Цена, даты и заметки». 55 совпадений по «пилснер» отранжированы вменяемо.
7. **Помощник варки**: блок «СЕЙЧАС / Следом» + чеклисты по этапам (Затор/Кипячение/Охлаждение, 0/5) + «Поставить на брожение» + списание склада и заметки на одной странице.
8. **Контекстные подсказки на партиях**: «Запишите начальную плотность (OG)», «10 дней без замера — проверьте FG» — прямо в карточках дашборда и в деталке.
9. **Демо-страница** `/demo` — экскурсия с нумерованными якорями (1 Рецепты … 5 Дашборд) и честным «все данные — примеры»; тизер BrewForge с бейджем «В разработке» не обещает лишнего.
10. Тёмная тема целостная; мобильный `/app` с таб-баром (Обзор/Рецепты/Склад/Партии/Ещё); карточки-оверлеи рецептов имеют `aria-label`.
11. Страница 404 предлагает быстрые ссылки по разделам (но см. П8).

## Находки

### P1 — чинить в первую очередь

**П1. Автоимя партии «\<рецепт\> brew №N»** — англохвост «brew» во всех местах разом: карточки дашборда, список `/app/brew-batches`, заголовок деталки, заголовок наклеек. Заголовок при этом дублирует подзаголовок: «Пиво для димы brew №1» / под ним «Пиво для димы». Напрашивается формат «Партия №1 · Пиво для димы» (или просто имя рецепта + номер). Противоречит принятой русской лексике раздела («Партии», «Сварить»).

**П2. График брожения при одной точке замера** (деталка партии, статус «Брожение»):
- ось Y растягивается от **−26.2 °P до 25.5 °P** — отрицательный Plato не существует, единственная точка 1.9 °P висит в центре пустого поля;
- ось X подписана «04.07» с обоих концов — дубль одной даты.
Автоскейл осей не рассчитан на серию из 1 точки. Важно: этот же график пойдёт под телеметрию цифровых ареометров (M2/M3) — чинить до того, как туда польются живые данные.

**П3. «День 11 из 10»** — когда брожение перевалило план, счётчик читается как баг, а не как «план превышен». Формат «День 11 · план 10 дней» (или бейдж «дольше плана») снимает вопрос.

### P2 — заметные шероховатости

**П4. Нативные date-инпуты в формате `mm/dd/yyyy`** в форме замера плотности (деталка партии) — даже при `locale: ru-RU` в браузере. Либо форматируемый инпут, либо хотя бы подсказка формата.

**П5. Бейджи «не проверен» на публичном хабе `/calculators`** — внутренний QA-статус формул торчит наружу и скорее подрывает доверие («Эффективность — не проверен»). Убрать с витрины или переформулировать (например, показывать только «✓ проверен»).

**П6. Висячий разделитель в шапке склада**: «21 в наличии • 3 закончились • » и «1 в наличии • » у новичка — после последнего элемента остаётся точка-буллет.

**П7. Маркет**: у лота «ЦКТ 60 л» битая картинка (404 в консоли, виден alt-текст); тестовый лот «Заготовка без фото (тест)» опубликован публично.

**П8. Страница 404 без шапки и навигации** — быстрые ссылки есть, но глобальное меню и логотип пропадают, из тупика нельзя уйти привычным способом. Заодно рассинхрон имён раздела: в меню «Стили пива», заголовок страницы «BJCP справочник стилей», хлебная крошка «BJCP»; интуитивный URL `/styles` не существует (только `/bjcp`) — стоит добавить редирект.

**П9. Чип «20 l» латиницей** на деталке рецепта (рядом «SRM 3.1 · Светло-золотистый», «60 мин кипячения») — везде в продукте литры пишутся «л».

**П10. Наклейки из партии теряют контекст партии**: вход через кебаб партии → «Наклейки», но ссылка возврата — «К рецепту», в сайдбаре подсвечивается «Рецепты». Вернуться к партии, из которой пришёл, нельзя.

### P3 — мелочи

**П11.** У анонима перед логин-гейтом «Сварить» на секунду мигает «Проверяем ваши устройства… Загрузка…» — для неавторизованного проверка устройств не нужна, гейт можно показывать сразу.

**П12.** Профиль спартанский: имя, валюта, единица плотности, уведомления, выход. Нет управления e-mail/телефоном/паролем — если это roadmap, ок; если нет, пользователю некуда пойти сменить контакт.

**П13.** Редактор рецепта на `/app/recipes/new` сразу называет черновик «Новый рецепт N» (счётчик растёт); в QA-аккаунте уже лежат пустые «Новый рецепт 2/4» без единого параметра. Черновики без содержимого замусоривают «Мои рецепты» — возможно, не сохранять до первого осмысленного действия (в моём прогоне до правок стоял статус «Не сохранён» — проверить, когда именно черновик персистится).
