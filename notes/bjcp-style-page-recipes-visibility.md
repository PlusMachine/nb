# ТЗ: страница стиля BJCP — видимость рецептов и навигация по интентам

Дата: 2026-07-04. Страница: `/bjcp/[slug]` (например `/bjcp/bjcp-24a-witbier`).
Код: `apps/web/components/content/bjcp-article-page.tsx`, `apps/web/components/content/style-community-recipes.tsx`, роут `apps/web/app/(public)/bjcp/[slug]/page.tsx`.

## Проблема

На страницу стиля приходят с двумя разными намерениями:

1. **Читатель** — хочет разобраться в стиле как таковом. Его сценарий закрыт: hero-паспорт + лонгрид.
2. **Искатель рецепта** — попал сюда из поиска, каталога или по ссылке, а на самом деле хочет **сварить** этот стиль, т.е. ищет конкретный рецепт.

Для второго сценария страница сейчас слепая: блок «Что варят в стиле» (рецепты сообщества) и блок «Ещё в категории» (соседние стили — выход для тех, кто открыл не тот стиль) находятся **ниже всего лонгрида** (~10 минут чтения). С первого экрана невозможно понять, что рецепты в этом стиле вообще существуют. Пользователь с рецептурным интентом либо уходит, либо думает, что тут «только энциклопедия».

## Текущий порядок блоков

breadcrumb → hero (заголовок + паспорт НП/КП/ABV/IBU/Цвет + медиа-панель) → лонгрид по секциям → карточка «Источник» → «Что варят в стиле» → «Ещё в категории».

---

## П1. Сигнал о рецептах на первом экране — P0

В hero добавить ссылку с числом рецептов в стиле: **«Рецепты в этом стиле (N)»**.

- Поведение: якорный переход к блоку «Что варят в стиле» (блок остаётся на своём месте, лонгрид не разрываем). Блоку задать `id`, например `id="recipes"`.
- Размещение — на усмотрение дизайнера, два кандидата:
  - рядом с сеткой паспорта (левая колонка hero);
  - нижняя часть медиа-панели (правая колонка) — сейчас это декоративная зона, там только код стиля и английское название.
- Число N живое. Страница — SSG без БД на билде, поэтому чип — клиентский остров по образцу `BjcpGravityPassportStats`.
- **Один запрос на страницу.** Сейчас `StyleCommunityRecipes` сам ходит в `/api/recipes/by-style`. Чип не должен дублировать запрос: поднять загрузку в общего клиентского родителя (или контекст/общий кеш на модуль), из которого читают и hero-чип, и нижний блок.
- Состояния чипа:
  - загрузка — ничего не показывать (никаких скелетон-кнопок в hero);
  - N > 0 — «Рецепты в этом стиле (N)», якорь вниз;
  - N = 0 — «Создать рецепт», ссылка на конструктор с предзаполненным стилем (см. П4);
  - ошибка запроса — не показывать (как уже делает нижний блок).

Сознательно **не** переносим сетку рецептов выше лонгрида: страница остаётся контентной (это и SEO-лонгрид), а рецептурный интент закрывается одним кликом из hero. Если дизайнер захочет усилить — допустим компактный вариант-превью (2–3 карточки) сразу под hero, но это отдельное решение, не для этой итерации.

## П2. Соседние стили — доступ сверху — P1

Сценарий «открыл не тот стиль» сейчас тоже спасается только внизу страницы. Дёшево чинится через breadcrumb: пункт категории (`кат. …`) сделать ссылкой на `/bjcp?category=<id>` — каталог уже восстанавливает состояние (категория, режим) из URL-параметров (`parseBjcpCatalogState`).

Нижний блок «Ещё в категории» остаётся как есть.

## П3. Якорная навигация по лонгриду — P1

Лонгрид длинный, секции уже имеют `id`. Добавить оглавление:

- desktop — sticky-рейл сбоку от статьи (колонка справа или слева от `max-w-3xl`);
- mobile — горизонтальная лента чипов-якорей под hero (или ничего, если дизайнер решит, что на мобиле это шум).
- Одинокий чип «N мин чтения» логично объединить с оглавлением, отдельно он мало что даёт.

В оглавление включить и пункт «Рецепты (N)» — вторая точка входа к блоку рецептов по мере чтения.

## П4. «Создать рецепт» с предзаполненным стилем — P2

Сейчас empty state блока рецептов ведёт на `/app/recipes/new` без стиля — пользователь должен заново найти стиль в конструкторе.

- Добавить в `/app/recipes/new` поддержку параметра стиля (сейчас `page.tsx` принимает только `recipeId | addSource | addId`) и проставлять стиль в конструкторе при создании.
- Использовать этот параметр: в empty state «Что варят в стиле» и в hero-чипе при N = 0 (П1).

## П5. Карточка «Источник» — компактная атрибуция со ссылкой — P2

Ссылка на источник **обязательна**: условия использования BJCP требуют атрибуции при перепечатке гайдлайнов, убирать её нельзя. Проблема только в форме: сейчас это крупная карточка на 4 поля (документ, файл, язык, категория), где файл часто «n/a», язык очевиден, а категория дублирует breadcrumb.

Заменить компактной строкой-атрибуцией под последней секцией статьи: «Источник: BJCP Style Guidelines 2021» со ссылкой на bjcp.org (документ гайдлайнов). Поля «файл», «язык», «категория» из UI убрать (в данных остаются).

## П6. Карточка рецепта на всю ширину при 1–2 рецептах — P1

В блоке «Что варят в стиле», когда рецепт один (сейчас так у большинства стилей), карточка растягивается на всю ширину экрана и выглядит разъехавшейся.

Причина — `apps/web/components/recipes/recipes-grid.tsx:47`: сетка `repeat(auto-fit, minmax(320px, 1fr))`. `auto-fit` схлопывает пустые треки, и единственная карточка получает весь контейнер.

Исправление: карточка при неполном ряде должна сохранять нормальную ширину — либо `auto-fill` вместо `auto-fit` (пустые треки остаются, карточка занимает свою колонку), либо `max-width` на карточку. Ориентир по виду — карточки рецептов на витрине `/recipes` при полной сетке; примеров компактных карточек в приложении много.

Внимание: `RecipesGrid` общий с витриной `/recipes` — там при одном результате поиска та же проблема, так что чинить лучше в самой сетке, а не обёрткой на странице стиля. После правки проверить обе поверхности (и комментарий про auto-fit в коде обновить).

## Критерии приёмки

1. На первом экране страницы стиля с рецептами видно число рецептов и есть переход к ним в один клик.
2. `/api/recipes/by-style` вызывается со страницы ровно один раз.
3. При нуле рецептов hero не пустует и не врёт: показывает «Создать рецепт», конструктор открывается с уже выбранным стилем.
4. Категория в breadcrumb кликабельна и открывает каталог на этой категории.
5. По лонгриду можно прыгать по секциям, включая якорь на блок рецептов.
6. Ничего из существующего контента не потеряно: лонгрид, нижний блок рецептов и «Ещё в категории» остаются.
7. Атрибуция BJCP присутствует на странице и ведёт ссылкой на bjcp.org.
8. Один рецепт в блоке «Что варят в стиле» (и один результат на `/recipes`) рендерится карточкой обычной ширины, без растягивания на весь контейнер.
