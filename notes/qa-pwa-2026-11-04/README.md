## Устройство исправления

В CacheStorage остаются только анонимный /offline, его обязательные чанки и разрешённая статика. HTML частных страниц, Flight, API, изображения рецептов и POST не кешируются worker. Кэш обычной статики ограничен 200 записями на release; обязательные ресурсы не участвуют в вытеснении. Для старых вкладок сохраняется один предыдущий уже подготовленный офлайн/статический кэш; более старые принадлежащие PWA кэши и nb-v1 удаляются. Наличие старого кэша не гарантирует доступность ранее не загруженных lazy-чанков при произвольном изменении приложения.

Предзагрузка выполняется с credentials:omit: новый userId в Providers не попадает в общий офлайн-HTML. Сам офлайн-документ пользуется последним локальным владельцем, не объявляет гостевой серверный snapshot реальным выходом и сохраняет его очередь при обычном обрыве/восстановлении сети. Пассивное завершение сессии сохраняет только подписанную очередь прежнего владельца до повторного входа; при входе другого аккаунта она очищается. Подтверждённый выход очищает личные локальные данные, включая несинхронизированную очередь; сохранённые на сервере данные не удаляются. При первом обновлении очищается старый неподписанный кэш пультов/воды, своя уже подписанная очередь сохраняется.

Стабильность Server Actions проверена для неизменённых действий. Явный NEXT_SERVER_ACTIONS_ENCRYPTION_KEY имеет приоритет; иначе ключ отдельно выводится из неизменного AUTH_SECRET. Build и start/реплики должны использовать согласованные секреты. Смена секрета и несовместимое изменение контракта требуют обновления старых вкладок; автоматическая совместимость любых исторических версий не заявляется. [Пояснение Next](https://nextjs.org/docs/messages/failed-to-find-server-action), [self-hosting](https://nextjs.org/docs/app/guides/self-hosting). Переход на [локальные шрифты Next](https://nextjs.org/docs/app/getting-started/fonts) устраняет сетевую загрузку шрифтов во время build; исходные семьи и их OFL сохранены.

## Стенд, воспроизведение и ограничения

Node.js 24.13.1, Next.js 15.5.28, PostgreSQL 16 Docker, Chromium Playwright. QA-база nb_qa_pwa_20261104 в контейнере nb-qa-pwa-20261104 на 127.0.0.1:55435, данные в tmpfs. Production-серверы на 3013/3014, прокси одного origin на 3011. Canonical APP_URL для стенда — nb.localhost; браузер использует доверенный localhost origin 127.0.0.1. Обычная локальная база nb в nb-postgres не использовалась для фикстур и не мигрировалась этим проходом.

Из-за production-гейта устройств пульт проверяется под отдельным QA admin с локальным in-process provider, без команд реальному оборудованию. Второй аккаунт — обычный user. Смена аккаунта использует действительную парольную сессию сервиса и обычные browser cookies. Полный HTTP-вход требует внешнего CAPTCHA: без ключа проверен штатный fail-closed ответ 400, защитный механизм не отключался. Логи/снимки не содержат raw session cookies или рабочего AUTH_SECRET.

Воспроизведение: создать временный Docker PostgreSQL с указанными именем/портом и --tmpfs /var/lib/postgresql/data:rw, дождаться pg_isready; подключить [qa-env.sh](tools/qa-env.sh), выполнить штатные migrate/seed. [build.sh](tools/build.sh) создаёт две независимые сборки fixed-f и fixed-g; запустить next start из apps/web с соответствующим NEXT_DIST_DIR на 3013 и 3014. [Прокси](tools/proxy.mjs) использует upstream-port.txt и fault-prefix.txt. Из apps/web запустить Playwright с e2e/pwa-prod.config.ts, PWA_PRODUCTION_QA=1 и PWA_UPDATE_QA=1. Для регрессии рецепта используется integration/vitest.config.ts и QA_ARTIFACT_DIR в папке этого отчёта.

Не подтверждены физическая установка/сон/выгрузка ОС Android/iOS, WebKit/Firefox, реальный HTTPS/CDN, Web Push, аппаратное BrewForge и нагрузочные бюджеты. По-прежнему остаются отдельные векторы плана. Сборка имеет существующие предупреждения ESLint вне исправляемой области; ошибок компиляции/typecheck в итоговых сборках нет.

Финальные build: fixed-f — AKM1bJwkB4tjhojpJnrjn, fixed-g — xbG3GhgycFykiGdd0JeAZ. Исходник worker одинаков, 161 идентификатор неизменённых Server Actions совпадает; значения ключей в доказательства не записывались. fixed-f — предыдущий релиз со всеми функциональными исправлениями, fixed-g также содержит SVG-значок B22. Основной итоговый прогон и визуальные проверки используют fixed-g; сценарии обновления начинают с fixed-f и переключают на fixed-g. Восемь сценариев редактора и модульная регрессия завершены до замены декоративного значка; после неё выполнены production build, 19 PWA-сценариев и TypeScript.

Тестовые несоответствия отделены от продуктовых ошибок: Playwright async waitForFunction не заменяет polling Promise-условия; готовность worker проверяется через expect.poll. Для production streaming сохранено требование ровно одного редактора до ввода. DB pool не закрывается между файлами одного Playwright worker; записи фикстур удаляются afterAll. В отказном обновлении ожидается завершение install, а не только controllerchange. Ранние диагностические логи сохранены отдельно и не суммируются как уникальные тесты.
